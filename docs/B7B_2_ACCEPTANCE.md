# B7b-2 数据看板验收

起点 `a4b406b`，分支 `codex/b7b-2-dashboard`。范围为 WORKBENCH_SPEC §11；五笔提交后停止，不合并、不推送。最大迁移仍为025，未新增迁移。

## 实现与口径

- 新增只读 `/dashboard` 与 Web 专用 `/api/v1/web/analysis?fromDay=&toDay=&basis=`；默认 posted，支持 restated。全响应共用一次只读事务、asOf 与水位，固定8次批量查询，不按月份或单据逐条查询，不读取单据行详情。
- 趋势与期间对比共用日/月聚合。完整月复用月合计，边界按日裁剪；趋势支持吨/包切换。Top 最多10项，商品/客户按有效出库克数、供应商按有效入库克数降序，同值编码升序；只列正排名值，Tooltip 展示双向数量。
- 库龄复用原FIFO投影，未归龄单列；周转复用原报表六个月图表计算。日终边界索引与轻量周转行保留原核验状态；无流水且同状态的零贡献项仅在周转汇总中折叠，不折叠库存或库龄余额。
- 热力以 toDay 结束，连续183个上海自然日；色阶为每日有效入库+出库克数。真实无发生为0，无法核验为null并说明原因，负净撤销量保留。
- 时效按建单至确认/最终发货，当前有效完成单据按完成时间归期；撤销/短关不计均值。终态样本规则为补充澄清未回复时的建议假设，已写入台账和规格。最长滞留取当前最早未完成单据，按建单至asOf小时数。
- 每块返回单位、实际期间、口径、核验状态和原因；缺少数据不填假零。缓存键包括日期范围和basis，使用共享写版本、30秒TTL、并发合并与克隆隔离；读取期间发生写入不把旧快照存入新版本。
- 页面顺序为日期、趋势、对比、Top、库龄、周转、热力、时效。日期预设与URL同步；数字先绘制，ECharts随后动态加载。热力按需注册Heatmap/Calendar/VisualMap；无Pie，Top横向Bar，新增样式/颜色全部取token。空区间不绘制坐标轴。
- 月/日/商品/库龄/周转下钻复用现有报表；客户下钻为现有出库列表按编码检索，不冒充同期间流水明细。异常UUID/快照值复用既有公开文本脱敏。
- 预取与应用脚本加载并行，当前范围响应在页面内存中消费一次；登录清理、30秒有效期及接口鉴权保持一致。首次侧栏统计等待analysis响应后发起，业务写入同时失效工作台与看板查询。

## 性能方法与限界

复用既有随机 `maozhi_test_*` 隔离库及生产Web构建静态服务。夹具包含入/出库主单各10000、明细各100000、流水100001；收发分布为一个商品在14个日期的入库，合计30010000000克，出库0。未通过缩减数据或改阈值达标，不外推至任意商品/时间分布。

并发1/5，冷热各30个样本，接口与首屏分别120个样本。冷组每批清analysis服务端缓存且使用新浏览器上下文；热组预热服务端并复用浏览器上下文。冷指应用缓存与浏览器上下文冷，不清MySQL buffer pool或操作系统缓存。首屏从导航开始，至真实数字内容出现并经过双requestAnimationFrame；骨架不算完成。每个样本验证响应数字和状态；无效样本保留并使验收失败。

记录首屏时间后等待该页面网络空闲，再关闭上下文或启动下一批；等待不计入已经记录的首屏时间，防止上一批侧栏请求残留在服务器端而使实际并发超过设定值。

主机为Windows、Intel i5-11400F（12逻辑核）、约32GiB内存，Node v24.14.1、MySQL 8.0.46，InnoDB buffer pool 128MiB；同机无网络/CPU限速。最终环境、构建摘要、SQL与逐次样本记录在 `.local/evidence/b7b-2/`。

首轮未达标数据保留于 `performance-before-turnover/`：并发1冷/热首屏p95为2028/485.5ms；并发5为2552/589.4ms。之后优化重复日终扫描、周转图文案构建、图表模块加载及侧栏请求时序，保持阈值2000ms和全部样本。
