# 打印子系统规范（PRINT_SPEC）

> 本文档中的状态、类型等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 定位

打印不是“点一下出个 PDF”，而是一条**可追溯的作业链**：谁、什么时候、打了哪张单、第几次、用什么模板、成功还是失败。

版式仍由积木报表负责（与老系统 1:1），本系统负责：任务、模板、次数、补打、水印、降级、审计。

## 2. 对标

| 系统 | 做法 | 借鉴 |
|---|---|---|
| SAP | 输出管理（spool）+ 输出类型 + 设备 + 表单，打印有作业记录，可重打 | 打印是“作业”，不是一次请求 |
| Oracle | BI Publisher 模板，可多模板、可重打 | 模板与单据解耦 |
| NetSuite | 每张单可打印多次，记录打印历史 | 次数与历史可见 |
| 金蝶/用友 | 套打模板 + 打印次数 + 补打标记 | 补打要写原因，纸上要能看出来 |

## 3. 核心原则

1. **每次打印都留痕**：任务记录不可删，含单号、模板、份数、操作人、结果；
2. **重打必须说明原因**：丢失/污损/客户要求/其他，纸上标注“补打 第 N 次”；
3. **重打用当时的数据**：取单据快照 + 当时模板版本，不用当前主数据；
4. **积木不可用时不断链**：降级为简易打印；
5. **token 不出服务端**：浏览器永远看不到积木地址与 token。

## 4. 数据模型

### print_templates（模板）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| kind | inbound / outbound / outbound_overlay / delivery_note |
| name | 显示名，如「出库单 A4」「出库单套打」 |
| api_url | 积木导出地址 |
| report_code | 积木报表 ID |
| jimu_token | 积木 token（仅服务端） |
| param_name | 参数名，如 orderNo |
| paper | A4 / 套打纸张规格说明 |
| version | 模板版本号，递增 |
| enabled | 启用 |
| is_default | 同 kind 的默认模板 |

### print_jobs（打印任务）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| doc_type / doc_id / doc_no | 单据 |
| template_id / template_version | 模板与版本 |
| copies | 份数 |
| reason | 首次为空；补打必填 |
| attempt_no | 第几次打印该单 |
| status | queued / running / done / failed |
| file_path / file_hash | 临时文件与哈希（24 小时后清理） |
| error_code / error_message | 失败原因 |
| operator / created_at / finished_at | 审计 |

### print_settings（设置）

| 字段 | 说明 |
|---|---|
| kind | 默认份数、是否允许补打、补打是否需审批（单用户恒否） |
| fallback_enabled | 是否允许简易打印 |

## 5. 打印流程

```
Web 选单据 → 选模板（默认自动）→ 份数 → 提交
→ 后台任务：逐单调用积木（单报表导出）→ 校验每份为 PDF
→ 用 pdf-lib 合并为一个 PDF → 下载/预览 → 用户自行打印
```

规则：
- 单张打印：直接出 PDF 预览；
- 批量打印（最多 50 张）：服务端循环调用 + 合并，**不使用积木的多报表导出**（它只返回 ZIP）；
- 任务异步，页面显示进度（3/10），可离开后回来查看；
- 失败的单据单独列在结果里，不影响其他单。

### 5.1 已验证事实（2026-11-10 本地实测）

| 事实 | 实测结果 |
|---|---|
| 单报表导出 | `GET /jmreport/exportReport` 返回 `%PDF`，423,909 字节 |
| 多报表导出 | 同一接口传 2 个 `exportParams` → 返回 **ZIP**（841,564 字节），内含 `1_单A.pdf`、`2_单B.pdf` |
| 合并 | `pdf-lib` 合并两个 1 页 PDF → 2 页单文件 PDF（846,310 字节） |
| `reportId` | 必须是数据库数值 id，传 `code` 会触发 NPE 500 |
| 数据源不可用 | 报表数据集连不上时接口返回 500，**响应体为空**，Content-Type 却标为 PDF |

结论：**积木支持批量，但产出是 ZIP，不是合并 PDF。** 要“点一次打印出一叠连续单据”，必须由本系统合并。

### 5.2 进度反馈

批量打印是秒级到分钟级操作，必须有进度，不能让用户干等。

#### 阈值

| 数量 | 方式 | 表现 |
|---|---|---|
| 1–2 张 | 同步 | 直接返回 PDF，不弹窗（2 秒内出结果，弹窗反而多余） |
| 3 张及以上 | 异步任务 | 弹「正在生成」窗口，轮询进度 |

#### 生成中弹窗

```
┌ 正在生成打印文件 ────────────────────── ✕ ┐
│   ████████████░░░░░░  6 / 10             │
│   ✓ RK-20261109-0001  已生成              │
│   ✓ RK-20261109-0002  已生成              │
│   ⏳ RK-20261109-0003  生成中…            │
│   ○ RK-20261109-0004  等待                │
│   已完成 6 张 · 失败 1 张                 │
│   [后台继续]                    [取消]    │
└──────────────────────────────────────────┘
```

规则：
- 进度按**单**计，不按字节；
- 每张单四种状态：等待 / 生成中 / 已生成 / 失败；
- 点「后台继续」关闭弹窗，任务继续，打印中心可见；
- 点「取消」：当前这张做完即停，已生成的保留；
- 关掉页面再回来，任务与结果仍在打印中心。

#### 完成弹窗

```
┌ 打印文件已生成 ────────────────────────┐
│  10 张单 · 10 页 · 2.4 MB              │
│  失败 1 张：CK-20261109-0012（积木超时）│
│  [下载 PDF]  [重试失败项]  [关闭]       │
└────────────────────────────────────────┘
```

规则：
- 下载由用户点击触发（异步完成后自动下载可能被浏览器拦截）；
- 失败项单独列出，可一键只重试失败的；
- 部分成功也允许下载，不因一张失败作废整批。

#### 技术约定

- `POST /print/jobs` 返回 `202 { jobId }`；
- 前端每 800ms 轮询 `GET /print/jobs/:id`，直到 `done` 或 `failed`；
- 任务记录持久化，刷新页面不丢；
- 失败单的重试复用同一任务，不新建重复记录。

## 6. 补打

| 规则 | 说明 |
|---|---|
| 触发 | 单据已打印过，再次打印即为补打 |
| 原因 | 必填：丢失 / 污损 / 客户要求 / 其他（需备注） |
| 标记 | PDF 上标注「补打 · 第 N 次 · 原因」 |
| 记录 | print_jobs.attempt_no 递增，不可删除 |
| 限制 | 作废单允许补打，但需额外确认 |

## 7. 水印与状态矩阵

| 单据状态 | 打印内容 | 水印 |
|---|---|---|
| 正常 | 正式单据 | 无 |
| 部分发货 | 当前已发量 | 「部分发货」 |
| 已出库/已入账 | 正式单据 | 无 |
| 已更正 | 最新有效数量 | 「已更正 · 第 N 版」 |
| 已撤销 | 原单内容 | 「已撤销」 |
| 已作废 | 原单内容 | 「作废」 |
| 补打 | 正式内容 | 「补打 第 N 次」 |

水印由积木模板通过参数渲染；本系统负责传参（`watermark`、`attemptNo`、`reason`），不自己叠图。

## 8. 快照与模板版本

重打必须还原当时的样子：

1. 单据内容取 `*_snapshots`（商品名、客户名、地址、联系人）；
2. 模板版本取 `print_jobs.template_version` 对应的模板参数；
3. 主数据后来改名、改电话，不影响历史打印件。

## 9. 降级打印

积木不可用（超时、非 PDF、5xx）时：

```
① 任务标记 failed，写明原因
② 页面提供「简易打印」按钮
③ 用浏览器打印纯 HTML 版：字段与正式版一致，不做套打定位
④ 页面标注「简易版 · 非套打」
⑤ 简易打印同样记 print_jobs（template_id=fallback）
```

目的：车等着走时，打印不能成为堵点。

## 10. 打印中心页面

路径：/print

Tabs：打印任务 | 模板管理 | 补打记录 | 设置

### 打印任务

列表：时间、单据号、类型、模板、份数、状态、操作人、操作（下载/重试/补打）。

筛选：时间范围、单据类型、状态（成功/失败）、单号。

### 模板管理

列表：类型、名称、报表 ID、纸张、版本、默认、启用。

操作：新增/编辑、测试打印（用真实单号生成 PDF 预览）、设默认、停用。

规则：同 kind 只有一个默认；修改地址或报表 ID 需二次确认；每次修改 version+1。

### 补打记录

按单据聚合：单号、打印次数、最近一次时间与原因；点开看每次记录。

### 设置

默认份数、是否允许简易打印、临时文件保留时长（默认 24 小时）。

## 11. 接口

| 接口 | 说明 |
|---|---|
| POST /api/v1/print/jobs | 创建任务（docType, ids[], templateId?, copies, reason?） |
| GET /api/v1/print/jobs/:id | 任务状态与进度 |
| GET /api/v1/print/jobs/:id/file | 下载结果（PDF 或 ZIP） |
| POST /api/v1/print/jobs/:id/retry | 重试失败任务 |
| GET /api/v1/print/jobs | 任务列表 |
| GET/POST/PUT /api/v1/print/templates | 模板管理 |
| POST /api/v1/print/templates/:id/test | 测试打印 |
| GET /api/v1/print/templates/:id/preview | 预览 |
| GET/PUT /api/v1/print/settings | 设置 |

## 12. 边界

| 情况 | 处理 |
|---|---|
| 积木超时（30 秒） | 任务失败，可重试，可降级 |
| 返回 HTML 错误页 | 判定非 PDF，报错不下载 |
| 积木 500 且响应体为空 | 视为失败，提示“积木报表错误”，并记录状态码；不向浏览器输出空文件 |
| 报表数据集连不上 | 部署时校验：模板数据源必须指向本系统使用的库，启动自检失败则打印按钮禁用 |
| 批量中部分失败 | 成功照常可下载，失败单独列出 |
| 临时文件过期 | 24 小时后清理，任务记录保留 |
| token 泄露 | 禁止前端直连积木；日志不记 token |
| 未配置模板 | 打印按钮禁用，提示「未配置打印模板」 |
| 套打纸张 | 模板固定尺寸，打印时禁止缩放 |

## 13. 验收

1. 单张打印：PDF 可打开，与老系统同单号打印件叠图一致；
2. 套打：A4 套打定位偏差 ≤ 1mm（实测，非目测）；
3. 补打：第二次打印需填原因，PDF 上出现「补打 第 2 次」；
4. 批量 10 张：一个任务，成功 10/10，进度可见；
5. 批量中 1 张失败：其余 9 张可下载，失败单列出；
6. 积木停机：任务失败有原因，简易打印可用且标注「非套打」；
7. 重打已更正单据：使用最新有效数量，水印「已更正」；
8. 重打已作废单据：水印「作废」；
9. 打印任务列表可按单号查到全部历史；
10. 浏览器网络面板无 token 与积木内网地址；
11. 模板改地址后 version+1，旧任务仍指向旧版本；
12. 3 张以上触发进度弹窗，进度按单递增，完成后显示页数与大小；
13. 生成中取消：当前单完成后停止，已生成的可下载；
14. 点「后台继续」关闭弹窗后，打印中心仍能看到任务并下载；
15. 部分失败：成功项可下载，失败项可单独重试，重试不产生重复记录；
16. 刷新页面后任务与结果仍在，不回到空白。

## 14. 不做

| 不做 | 原因 |
|---|---|
| 自研 PDF 排版引擎 | 积木已解决，重复投入 |
| 服务端控制打印机 | 浏览器打印即可，单机无打印服务器 |
| 打印审批流 | 单用户，无审批 |
| 电子签章 | 无此需求 |
| 长期保存 PDF | 24 小时临时文件足够，单据数据才是权威 |
