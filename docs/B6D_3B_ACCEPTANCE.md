## 范围与决策

- 放弃对象是整版已校验未发布候选，不支持逐条跳过或部分发布。放弃不可原位撤销；显式重建使用保留原文、原编码及当前基准生成新版本，旧版本和放弃证据保留。
- 同内容普通重传不新建，返回匹配的已放弃版本、状态及指定中文提示。原上传和原查重结果的幂等重放/查询也读取最新放弃状态。
- 原因必填，操作人和时间由服务端记录；放弃证据、成功审计及幂等结果同事务。同键同正文重放成功，新键重复/已发布放弃为 422，同键不同正文为 409。
- 基准已变时拒绝发布，需重建候选。行数骤减 ≥50% 的上传 warning + 前端确认仅记 backlog，未增加服务端硬门禁。
- 候选详情下按该候选的基准版本展示已登记交接摘要，只读、分页。预期数来自 PDA 交接事实快照，候选放弃不扣减；没有证据时说明设备情况未知。

## 迁移与接口

新增 `023_catalog_candidate_abandons`，不改 006/007 或父表主键。子表 `version_id` 为有符号 `INT NOT NULL PRIMARY KEY`，与 `catalog_versions.version_id` 完全一致；正数 CHECK、父表外键 RESTRICT、唯一 `operation_id CHAR(36)`、必填 reason/actor/UTC created_at。UPDATE/DELETE 由触发器拒绝。迁移注明父键类型调整前须评估全部引用表。

`migrateDown` 在任何 DDL 及迁移状态修改前检查非空，有证据即拒绝。down SQL 只供迁移执行器调用。023 仅在可销毁测试库做往返和守卫验证，未应用开发样本库。

新增 Web 登录渠道接口：

- `POST /catalog/versions/:id/abandon { reason }`
- `POST /catalog/versions/:id/rebuild {}`
- `GET /catalog/versions/:id`
- `GET /catalog/versions/:id/handoffs?page=`

原版本状态保留，`abandoned` 从追加表投影；上传、版本列表、条码轨迹及候选详情使用该投影。放弃版本仍可只读核对差异。发布已放弃候选优先返回 422「该候选已放弃，请重建候选」，原发布幂等重放保持兼容。
