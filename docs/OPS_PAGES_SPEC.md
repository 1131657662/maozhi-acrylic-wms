> 本文档中的状态、类型、结果等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 一、消息中心

### 1. 定位

只做**系统通知**：有事提醒我，点一下能到现场。不做公告、私信、@人、已读回执。

### 2. 页面结构

```
┌ 消息中心 ─────────────────────── [全部已读] ┐
│ 未读 3 ｜ 全部 12 ｜ 类型 [全部 ▾]          │
├──────────────────────────────────────────────┤
│ ● 11-09 10:12  待确认  入库单 RK-…031 待确认 │
│ ● 11-09 09:40  超时    出库单 CK-…008 冻结 8 天 │
│ ● 11-08 18:00  备份    每日备份失败（磁盘不足）│
│ ○ 11-08 09:00  盘点    主仓盘点进行中 12 小时 │
└──────────────────────────────────────────────┘
```

点一条 → 直接跳到对应单据/页面，并标记已读。

### 3. 消息类型

| 类型 | 触发 | 跳转 |
|---|---|---|
| 待确认 | 本地待确认入库创建超过2小时；本地未完成出库结束扫码超过2小时，仍需 Web 人工实发确认 | 单据详情 |
| 发货超时 | 本地未删除的 open/frozen/partially_shipped，scan_closed_at 非空且满7天，仍未完成发货；部分发货继续提醒，终态排除，历史缺时间标未知，不新增 frozen | 单据详情 |
| 盘点未结束 | 盘点锁仓超过 24 小时 | 盘点详情 |
| 目录待更新 | 当前发布版本的 published_at 距今满30天；上传未发布不刷新时效，未初始化/缺时间显示未知，与工作台一致 | 条码目录 |
| 备份失败 | 备份任务失败 | 系统维护 |
| 异常 | 历史异常负余额（诊断，不允许新写负库存）、盘点差异超提示阈值 | 对应页面 |

生成方式：服务端定时任务扫描，**同一对象同一类型同一事件周期只保留一条活动通知**（已读不自动重发，条件解除记录resolved，新周期才新建），避免轰炸。

### 4. 交互

- 未读数显示在左侧菜单角标；
- 支持「全部已读」；
- 单条已读在点击跳转时自动完成；
- 消息保留 90 天，过期自动清理（仅删通知，不动业务数据）；
- 不做消息回复、不做评论。

### 5. 接口

GET /api/v1/messages?type=&unread=&page=
POST /api/v1/messages/:id/read
POST /api/v1/messages/read-all
GET /api/v1/messages/unread-count

### 6. 边界

| 情况 | 处理 |
|---|---|
| 对象已删除 | 消息保留，跳转提示“对象不存在” |
| 重复触发 | 同事件周期合并last_seen/count，不重置已读；条件解除后标已恢复 |
| 免打扰 | 不做（单用户，量很小） |

## 二、系统维护

### 1. 定位

保证两件事：**数据有备份、系统没毛病**。

两个 Tab：备份 | 健康。

### 2. 备份 Tab

```
┌ 备份 ────────────────────────── [立即备份] ┐
│ 最近成功：2026-11-09 02:00（8 小时前）✓      │
│ 磁盘剩余：120 GB                           │
├─────────────────────────────────────────────┤
│ 时间 │ 类型 │ 大小 │ 校验 │ 状态 │ 操作     │
│ 11-09 02:00 │ 自动 │ 42 MB │ ✓ │ 成功 │ 下载/恢复 │
│ 11-08 02:00 │ 自动 │ 42 MB │ ✓ │ 成功 │ 下载/恢复 │
│ 11-07 18:20 │ 手动 │ 41 MB │ ✗ │ 损坏 │ 下载/删除 │
└─────────────────────────────────────────────┘
```

规则：
- 每日自动备份 1 次（凌晨）；
- 保留策略：30 个日备 + 12 个月备，超出自动清理；
- 每次备份写 SHA-256 与大小清单；
- 下载前校验哈希；
- 备份失败 → 消息中心 + 页面顶部红色提示。

### 3. 恢复（危险操作）

```
① 点击恢复 → 弹窗列出：备份时间、大小、校验状态
② 要求输入 “RECOVER” 确认
③ 自动先备份当前库（防止越恢复越糟）
④ 恢复到隔离库 → 校验表数量、行数、库存合计
⑤ 校验通过后提示“需手动切换到恢复库”，不自动切换
⑥ 失败保留本任务隔离库、日志、指纹及错误证据，不自动清理，原库不动（B8a-2取代原失败后清理规则）
```

明确：**不在原库上直接覆盖恢复**。

### 4. 健康 Tab

| 区块 | 内容 |
|---|---|
| 数据库 | 连接状态、版本、表数量、慢查询数（近 24h） |
| 磁盘 | 剩余空间、数据目录大小、备份目录大小 |
| 服务 | 运行时长、近 24h 请求数、错误数、p95 耗时 |
| 备份 | 最近成功时间、最近失败原因 |
| 任务 | 最近定时任务执行结果（备份、消息扫描） |

异常项标红，正常项绿点。

### 5. 接口

GET /api/v1/maintenance/backups
POST /api/v1/maintenance/backups
GET /api/v1/maintenance/backups/:id/download
POST /api/v1/maintenance/backups/:id/restore
DELETE /api/v1/maintenance/backups/:id
GET /api/v1/maintenance/health

### 6. 边界

| 情况 | 处理 |
|---|---|
| 磁盘不足 | 备份前检查，直接拒绝并提示 |
| 备份超大 | 记录大小，超阈值告警 |
| 恢复中断 | 保留诊断、任务状态和隔离库，停止专用账号会话并锁定账号，原库不变 |
| 无备份 | 顶部红条「从未备份」 |
| 并发备份 | 同一时间只允许一个 |

### 7. 不做

| 不做 | 原因 |
|---|---|
| 云备份 | 单机部署，本地 + 手动下载够用 |
| 定时任务可视化编辑 | 固定任务，代码里配置 |
| 数据库迁移工具界面 | 迁移由脚本执行 |

## 八、B8b 身份与个人中心（2026-11-17 定稿）

### 8.1 范围与迁移

起点63b5ec8，codex/b8b-identity，功能五笔提交后停止并等待验收；用户验收后授权的迁移与合并收尾见8.5。只做本人资料/会话/改密及账户锁定，不做RBAC、多用户管理、找回密码、OAuth或头像联系方式。

028为owner增加display_name VARCHAR(80) NULL、password_changed_at DATETIME(3) NULL、auth_epoch INT UNSIGNED NOT NULL DEFAULT 0、failed_attempts INT UNSIGNED NOT NULL DEFAULT 0、locked_until DATETIME(3) NULL；sessions增加id CHAR(36) NOT NULL UNIQUE、created_at DATETIME(3) NOT NULL、epoch INT UNSIGNED NOT NULL DEFAULT 0。时间UTC保存、上海显示。旧会话不删除：补独立UUID，created_at按既有固定8小时有效期由expires_at减8小时回填，epoch为0。会话id仅供接口定位，不展示。

down在任何DDL前检查owner可空新列非NULL、计数/版本非0以及任一sessions记录；有数据拒绝，不自动清理。默认0不视为业务数据，旧会话补值也受保护；空扩展数据可down/up。迁移仅在隔离合成测试库验证，不自动应用开发样本库。

### 8.2 接口与显示

新/me接口全部先认证，再校验Web渠道；写操作要求Origin白名单，Authorization头被拒绝。账号来自服务端会话，不接收客户端username。保留/auth/login、/auth/me、/auth/logout。

| 方法/路径（/api/v1） | 行为 |
|---|---|
| GET /me | username、displayName（可空）、channel、lastLoginAt（当前会话之前最近成功登录，无证据null）、expiresAt、passwordChangedAt |
| PUT /me/profile | 严格仅displayName；去首尾空白，最多80字符，空串归NULL；不改账号；事务审计 |
| POST /me/password | 严格oldPassword/newPassword；正确原密码后同事务更新哈希、改密时间、auth_epoch+1、删本人全部渠道会话、成功审计；成功清Cookie并重新登录 |
| GET /me/sessions | 本人有效且epoch匹配会话；id、channel、createdAt、expiresAt、isCurrent；创建时间倒序、页面分页常量控制；不声称实时在线 |
| DELETE /me/sessions/:id | 仅本人；未知/他人编号统一404；撤销当前等同退出并清Cookie；审计仅渠道/是否当前，不含会话UUID/哈希/token |
| POST /me/logout | 当前会话退出别名；/auth/logout保持兼容 |

/me按资料、登录会话、密码安全分区，唯一主操作修改密码，资料保存为次级；撤销/退出与主操作分区并二次确认。标题16px UserOutlined，既有PageShell、Ant Design、theme token，不加UI库。渠道中文，UUID和内部版本不展示；显示名保存同步账号入口。密码表单不接草稿、不持久化；确认前输入仅留在当前组件内存；请求成功/失败或离开后均清空密码字段。

### 8.3 密码、锁定与并发

新密码UTF-8 12–72字节，含英文字母和数字，不trim；超72字节明确422。登录/旧密码保持1–128字符串长度兼容，旧超长bcrypt密码仍可认证，成功返回需改密提示，Web进入个人中心提示、PDA显示提示、小程序确认提示后继续查询；新密码禁止截断。确认密码仅页面校验。

连续失败按实际owner持久计数，跨渠道/进程共用；第5次锁15分钟并返回429及retryAfterSeconds/Retry-After。锁定中正确/错误密码同429，在bcrypt前拒绝，不增加计数、不续锁。到期下次尝试从0开始；成功清零/清锁；不存在账号统一401，不新增owner。HTTP按IP的15分钟20次限流独立保留。

登录比较密码后在事务中锁owner，复核此前auth_epoch和密码哈希，变化即拒绝签发。事务中复查锁定，提交失败计数或清零并签发；失败结果在事务提交后抛错，避免计数回滚。每次认证要求sessions.epoch=owner.auth_epoch。改密在owner行锁下再次认证当前会话，验证旧密码后更新并撤销，保证并发两次仅一次成功、旧密码已验证的并发登录不能事后签发。撤销/资料更新同样在owner行锁后复验会话。

成功写operation_log，失败复用operation_attempts；仅动作、本人账号与安全业务摘要。密码、密码哈希、token、token哈希不得进入审计、日志或表单草稿；密码及密码哈希不进入客户端持久缓存，认证凭证继续沿既有会话存储方式保存。兼容提示只返回布尔信号/固定文案。

### 8.4 PDA与验收

PDA离线时不清业务数据；下次联网请求401才提示重新登录并清认证凭证。后台401停止重试并标记需认证，前台恢复时显示登录；登录后沿既有补传链路继续。Room队列、目录、计划、交接清单、UUID及正文原样保留，仅上传状态允许变化。

验收：三端旧token全401；双改密仅一次成功；登录/改密竞态；5次锁15分钟、重建服务仍锁、到期恢复/成功清零；锁中正确错误同响应；字节边界/中文/旧超长提示；渠道/Origin/伪造账号/他人会话拒绝；事务回滚/审计无秘密；028回填/空数据往返/非空拒绝。完整test/build/E2E、token和AntD检查、1440/1280截图仅.local/evidence/b8b；PDA构建/单测/lint，模拟器可用时验证并注明不等于实体/生产验收。不改截图基础设施，不为截图写开发样本库。

### 8.5 用户验收与收尾（2026-11-17）

B8b已用户验收，629/234/0；按明确授权备份、指纹后应用028至开发样本库，原55张表原有列指纹一致。个人中心显示名保存刷新、当前会话与到期时间、5次失败429及剩余时间均通过；验证后SQL清计数/锁期限，原密码恢复登录200。开发库禁止改密，密码哈希未变，改密由自动化覆盖。功能已非快进合并推送d122652，收尾文档更新后停止，不开始B8c；详见B8B_ACCEPTANCE。

单用户的最小身份页：改密码、看会话、退出。

### 2. 页面结构

```

│ 账号 owner（管理员）           │
│ 上次登录 2026-11-09 08:30     │
│ 当前会话 到期 16:30           │
├────────────────────────────────┤
│ 显示名 [owner________] [保存] │
│ 修改密码                       │
│  原密码 [________]            │
│  新密码 [________]            │
│  确认   [________]            │
│  [修改密码]                    │
├────────────────────────────────┤
│ [退出登录]                     │
└────────────────────────────────┘
```

规则：
- 改密码需原密码；
- 新密码 UTF-8 长度 12–72 字节，含英文字母与数字；超过 72 字节明确拒绝，不静默截断（B8b 取代原字符长度规则）；

## 四、验收

### 消息中心
1. 未读数与列表一致，点开自动已读；
2. 同一对象同类型同事件周期仅一条活动通知，已读后不因扫描重发；恢复后新周期可重新通知；
3. 六种类型各触发一次，跳转正确；
4. 90 天后过期清理不影响业务数据。

### 系统维护
5. 手动备份成功，列表显示大小与校验；
6. 备份失败时消息中心与页面同时提示；
7. 恢复需输入确认词，自动先备份当前库；
8. 恢复失败时原库不变（给实际输出）；
9. 磁盘不足时拒绝备份；
10. 健康指标逐项标采集来源/水位，未接采集器显示不支持而非0，异常项标红。

### 个人中心
11. 改密码需原密码，成功后强制重新登录；
12. 新密码不合规被拒；
13. 连续 5 次登录失败锁定 15 分钟。

### 通用
14. 1440/1280 截图（消息列表、备份列表、恢复确认、健康页、个人中心）。

维护接口是异步任务：POST返回jobId、GET读取状态，不让浏览器执行任意路径/命令/目标库名。备份/恢复按任务互斥、超时/重启可查；备份文件清理只针对自身产物且已核验归属，恢复隔离库不自动清理。备份已在B8a-1产品化，恢复按第七节实施；恢复副本现有清空会话行为在指纹中明确排除并验证，其余业务表必须逐项对账。UI中的恢复不覆盖原库，切换连接另有CUTOVER门禁；不自动触发迁移。

健康页需要数据库/磁盘/HTTP耗时及错误采集服务，记录采集时间/窗口和缺测原因；慢查询数、24小时p95在未启用采集器时标不支持。车辆离场/实时设备队列始终不由维护页猜测，沿用WORKBENCH/CATALOG证据范围。账户密码/token不进审计，失败尝试依赖B6c；改密/会话撤销认证检查在服务端，单用户不引入RBAC。

迁移编号按仓库当前最大编号递增分配；B8a-1明确使用026，后续不预占编号。up保留来源与历史证据，非空业务/任务/通知记录拒绝破坏性down。查询/分页/导出和唯一主操作遵循WEB_UX_SPEC，不在三页各定一套。阶段先B8a-1、B8a-2与B8b身份，再接稳定事件做B8c通知；演练、实体与生产结果分别记录。

修订记录：C15 补通知去重/恢复周期、任务产物/指纹/失败保全、健康采集及身份会话服务依赖。
