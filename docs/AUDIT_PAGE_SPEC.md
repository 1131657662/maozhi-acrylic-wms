# 操作记录页面规范（AUDIT_PAGE_SPEC）

> 本文档中的状态、类型、结果等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 定位

操作记录回答：**谁、什么时候、对什么、改了什么、改成什么**。

参照：SAP 变更凭证（表/字段级旧值新值）、NetSuite System Notes（单据时间线）、Salesforce Field History（跟踪字段）、GitHub Audit Log（筛选+导出+correlation id）。

审计只读、不可删除、不可编辑。

## 2. 页面结构

```
┌ 操作记录 ───────────────────────────────────── [导出 ▾] ┐
│ 今日 128 条 · 失败 2 条 · 涉及单据 46 张                │
├──────────────────────────────────────────────────────────┤
│ 时间 [近 7 天 ▾]  类型 [全部 ▾]  关键字 [单号/商品/人]   │
│ [筛选 ·N]   [保存为视图 ▾]                              │
├──────────────────────────────────────────────────────────┤
│ 视图：列表 ｜ 时间线                                     │
├──────────────────────────────────────────────────────────┤
│ 表格 / 时间线内容                                        │
└──────────────────────────────────────────────────────────┘
```

页头只有导出（审计只读，无写操作）。

## 3. 统计条

| 指标 | 说明 |
|---|---|
| 今日操作数 | 当前日期的记录数 |
| 失败数 | 红色，点击只看失败 |
| 涉及单据数 | distinct target_id |
| 危险操作数 | 撤销 / 作废 / 更正 / 盘点回写，橙色，点击筛选 |

## 4. 列表视图

| 列 | 说明 |
|---|---|
| 时间 | 精确到秒，上海时区 |
| 类型 | 图标 + 中文：入库确认 / 入库撤销 / 出库确认 / 库存调整 / 盘点回写 / 目录发布 / 更正 / 登录 |
| 对象 | 单号或商品/仓库，可点进单据 |
| 变更摘要 | 一句话：「状态 待确认→已入账；包数 216→240」 |
| 渠道 | Web / PDA / 小程序 |
| 结果 | 成功 / 失败（带错误码） |
| 追踪号 | trace_id 前 8 位，点击聚合 |

颜色规则：
- 危险操作（撤销、作废、更正、盘点回写、目录发布）→ 橙色标签；
- 失败 → 红色；
- 普通 → 默认色。

默认按时间倒序，50/页。

## 5. 时间线视图

按对象聚合，像 NetSuite System Notes：

```
RK-20261109-0031 · 入库单
├ 11-09 10:12  确认入账   owner  Web   状态 待确认→已入账
├ 11-09 10:12  库存变更   owner  Web   003/主仓 216→240 包
├ 11-09 10:12  流水生成   owner  Web   1 条
└ 11-09 10:10  创建单据   owner  Web   —
```

用途：查一张单的完整历史，比列表更直观。

时间线视图按“对象”分组，默认展示最近 20 个对象，可搜索单号。

## 6. 详情抽屉

```
┌ 操作详情 · 入库确认 RK-20261109-0031 ─────────────────┐
│ 时间 2026-11-09 10:12:03  操作人 owner  渠道 Web       │
│ 追踪号 a1b2c3d4-…  [复制]  结果 成功                  │
├───────────────────────────────────────────────────────┤
│ 变更字段（3）                                          │
│ 字段        │ 变更前     │ 变更后                     │
│ 状态        │ 待确认     │ 已入账                     │
│ 包数（合计）│ 216 包     │ 240 包                     │
│ 吨数（合计）│ 64.8000 吨 │ 72.0000 吨                 │
├───────────────────────────────────────────────────────┤
│ 同一次请求的其他记录（3）  [全部展开]                  │
│ ▸ 库存变更 003/主仓 216→240 包                         │
│ ▸ 流水生成 1 条                                        │
│ ▸ 审计写入                                             │
├───────────────────────────────────────────────────────┤
│ ▸ 原始数据（JSON）    [复制] [导出该请求]              │
└───────────────────────────────────────────────────────┘
```

规则：
1. 默认只显示变化字段，字段名转中文并带单位；
2. 未变化字段折叠「显示全部字段」；
3. 同一 trace 的其他记录并列展示，可一键展开；
4. 原始 JSON 折叠，可复制或导出该 trace 的完整 JSON（排查用）；
5. 对象可点，跳当前单据。

## 7. 筛选

- 快捷：时间范围（今天 / 昨天 / 近 7 天 / 本月 / 自定义）、类型
- 关键字：一次匹配单号、商品编码、操作人、追踪号
- 抽屉：渠道、结果、危险操作、追踪号
- 支持保存为视图（如「本周撤销记录」「失败操作」）

## 8. 导出

| 格式 | 内容 |
|---|---|
| XLSX / CSV | 当前筛选结果：时间、类型、对象、变更摘要、渠道、结果、追踪号 |
| JSON | 单条或单 trace 的完整记录（详情里导出） |

- 单次导出上限 10 万行，超出提示缩小范围；
- 导出不含原始 JSON（体积大），需要时单独导出 trace。

## 9. 保留与完整性

- 记录永久保留，不提供删除与修改；
- 页面顶部标注「审计记录不可修改」，让使用者知道可信；
- 超 1 年支持按年导出归档，导出后仍保留；
- 历史导入数据不生成审计（无对应操作）。

## 10. 性能

- 索引：created_at、action、target_id、trace_id；
- 默认查询近 7 天，避免全表扫描；
- 列表不返回 JSON，详情按需加载；
- 服务端解析变更字段，前端不解析原始 JSON。

## 11. 接口

| 接口 | 说明 |
|---|---|
| GET /api/v1/web/lists/audit | 列表（扩展筛选与关键字） |
| GET /api/v1/web/lists/audit/:id | 详情（结构化变更字段 + 同 trace 记录） |
| GET /api/v1/web/lists/audit?traceId= | 按追踪号聚合 |
| GET /api/v1/web/lists/audit/timeline?targetId= | 时间线视图 |
| GET /api/v1/web/lists/audit/export | 导出（格式参数） |
| GET /api/v1/web/lists/audit/:id/trace.json | 导出单 trace JSON |

响应中的 changes 为结构化数组：`{field, label, before, after, unit}`。

## 12. 边界

| 情况 | 处理 |
|---|---|
| 失败操作 | 保留，结果红标，详情显示错误码 |
| 无变更字段（登录等） | 只显示基本信息 |
| JSON 超大 | 截断 + 提示导出 |
| 对象已删除 | 显示原标识，不跳转 |
| 历史导入数据 | 不生成审计 |
| 时区 | 统一上海时间 |

## 13. 不做

| 不做 | 原因 |
|---|---|
| 撤销/回滚审计 | 审计不可变 |
| 删除审计 | 合规 |
| 表级审计查询 | 业务视角够用 |
| 实时推送 | 单用户 |
| 审计报表图表 | 导出到 Excel 分析即可 |

## 14. 验收

1. 列表倒序、分页正确，统计条与筛选结果一致；
2. 危险操作与失败正确着色；
3. 时间线视图按对象聚合，顺序正确；
4. 详情只显示变化字段，字段名/单位正确；
5. 同 trace 记录可展开，trace JSON 可导出；
6. 关键字一次匹配单号/商品/人；
7. 保存视图后刷新仍生效；
8. 导出字段与列表一致，上限提示正确；
9. 1440/1280 截图（列表、时间线、详情、失败筛选）。
