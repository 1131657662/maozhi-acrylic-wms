# 操作记录页面规范（AUDIT_PAGE_SPEC）

> 本文档中的状态、类型、结果等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 定位

操作记录回答：**谁、什么时候、对什么、改了什么、改成什么**。

参照：SAP 变更凭证（表/字段级旧值新值）、NetSuite System Notes（单据时间线）、Salesforce Field History（跟踪字段）、GitHub Audit Log（筛选+导出+correlation id）。

审计只读、不可删除、不可编辑。

## 2. 页面结构

```
┌ 操作记录 ───────────────────────────────────── [导出 ▾] ┐
│ 当前筛选 128 条 · 失败 2 条 · 涉及单据 46 张            │
├──────────────────────────────────────────────────────────┤
│ 时间 [近 7 天 ▾]  类型 [全部 ▾]  关键字 [单号/商品/人]   │
│ [筛选 ·N]   [保存为视图 ▾]                              │
├──────────────────────────────────────────────────────────┤
│ 视图：列表 ｜ 时间线                                     │
├──────────────────────────────────────────────────────────┤
│ 表格 / 时间线内容                                        │
└──────────────────────────────────────────────────────────┘
```

页头只有导出（审计只读，无写操作）。

## 3. 统计条

| 指标 | 说明 |
|---|---|
| 操作数 | 当前筛选的记录数；仅时间筛选为今天时标「今日操作」，其他情况标「当前筛选」 |
| 失败数 | 红色，点击只看失败 |
| 涉及单据数 | 当前筛选内按 target_kind + target_id 去重，未知对象不计作单据 |
| 危险操作数 | 撤销 / 作废 / 更正 / 盘点回写 / 目录发布，橙色，点击筛选 |

所有统计与列表使用同一筛选条件、同一读取水位；计数粒度为成功事件或失败尝试，不把同一次操作的库存/流水证据另计操作数。

## 4. 列表视图

| 列 | 说明 |
|---|---|
| 时间 | 精确到秒，上海时区 |
| 类型 | 图标 + 中文：入库确认 / 入库撤销 / 出库确认 / 库存调整 / 盘点回写 / 目录发布 / 更正 / 登录 |
| 对象 | 单号或商品/仓库，可点进单据 |
| 变更摘要 | 一句话：「状态 待确认→已入账；包数 216→240」 |
| 渠道 | 网页端 / 手持终端 / 小程序；历史无记录显示未记录 |
| 结果 | 完成 / 失败 / 已取消 / 结果待核实 / 未记录，错误原因中文，不附原始错误码 |

颜色规则：
- 危险操作（撤销、作废、更正、盘点回写、目录发布）→ 橙色标签；
- 失败 → 红色；
- 普通 → 默认色。

默认按时间倒序，50/页。

## 5. 时间线视图

按对象聚合，像 NetSuite System Notes：

```
RK-20261109-0031 · 入库单
├ 11-09 10:12:03 确认入账  操作人  网页端  待确认→已入账
│  └ 关联证据：库存前后值、流水（不是另造两次操作）
└ 11-09 10:10:01 创建单据  操作人  网页端  —
```

用途：查一张单的完整历史，比列表更直观。

时间线视图按“对象”分组，默认展示最近 20 个对象，可搜索单号。

对象详情中的操作时间线与审计页共用事件来源，必须包含该对象的失败尝试，不能只在审计页显示失败。失败不能表现为状态已改变；只有已确认回滚或尚未开始业务写入的尝试显示「未生效」，提交结果无法确认时显示「结果待核实」。

## 6. 详情抽屉

```
┌ 操作详情 · 入库确认 RK-20261109-0031 ─────────────────┐
│ 时间 2026-11-09 10:12:03  操作人  渠道 网页端         │
│ 结果 完成                                             │
├───────────────────────────────────────────────────────┤
│ 变更字段（3）                                          │
│ 字段        │ 变更前     │ 变更后                     │
│ 状态        │ 待确认     │ 已入账                     │
│ 包数（合计）│ 216 包     │ 240 包                     │
│ 吨数（合计）│ 64.8000 吨 │ 72.0000 吨                 │
├───────────────────────────────────────────────────────┤
│ 关联证据（仅展示实际存在的库存操作/流水/审计）         │
│ ▸ 库存前后值、流水明细                                 │
├───────────────────────────────────────────────────────┤
│ ▸ 原始数据（默认折叠；展开后含追踪号/原值及诊断操作） │
└───────────────────────────────────────────────────────┘
```

规则：
1. 默认只显示变化字段，字段名转中文并带单位；
2. 未变化字段折叠「显示全部字段」；
3. 同一次请求仅关联真实已持久化事件，不把单笔事务虚构成库存/流水/审计三次业务操作；
4. 原始JSON、原始值、错误码与追踪号只在已登录的「原始数据」折叠区按需读取、展示/复制/按追踪号查询或导出；其他详情区域、时间线、列表及普通导出均不展示。始终脱敏密码、凭证、token，登录检查不能只靠前端；
5. 对象可点，跳当前单据。

## 7. 筛选

- 快捷：时间范围（今天 / 昨天 / 近 7 天 / 本月 / 自定义）、类型
- 关键字：一次匹配单号、商品编码、操作人
- 抽屉：渠道、结果、危险操作；追踪号查询只在详情原始数据区，不进入普通列表条件/URL
- 支持保存为视图（如「本周撤销记录」「失败操作」）

## 8. 导出

| 格式 | 内容 |
|---|---|
| XLSX / CSV | 当前筛选结果：时间、类型、对象、变更摘要、渠道、结果（全部业务中文） |
| JSON | 单条或单追踪号的脱敏诊断记录，仅登录详情原始数据折叠区导出 |

- 单次导出上限 10 万行，超出提示缩小范围；
- 导出不含原始 JSON（体积大），需要时单独导出 trace。
- 普通 XLSX/CSV 复用公共异步导出任务（POST /api/v1/web/exports）；GET 仅用于下载，不另建同步生成接口。诊断 JSON 使用详情原始数据区的专用受保护入口。

## 9. 保留与完整性

- 记录永久保留，不提供删除与修改；
- 页面顶部标注「审计记录不可修改」，让使用者知道可信；
- 超 1 年支持按年导出归档，导出后仍保留；
- 历史导入数据不生成审计（无对应操作）。

## 10. 性能

- 索引：created_at、action、target_id、trace_id；
- 默认查询近 7 天，避免全表扫描；
- 列表不返回 JSON，详情按需加载；
- 服务端解析变更字段，前端不解析原始 JSON。

## 11. 接口

| 接口 | 说明 |
|---|---|
| GET /api/v1/web/lists/audit | 列表（扩展筛选与关键字） |
| GET /api/v1/web/lists/audit/:id | 详情（结构化变更字段 + 同 trace 记录） |
| GET /api/v1/web/lists/audit/:id/raw?traceId= | 新增登录详情原始数据区专用投影 |
| GET /api/v1/web/lists/audit/timeline?target= | 按单号/名称筛选最近对象的时间线视图 |
| GET /api/v1/web/lists/audit/objects/:kind/:targetId | 对象详情事件分页；身份为类型 + 主键 |
| POST /api/v1/web/exports | 普通审计 XLSX/CSV 异步生成（kind=audit） |
| GET /api/v1/web/exports/:id/download | 已完成的普通导出下载 |
| GET /api/v1/web/lists/audit/:id/trace.json | 导出单 trace JSON |

普通响应changes为结构化业务投影：`{field, label, before, after, unit}`；before/after按字段映射中文，原始值只在raw响应。timeline/export等静态路由必须注册在/:id之前，避免被当ID。分页/保存视图/导出上限与公共交互仅引用WEB_UX_SPEC。

## 12. 边界

| 情况 | 处理 |
|---|---|
| 失败操作 | 回滚后单独记录失败尝试，中文原因；原始错误码仅详情原始数据区；提交结果不确定标「结果待核实」 |
| 无变更字段（登录等） | 只显示基本信息 |
| JSON 超大 | 预览超过 256 KiB、诊断文件超过 100 MiB 或记录超过 10 万条直接拒绝，不静默截断 |
| 对象已删除 | 显示原业务单号/名称，不跳转；内部ID只在原始数据区 |
| 历史导入数据 | 不生成审计 |
| 时区 | 统一上海时间 |

## 13. 不做

| 不做 | 原因 |
|---|---|
| 撤销/回滚审计 | 审计不可变 |
| 删除审计 | 合规 |
| 表级审计查询 | 业务视角够用 |
| 实时推送 | 单用户 |
| 审计报表图表 | 导出到 Excel 分析即可 |

## 14. 验收

1. 列表倒序、分页正确，统计条与筛选结果一致；
2. 危险操作与失败正确着色；
3. 时间线视图按对象聚合，顺序正确；
4. 详情只显示变化字段，字段名/单位正确；
5. 登录详情原始数据区可查脱敏追踪记录/导出；列表/时间线/普通导出无原值及追踪号，未登录raw接口拒绝；
6. 关键字一次匹配单号/商品/人；
7. 保存视图后刷新仍生效；
8. 导出字段与列表一致，上限提示正确；
9. 1440/1280 截图（列表、时间线、详情、失败筛选）。

## 15. 持久化与接口前置（需要新增服务能力）

B6c（UI-7）复用operation_log成功业务审计；该表当前无result/channel，不推断旧记录成功或失败。M-AUDIT-ATTEMPTS为成功日志补可空channel/target_kind/业务编号等投影证据，新建operation_attempts保存attempt_id、actor、channel、action、target_kind/业务编号、result/error_code、trace_id、发生时间、脱敏输入摘要及failure_reason。没有证据的历史字段NULL并标未记录，不回填假渠道/结果。

成功审计仍与库存同事务；失败尝试在业务事务回滚后独立持久化，并标「未生效」。幂等重放不重复成功事件；失败尝试按请求attempt_id去重，另次重试可有新尝试。失败记录写入异常须可监测，不能宣称全部失败已永久落库。查询合并投影区分business_event/attempt，统计按该粒度、业务对象去重，历史未知单列。

渠道由服务端从已验证令牌对应的会话或固定路由判定，不读取客户端自报的渠道请求头。共享登录路由在身份验证前无法确定真实渠道时记 NULL；请求正文中的 channel 不作为失败尝试的可信渠道。操作人同样以验证后的身份为准，登录失败的自报账号只可作为白名单摘要中的 claimedUsername。

input_summary 采用动作/路由白名单：仅允许业务编号、对象标识、商品/仓库/客户/供应商编码、业务日期、包数/重量数值及条目数量等必要信息；登录失败只允许 claimedUsername。未知字段默认丢弃；密码、令牌、Cookie、Authorization、完整请求体、上传内容、自由文本备注/原因及堆栈不进入摘要。集合仅记录必要数量或有界的白名单元素，超限明确标记。保存前再次递归脱敏嵌套对象、数组及可解析的 JSON 字符串；读取旧 raw 时也必须执行同等脱敏。

新事件结果标识统一为 success（完成）、failed（失败）、cancelled（已取消）、unknown（结果待核实）；历史没有证据的 NULL 显示未记录。effect_state 单独区分 applied / not_applied / unknown，不以 HTTP 错误等同业务未生效。批量每单一个 attempt_id，同请求共享服务端 trace；成功事件携带 attempt_id，失败尝试独立保存，不把整批包成事务。失败留证异常只输出脱敏诊断和可监测计数，不吞掉原业务错误，不返回“留证成功”。

B6c-1 实施边界：015_audit_attempts、成功审计可空扩展、失败留证及独立合成库验收；审计查询、raw/trace、审计页与对象详情时间线展示在后续 B6c-2 实现。本节中的页面要求是后续验收目标，不表示本次已有页面能力。

结构化字段差异由服务端按对象schema映射、脱敏；关联库存操作/流水沿真实外键与追踪关系，不伪造事件。列表不加载before/after原始JSON，raw/trace.json单独登录+渠道校验、大小限制、脱敏导出；响应不缓存到公共视图。索引按查询过滤和时间排序复合路径经EXPLAIN验证，不以多个单列索引宣称完成。迁移非空拒绝丢证据down。

修订记录：C13 补失败尝试独立表/事务、历史未知、结构化投影与静态路由顺序，标明新增服务。
修订记录：C16 查询/导出引用公共契约，诊断追踪查询从普通列表移出。
修订记录：C17 落实登录详情原始数据例外，移除列表/正文/普通导出中的原值和追踪号。
修订记录：B6c-1 按已确认裁定统一当前筛选统计、异步普通导出、目录发布危险标记及结果枚举；明确服务端渠道、输入白名单、递归脱敏与对象详情失败时间线。

修订记录：B6c-2 普通响应只返回业务投影；主键采用 event:ID / attempt:UUID，带来源和来源主键防冲突。列表不读取 before/after/input_summary。详情按动作注册表生成变化；raw 按需读取、Web 会话鉴权、no-store。traceId 仅在 raw 内精确关联当前记录的同一 trace，并以游标继续分页；诊断 JSON 完整生成后才发送，失败或客户端取消不发布临时文件。所有诊断下载重新鉴权，大小和条数上限集中在共享常量。时间线先分页最近 20 个对象，再批量取事件；单对象可继续分页。对象身份只用类型+ID，显示已保存的名称/单号，缺失显示未记录，删除后不提供跳转。

诊断大小保护同时检查待读取原文的 JSON 字节量和脱敏后的完整响应字节量；读取前超限同样拒绝，避免先把过大原文加载进内存。不会通过截断原文、跳过事件或省去剩余页来生成看似完整的文件。
