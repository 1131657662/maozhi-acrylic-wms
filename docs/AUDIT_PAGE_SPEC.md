# 操作记录页面规范（AUDIT_PAGE_SPEC）

> 本文档中的状态、类型、结果等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 定位

操作记录回答：**谁、什么时候、对什么、改了什么、改成什么**。

参照：SAP 变更凭证（表/字段级旧值新值）、NetSuite System Notes（单据时间线）、Salesforce Field History（跟踪字段）、GitHub Audit Log（筛选+导出+correlation id）。

审计只读、不可删除、不可编辑。

## 2. 页面结构

```
┌ 操作记录 ───────────────────────────────────── [导出 ▾] ┐
│ 今日 128 条 · 失败 2 条 · 涉及单据 46 张                │
├──────────────────────────────────────────────────────────┤
│ 时间 [近 7 天 ▾]  类型 [全部 ▾]  关键字 [单号/商品/人]   │
│ [筛选 ·N]   [保存为视图 ▾]                              │
├──────────────────────────────────────────────────────────┤
│ 视图：列表 ｜ 时间线                                     │
├──────────────────────────────────────────────────────────┤
│ 表格 / 时间线内容                                        │
└──────────────────────────────────────────────────────────┘
```

页头只有导出（审计只读，无写操作）。

## 3. 统计条

| 指标 | 说明 |
|---|---|
| 今日操作数 | 当前日期的记录数 |
| 失败数 | 红色，点击只看失败 |
| 涉及单据数 | distinct target_id |
| 危险操作数 | 撤销 / 作废 / 更正 / 盘点回写，橙色，点击筛选 |

## 4. 列表视图

| 列 | 说明 |
|---|---|
| 时间 | 精确到秒，上海时区 |
| 类型 | 图标 + 中文：入库确认 / 入库撤销 / 出库确认 / 库存调整 / 盘点回写 / 目录发布 / 更正 / 登录 |
| 对象 | 单号或商品/仓库，可点进单据 |
| 变更摘要 | 一句话：「状态 待确认→已入账；包数 216→240」 |
| 渠道 | 网页端 / 手持终端 / 小程序；历史无记录显示未记录 |
| 结果 | 完成 / 失败 / 未记录，错误原因中文，不附原始错误码 |

颜色规则：
- 危险操作（撤销、作废、更正、盘点回写、目录发布）→ 橙色标签；
- 失败 → 红色；
- 普通 → 默认色。

默认按时间倒序，50/页。

## 5. 时间线视图

按对象聚合，像 NetSuite System Notes：

```
RK-20261109-0031 · 入库单
├ 11-09 10:12:03 确认入账  操作人  网页端  待确认→已入账
│  └ 关联证据：库存前后值、流水（不是另造两次操作）
└ 11-09 10:10:01 创建单据  操作人  网页端  —
```

用途：查一张单的完整历史，比列表更直观。

时间线视图按“对象”分组，默认展示最近 20 个对象，可搜索单号。

## 6. 详情抽屉

```
┌ 操作详情 · 入库确认 RK-20261109-0031 ─────────────────┐
│ 时间 2026-11-09 10:12:03  操作人  渠道 网页端         │
│ 结果 完成                                             │
├───────────────────────────────────────────────────────┤
│ 变更字段（3）                                          │
│ 字段        │ 变更前     │ 变更后                     │
│ 状态        │ 待确认     │ 已入账                     │
│ 包数（合计）│ 216 包     │ 240 包                     │
│ 吨数（合计）│ 64.8000 吨 │ 72.0000 吨                 │
├───────────────────────────────────────────────────────┤
│ 关联证据（仅展示实际存在的库存操作/流水/审计）         │
│ ▸ 库存前后值、流水明细                                 │
├───────────────────────────────────────────────────────┤
│ ▸ 原始数据（默认折叠；展开后含追踪号/原值及诊断操作） │
└───────────────────────────────────────────────────────┘
```

规则：
1. 默认只显示变化字段，字段名转中文并带单位；
2. 未变化字段折叠「显示全部字段」；
3. 同一次请求仅关联真实已持久化事件，不把单笔事务虚构成库存/流水/审计三次业务操作；
4. 原始JSON、原始值、错误码与追踪号只在已登录的「原始数据」折叠区按需读取、展示/复制/按追踪号查询或导出；其他详情区域、时间线、列表及普通导出均不展示。始终脱敏密码、凭证、token，登录检查不能只靠前端；
5. 对象可点，跳当前单据。

## 7. 筛选

- 快捷：时间范围（今天 / 昨天 / 近 7 天 / 本月 / 自定义）、类型
- 关键字：一次匹配单号、商品编码、操作人
- 抽屉：渠道、结果、危险操作；追踪号查询只在详情原始数据区，不进入普通列表条件/URL
- 支持保存为视图（如「本周撤销记录」「失败操作」）

## 8. 导出

| 格式 | 内容 |
|---|---|
| XLSX / CSV | 当前筛选结果：时间、类型、对象、变更摘要、渠道、结果（全部业务中文） |
| JSON | 单条或单追踪号的脱敏诊断记录，仅登录详情原始数据折叠区导出 |

- 单次导出上限 10 万行，超出提示缩小范围；
- 导出不含原始 JSON（体积大），需要时单独导出 trace。

## 9. 保留与完整性

- 记录永久保留，不提供删除与修改；
- 页面顶部标注「审计记录不可修改」，让使用者知道可信；
- 超 1 年支持按年导出归档，导出后仍保留；
- 历史导入数据不生成审计（无对应操作）。

## 10. 性能

- 索引：created_at、action、target_id、trace_id；
- 默认查询近 7 天，避免全表扫描；
- 列表不返回 JSON，详情按需加载；
- 服务端解析变更字段，前端不解析原始 JSON。

## 11. 接口

| 接口 | 说明 |
|---|---|
| GET /api/v1/web/lists/audit | 列表（扩展筛选与关键字） |
| GET /api/v1/web/lists/audit/:id | 详情（结构化变更字段 + 同 trace 记录） |
| GET /api/v1/web/lists/audit/:id/raw?traceId= | 新增登录详情原始数据区专用投影 |
| GET /api/v1/web/lists/audit/timeline?targetId= | 时间线视图 |
| GET /api/v1/web/lists/audit/export | 导出（格式参数） |
| GET /api/v1/web/lists/audit/:id/trace.json | 导出单 trace JSON |

普通响应changes为结构化业务投影：`{field, label, before, after, unit}`；before/after按字段映射中文，原始值只在raw响应。timeline/export等静态路由必须注册在/:id之前，避免被当ID。分页/保存视图/导出上限与公共交互仅引用WEB_UX_SPEC。

## 12. 边界

| 情况 | 处理 |
|---|---|
| 失败操作 | 回滚后单独记录失败尝试，中文原因；原始错误码仅详情原始数据区 |
| 无变更字段（登录等） | 只显示基本信息 |
| JSON 超大 | 截断 + 提示导出 |
| 对象已删除 | 显示原业务单号/名称，不跳转；内部ID只在原始数据区 |
| 历史导入数据 | 不生成审计 |
| 时区 | 统一上海时间 |

## 13. 不做

| 不做 | 原因 |
|---|---|
| 撤销/回滚审计 | 审计不可变 |
| 删除审计 | 合规 |
| 表级审计查询 | 业务视角够用 |
| 实时推送 | 单用户 |
| 审计报表图表 | 导出到 Excel 分析即可 |

## 14. 验收

1. 列表倒序、分页正确，统计条与筛选结果一致；
2. 危险操作与失败正确着色；
3. 时间线视图按对象聚合，顺序正确；
4. 详情只显示变化字段，字段名/单位正确；
5. 登录详情原始数据区可查脱敏追踪记录/导出；列表/时间线/普通导出无原值及追踪号，未登录raw接口拒绝；
6. 关键字一次匹配单号/商品/人；
7. 保存视图后刷新仍生效；
8. 导出字段与列表一致，上限提示正确；
9. 1440/1280 截图（列表、时间线、详情、失败筛选）。

## 15. 持久化与接口前置（需要新增服务能力）

B6c（UI-7）复用operation_log成功业务审计；该表当前无result/channel，不推断旧记录成功或失败。M-AUDIT-ATTEMPTS为成功日志补可空channel/target_kind/业务编号等投影证据，新建operation_attempts保存attempt_id、actor、channel、action、target_kind/业务编号、result/error_code、trace_id、发生时间、脱敏输入摘要及failure_reason。没有证据的历史字段NULL并标未记录，不回填假渠道/结果。

成功审计仍与库存同事务；失败尝试在业务事务回滚后独立持久化，并标「未生效」。幂等重放不重复成功事件；失败尝试按请求attempt_id去重，另次重试可有新尝试。失败记录写入异常须可监测，不能宣称全部失败已永久落库。查询合并投影区分business_event/attempt，统计按该粒度、业务对象去重，历史未知单列。

结构化字段差异由服务端按对象schema映射、脱敏；关联库存操作/流水沿真实外键与追踪关系，不伪造事件。列表不加载before/after原始JSON，raw/trace.json单独登录+渠道校验、大小限制、脱敏导出；响应不缓存到公共视图。索引按查询过滤和时间排序复合路径经EXPLAIN验证，不以多个单列索引宣称完成。迁移非空拒绝丢证据down。
