# UI 统一实施方案（UI-0 / UI-1）

## 1. 依据与验证边界

- 产品：茂智云仓 · 腈纶仓储管理系统（茂智腈纶仓 / Maozhi Acrylic Fiber WMS）。
- UI-1 代码基线：`84fb14d`（B3c）。本文件区分设计目标、本批次改动和实际验证，不把上一会话的描述当作验收证据。
- 信息架构参考旧系统已确认的业务模块、字段和作业顺序；视觉与交互采用现有 Ant Design Pro。旧系统业务源码只读，不复制；废弃设计导出不作为视觉、布局或尺寸依据。
- 使用仓库当前依赖：Ant Design `6.7.0`、ProComponents `3.1.15-9`、React `19.3.1`、Umi `4.7.3`。本批次不升级依赖。
- 本轮视觉核查只覆盖入库列表、登记、详情的 1440×960 / 1280×800 视口。其他模块属于后续迁移范围；390px、PDA 实体设备、小程序模拟器和生产验收不能由本轮截图推断。

## 2. 基线问题与 UI-1 决策

| 位置 | 基线问题 | 本批次处理 |
|---|---|---|
| `BusinessList/index.tsx` | 列表有 PageContainer，入库登记和详情另用自定义页头 | 三页统一 PageContainer、单一 h1、返回路径和操作区；标题使用 `fontSizeHeading4` |
| `BusinessList/table.tsx` | 共用表格只有固定空态文字 | 增加可选 `emptyText`，其他调用方保留原默认文案 |
| `inbound/list.tsx` | 无查询结果时只有文字，没有就近登记入口 | 使用 Empty，保留既有筛选提示并补充登记入口；页头保留唯一主要登记按钮 |
| `inbound/editor.tsx` | 英文 eyebrow、自定义提示条与列表不一致；字段分组不清楚 | 使用 Alert、单据信息/商品明细分组与响应式栅格；包数与吨数继续独立录入 |
| `inbound/detail.tsx` | 加载/错误时页头消失；生命周期在单据信息之前；区块间距不统一 | 保留页头和返回入口，使用 Skeleton / Result / Alert；按确认提示、入库信息、商品明细、生命周期排序 |
| `styles/base.css` | 全局 h1/h2 规则影响组件内部标题；存在未使用的独立尺寸变量 | 删除未使用的 `--space` / `--radius`，将旧标题样式收窄到尚未迁移页面和登录页，避免连带重做其他页面 |
| 三份 handoff 文档 | 把已废弃设计资产列为参考依据 | 移除相关资产/索引引用，写清旧信息架构与 Ant Design Pro 的依据 |

## 3. 设计 token 与布局约定

| 类别 | 约定 | UI-1 状态 |
|---|---|---|
| 品牌 | 沿用现有 `colorPrimary: #105957`、`colorBgLayout: #f3f6f5`；不另建色板 | 保留现有主题 |
| 正文与表面 | 使用 `colorText` / `colorTextSecondary` / `colorBgContainer` / `colorBorderSecondary` | 使用组件主题，未全局迁移遗留 CSS |
| 状态 | 成功、警告、错误、信息使用 AntD 语义 token；保留文字标识 | 复用现有 StatusTag、确认提示；未知状态的全站统一另批处理 |
| 字号 | 页面标题 `fontSizeHeading4`（20px），区块标题 `fontSizeLG`，正文 `fontSize`，辅助 `fontSizeSM` | 列表共享标题及入库登记/详情对齐 |
| 间距 | 页面内容使用 `paddingLG`；区块使用 `margin`；字段间隔使用 `marginLG` | 入库三页对齐，不新增重复尺寸变量 |
| 圆角与阴影 | 优先组件 token，不额外包多层 Card 或增加装饰阴影 | 保留现有主题；全站 `borderRadiusLG` 收敛为后续目标 |
| 密度 | 表格保留服务端分页、排序、列设置、导出和内部横向滚动 | 当前保持 `middle`；`small` 密度及首屏行数目标尚待其他页面统一批次验证 |

### 列表

使用 `PageContainer + QueryFilter + ProTable`。筛选状态继续由 URL 驱动，分页、排序、选择和导出语义保持原样。表格内部允许横向滚动，页面本身不横向溢出。筛选失败时明确提示错误，不把失败伪装成空列表或零值。

### 表单

使用 PageContainer、ProForm 和 AntD 栅格。供应商与仓库在桌面并排，备注独占行；商品、包数、总吨数属于同一明细。小屏列宽降级为单列。提交仍创建待确认单据，不能因为页面改造提前入账。普通提交错误保留字段值；403 给明确无权限结果和返回入口。

### 详情

标题使用单号，状态与返回入口位于页头。确认区保持独立明确操作，继续二次确认；详情与明细随后展示，生命周期操作放在末尾。不同区块使用统一间距。加载、错误和无权限时保留页面身份及安全返回路径。

## 4. 四种状态

| 状态 | 规则 |
|---|---|
| 加载 | 页头保留，内容区显示 Skeleton；不在请求未返回时显示“暂无数据” |
| 空态 | 表格内保留筛选/重置指引和登记入口，避免两个同名主要按钮；空态不得掩盖请求错误 |
| 错误 | Alert 显示错误并提供重试；不展示失效的结果数据，不改变用户筛选 |
| 无权限 | Result 403 给清晰操作范围和返回路径；不新增角色、组织或多用户审批模型 |

## 5. 本批次边界

UI-1 只改 `AGENTS.md`、BusinessList 的 index/table、inbound 的 list/editor/detail、base.css、三份 handoff 文档和本方案。

三份 handoff 文档的清理是本次明确授权的只读参考区例外，范围仅限废弃设计引用和对应索引编号；不改旧业务源码，也不读取废弃设计图片作为 UI 依据。

不修改 API、contracts 或 migrations；不增加业务日期、更正、取样、分批发货等业务功能。共享列表可选空态参数不改变接口或查询契约。入库仍只填包数和独立总吨数，不扫码、不按统一件重推算重量。

## 6. 后续迁移顺序（未在 UI-1 实施）

1. 出库工作台、计划编辑和详情：统一页头、流程与实扫/计划/确认信息层级。
2. 库存概览和流水：统一汇总、主表、口径说明与空态。
3. 盘点与操作记录：统一筛选、宽表、暂停提示和详情 Drawer。
4. 明细、月报、周转率、库龄：统一高密度表格、对账和不可验证提示。
5. 主数据与单据编号配置：统一加载、403、错误和表单布局。
6. 登录页：保留独立认证壳，再单独处理 token 和移动端留白。

仓管的信息密度以编码、单号、仓库、状态、关键时间、包数/吨数和行级操作为核心，不把逐行表格改成展示卡片。尚无本轮可核验的旧系统行高/首屏行数对照；任何密度目标都不能写成旧系统实测结论。

- 截图为原始视口宽度的全页 PNG；全页高度可以超过视口高度。每张图片的同名 JSON 记录页面 URL、视口、文档尺寸和标题，文件哈希及源码来源见本地证据清单。
- 临时截图用例与配置只存 `.local/evidence`，不进入产品提交；此前来源未验证的图片单独保存在 `ui1-inherited/`，不作为本次验收依据。
- 实际测试环境：现有 `scripts/e2e-api.ts` 创建本机 `127.0.0.1:3307` MySQL 随机 `maozhi_test_*` 库，并校验实例目录为本仓库 `.local/mysql/data/`；当前实现不是内存库。不得连接生产或复用用户作业库。
- 命令原始输出分别保存在 `ui1-test.log`、`ui1-build.log`、`ui1-e2e.log`；验收只引用实际运行结果，不以代码已写完替代测试通过。
- 本批次只涉及 Web。小程序模拟器、Android 模拟器、实体 PDA 和生产环境均未验收。
