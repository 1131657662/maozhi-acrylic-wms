## 3. 四种范式：同样的标题，不同的阅读顺序

| 范式／使用人此刻的问题 | 布局与信息层级 | 组件与边界 |
|---|---|---|
| **A 总览**：「今天什么要办？」和「这段时间发生了什么？」是两件事 | 工作台保持四指标 → 待我处理 → 目录／交接 → 车号 → 最近操作／快捷入口 → 14 天趋势；盘点与扫码超时入口不能沉到下一屏。看板先交代期间和口径，随后按问题分图，每块显示实际时间窗、单位、核验状态。 | `PageShell`、`Card`、指标、待办链接。工作台数字先出，保留延后绘制的 SVG；看板用现有按需 ECharts。保留工作台四指标和看板七区，不机械照搬「每页四卡两图」。无历史依据不画假趋势。 |
| **B 查单与对账**：「我查的是哪些记录，合计算的是什么？」 | 标题／建单入口 → 快捷条件与已用条件 → 同位置工具栏／批量栏 → 表头、业务行、适用的合计 → 分页。报表在结果附近保留口径、水位、核验和原快照；图表是筛选入口，不是另算一套数字。 | `BusinessList` 及既有 `ReportShell`；数字右对齐、长名称可读全。表内横滚不等于页面溢出。只有原本支持的页才显示勾选、导出、合计；库存流水不用大表所有能力。 |
| **C 录入与核对**：「哪些数是我填的，按下去库存会不会变？」 | 录入按单据信息 → 往来／仓库 → 商品行 → 提交结果；详情按单号与状态 → 影响摘要 → 明细／差异 → 单据动作与记录。计划、扫码证据、人工实发是三个独立区。 | 表头和字段用 `ProForm`、`MasterSelect`，只读用 `ProDescriptions` 与明细表；更正、调整沿用所在单或库存格的抽屉。具体单据详情按 `WEB_UX_SPEC` §7 把唯一主操作留给操作条，页头不再复制；登录／404 用独立极简壳。 |
| **D 配置与运维**：「这次修改影响哪一项、哪些设备或哪份备份？」 | 先选对象／页签，右侧或下方展示该项当前值、作用范围与局部动作。六项主数据、两个维护页签沿用现有入口；编号是只读说明；消息是收件列表。移动分组而非再建一层侧栏。 | `Tabs`、`Segmented`、`Descriptions`、局部表单与确认弹窗。个人资料和改密可分栏，会话列表独占整行。显示当前账号来自会话；不加入组织、权限树、角色管理。 |

## 4. 共享 Token 草案与冲突处理

已从 `apps/web` 的实际依赖解析核对：React **19.3.1**、antd **6.7.0**、ProComponents **3.1.15-9**、图标 **6.3.2**、Umi Max **4.7.3**、ECharts **6.1.0**。Pro v6 是项目脚手架，不表示 ProComponents 的主版本是 6。沿用 `apps/web/src/app.tsx:50` 的 ConfigProvider 与 `apps/web/src/theme/design-tokens.ts:4` 的共享字典，不改依赖、字体或引入第二个主题。

| 类别 | 来源／目标值 | 在本项目的用途 |

## 5. 四类模板：按真实页面走一遍

**A｜工作台与看板。** 以 `/` 为例：标题与次级刷新 → 截至时间、入账口径 → 四张指标 → 四列待办 → 后续六个业务区块按 §3 的原顺序组合。卡内分出「指标名/数值＋单位/说明或趋势」；超时和锁仓以文字加状态提示，待办每列独立滚动。`/dashboard` 用同一标题和区块组件，改为「快捷期间＋起止日期＋口径 → 收发趋势、期间对比、排行、库龄、周转、热力、时效」。失败只占原区块并给可用动作；已核验零、未知、整块请求失败三种画面分开。

**B｜入库列表与报表。** `/inbound` 首行左侧「入库记录」，右侧仅「登记入库」；接着直接查登记时间／单号，旁边显示高级条件数量。查询结果标题与工具栏不因勾选多占一行；单号左固定，原始／入账状态和操作右固定，可横滚读供应商及数量。首次载入用骨架、排序翻页保留旧结果并限制对占位行的操作。`/reports/details` 在同一表壳插入口径、水位与对账，`/stock` 用自己的本页合计；不能把两个「合计」抽成同一算法。1440/1280 都要能聚焦首行、看到状态全文、读出筛选范围。

**C｜建单与确认。** `/inbound/new`：单号预览／业务日期 → 供应商、仓库等表头 → 商品行的包数与本次总吨数 → 「创建待确认入库单」。标签常显、长表单分组；422 定位到具体行和字段，失败不清输入，重复提交不中第二次。`/outbound/:id`：单号／状态／返回 → 计划与已发摘要 → 清点证据（不计库存）→ 本次人工实发、与待发差额 → 明确确认及操作记录；有差异也不在页面擅判资格。加载／失败保留标题与返回，不显示过期可写操作。调整或更正保留抽屉：先列前值、后值、差额、原因；取消不发请求，关闭后焦点回触发处。数量更正和业务日期更正不并成一个命令。

**D｜配置与通知。** `/system/document-numbering`：页题与说明 → 入库／出库切换 → 当前类别的下一号、未占用提示、刷新预览 → 三条只读规则。无规则、不可取号、请求失败分别呈现。`/maintenance` 保留备份／健康两页签；备份区保留唯一主操作，清理或恢复与主操作分开，确认时显示对象、后果及既有确认词；不新增覆盖原库入口。六类基础资料收进页内页签；`/messages` 则保留类型／阅读状态、通知正文、已读动作，不能为了统一而套成保存设置的表单。
