# 编号规则规范（NUMBERING_SPEC）

> 本文档中的状态、类型等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 范围

| 对象 | 前缀 | 位宽 | 容量 | 生成方式 |
|---|---|---|---|---|
| 入库单 | `RK-` | 日期 + 3 位 | 999 / 日 | 系统按日生成 |
| 出库单 | `CK-` | 日期 + 3 位 | 999 / 日 | 系统按日生成 |
| 更正单 | `GZ-` | 日期 + 3 位 | 999 / 日 | 系统按日生成 |
| 盘点单 | `PD-` | 日期 + 3 位 | 999 / 日 | 系统按日生成 |
| 客户 | `C` | 5 位 | 99,999 | 系统流水 |
| 供应商 | `S` | 4 位 | 9,999 | 系统流水 |
| 仓库 | `W` | 2 位 | 99 | 系统流水 |
| 商品 | 无强制 | — | — | 手工填写（见第 5 节） |
| 车辆 | 无编码 | — | — | 车牌即标识 |

位宽按 20 年容量选定，**不自动扩位**；用尽时报错并要求计划重编。

## 2. 单据号

### 2.1 格式

```
RK-YYYYMMDD-NNN
CK-YYYYMMDD-NNN
GZ-YYYYMMDD-NNN
PD-YYYYMMDD-NNN
```

示例：`RK-20261110-001`

规则：
1. 入库、出库在新建时取业务日期（上海时区），之后调整业务日期不改原单号；更正单按 DOMAIN_RULES 不设业务日期，取上海创建日，不使用服务器 UTC 日期；
2. 流水号按「单据类型 + 日期」独立计数，每天从 001 开始；
3. 位宽 3 位，单日超过 999 单报错，提示「编号容量已用尽，需计划重编」，不静默进位、不自动扩位；
4. 号码只在单据成功创建时占用；事务回滚不消耗号码；
5. 号码不可复用，作废单据的号码也不回收；
6. 历史导入单保持原样（如 `IN20261021001`），不重新编号；
7. 已被旧规则发出 4 位的号码（如有）保持原样，解析时按任意位数匹配。
8. 新号固定 3 位，编号规则页只读，不再提供 2–8 位调整；已有当日序号继续递增，不重置。例如旧号 `0088` 后发 `089`；当日已有序号达到 999 则拒绝继续创建。

B6a-num 实施 RK/CK/GZ 与三类主数据编码；PD 按日序号统一及历史主数据重编属于 B10，本批不改盘点编号。014 回填三类主数据 `legacy_code`、初始化已有规范编码的最大计数并固定编号规则为 3 位，不改已有编码或单号。新建客户/供应商/仓库请求禁止传 `code`，支持幂等键重放；编辑禁止改编码。014 非空回退在任何 DDL 前拒绝，已有数据须通过备份恢复方案回退。

### 2.2 为什么保留日期

- 按天对账、按天排查时可直接从单号看日期；
- 单号天然分段，排序稳定；
- 与老系统 `IN2026…` 的区别一眼可见，不会混淆新老数据。

### 2.3 为什么用 RK / CK / GZ / PD

- 中文语境下的拼音首字母，仓管不需要记英文缩写；
- `IN` / `OUT` 过于通用（`IN` 是英文介词），不适合做正式前缀；
- 与历史的 `IN` / `OUT` 明确区分，切换期不会混号。

## 3. 主数据编码

### 3.1 格式

| 对象 | 格式 | 示例 | 容量 |
|---|---|---|---|
| 客户 | `C` + 5 位流水 | `C00001` | 99,999 |
| 供应商 | `S` + 4 位流水 | `S0001` | 9,999 |
| 仓库 | `W` + 2 位流水 | `W01` | 99 |

规则：
1. **由系统生成，用户不填写**；
2. 流水号全局递增，不复用，删除不回收；
3. 一个前缀一个计数器，与单据号计数器分开；
4. 编码一旦生成不可修改（改名可以，改编码不行）；
5. 编码唯一索引兜底，生成冲突时自动取下一个；
6. 容量用尽时报错并提示计划重编，**不自动扩位**。

### 3.2 展示规则

界面上**名称优先，编码辅助**：

```
宁波中纤进出口有限公司        C00001
```

- 列表主列显示名称，编码以灰色小字跟在后面（或作为可选列）；
- 下拉选择、详情页标题同样以名称为主；
- 编码提供复制按钮，便于对外沟通。

### 3.3 历史编码处理（切换时重编，方案 B）

切换前导入的数据带老编码（如 `CUST000001`）。采用**切换时统一重编**：

| 项 | 做法 |
|---|---|
| 重编时机 | 切换导入阶段一次性完成，不在上线后逐条改 |
| 旧编码 | 存入 `legacy_code` 字段，可查、可回溯 |
| 映射 | 生成临时映射表（旧码 → 新码），导入与校验共用同一份 |
| 校验 | 客户/供应商/仓库数量不变；单据引用数不变；无孤儿外键 |
| 对外 | 客户详情显示「原编码」，便于与老系统对账 |

## 4. 实现要点

| 项 | 要求 |
|---|---|
| 计数器表 | `document_number_counters`（单据）、`master_code_counters`（主数据），按前缀分行 |
| 并发 | 取号在事务内加锁，冲突时重试或报错，不重复发号 |
| 幂等 | 同一幂等键重放返回原号码，不重新取号 |
| 审计 | 每次发号记录类型、日期、号码、操作人 |
| 迁移 | 计数器记录历史已发最大序号；下次取号加一，必须大于历史最大号（切换校验项） |
| 用尽 | 报错并阻断创建，提示需要计划重编；不允许自动扩位 |

## 5. 商品编码

商品编码保持手工填写：
- 历史商品编码是 ERP 里的业务编码（如 `003`），有外部含义，不能重编；
- 新建商品时手工填，系统只校验唯一与格式；
- 商品编码在单据、库存、报表中作为业务标识出现，必须稳定。

## 6. 验收

1. 新建入库单得到 `RK-YYYYMMDD-001`，同日第二单 `002`；
2. 跨日第一单回到 `001`；
3. 事务失败不消耗号码；
4. 同一幂等键重放返回同一单号；
5. 单日第 1000 单报错，提示容量用尽，不产生 `1000` 号；
6. 新建客户得到 `C00001`，删除后再建得到 `C00002`（不复用）；
7. 客户编码不可编辑；
8. 列表以名称为主、编码为辅；
9. 切换重编后：客户/供应商/仓库数量不变，单据引用无断裂，旧编码可在详情查到；
10. 客户第 100000 个、仓库第 100 个报错并提示计划重编。
