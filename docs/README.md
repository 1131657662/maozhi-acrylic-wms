# 文档索引与权威顺序（docs/README.md）

> 2026-11-09 文档入库状态：C01–C18已按通过的评审和四项用户决策定点修订，闭环见 [DOC_REVIEW.md](DOC_REVIEW.md) §9；规格已对齐不表示服务能力已实现。已有批次的“完成”须按原验收记录区分代码、自动化、设备与生产。011 开发库已按 [应用计划与执行记录](MIGRATION_011_APPLICATION_PLAN.md) 应用；B6a与012的本地验收见 [B6A_ACCEPTANCE.md](B6A_ACCEPTANCE.md)。

## 1. 权威顺序（冲突时从上到下）

1. `AGENTS.md`（项目硬约束）
2. `DOMAIN_RULES.md`（业务规则总纲）
3. `UX_STANDARDS.md`（文案、格式、图标、无硬编码、操作舒适度）
4. `WEB_UX_SPEC.md`（全局交互：操作分层、选择、查询抽屉、商品反查）
5. `REPORT_SPEC.md`（报表会计口径D1–D7及§10更正/重述，算术优先于页面示例；仍服从DOMAIN）
6. 各页面规格（`*_PAGE_SPEC.md`、`*_SPEC.md`）
7. 批次记录（`B*_ACCEPTANCE.md`、`B*_VALIDATION.md`、`B*_IMPLEMENTATION_PLAN.md`）

页面规格与 UX_STANDARDS 冲突时，以 UX_STANDARDS 为准。

## 3. 术语表

| 术语 | 含义 |
|---|---|
| 本系统 | 本项目，替代老系统的仓储业务系统 |
| 老系统 | `https://erp.nbsmzwl.cn`，历史数据与旧版业务入口；文档中常写作“ERP”，两者同义 |
| 历史导入 | 从老系统导入的商品、客户、供应商等**主数据**；历史单据不导入，期初库存单独导入 |
| 条码目录 | 用户手动上传的 sku.txt 全量快照，条码 → 规格 + 实重，只用于扫码 |
| 扫码记录 | PDA 扫到的条码与重量，仅作计数参考与打印凭证，不参与库存计算 |
| 开始扫码 / 结束扫码 | PDA 上的作业状态；结束扫码不等于出库 |
| 确认 | Web 端明确操作，按人工填写的实发量写库存、流水、审计 |
| 更正 | 对已入账单据的数量修正，引用原单，不改原值 |
| 小程序 | WMS 的只读查询延伸：查进出库单、流水、库存；不面向客户、不交易 |

> 历史文档（`IMPLEMENTATION_PLAN`、`DESIGN_DECISIONS`、`UPGRADE_PROPOSALS`、`FOUNDATION_MIGRATION`、`UI_SPEC`）中的「事实 / 扫码事实」是当时的写法，现行术语以本表为准：扫码相关一律叫「扫码记录」，且不参与库存。
| 锁仓 | 盘点期间禁止该仓的库存变动操作 |

## 6. 维护规则

1. 规格变更先改文档、再改代码；代码超出规格视为缺陷。
2. 每批完成后更新 `IMPLEMENTATION_PLAN.md` 与 `ACCEPTANCE.md`。
3. 已废弃文档在标题下标注「已废弃」并说明替代文档。
4. 不新增第 5 份 UI 规范——UI 约束只放 `UX_STANDARDS.md` 与 `WEB_UX_SPEC.md`。
