# 设计决策

本轮只记录文档阶段的决策，编号规则、商品聚合口径和差异放行均标记“需确认”，不进入实现。

## DD-01 统一列表壳

- 问题：单用户每天反复查入库、出库、库存和日志，旧系统各列表筛选和操作位置不同。
- 方案：使用统一 ProTable 壳，顶部组合筛选，中部关键列，右侧固定操作；筛选和列显隐按页面持久化。
- 备选：每个页面独立设计；否决原因是重复学习成本高，难以保证 200 行扫读和导出字段一致。
- 与旧系统差异：从关键词搜索/多页跳转改为同页多条件筛选，目标将查单步骤从 4 步降到 2 步，减少误筛。

## DD-02 入库重量独立录入

- 问题：腈纶每包实重可不同，入库只有包数和本次总吨数，统一件重会制造库存误差。
- 方案：明细行分别录包数、总吨数；合计只做校验和展示，不从包数反算重量。
- 备选：输入件重后自动乘包数；否决原因是与业务边界冲突，会把估算写成事实。
- 与旧系统差异：保留旧单据字段含义，新增差异提示和字段级错误定位，目标减少一次返工和重量误录。

## DD-03 出库冻结与确认分层

- 问题：旧 ERP 审核动作同时承载作业完成和库存扣减，PDA 冻结容易被误认为出库。
- 方案：PDA 只写不可变扫码事实并冻结；Web 详情单独确认，在一个事务中扣库存、写流水、审计和幂等结果。
- 备选：PDA 提交直接扣库存；否决原因是违反单用户仍需可追溯的 Web 明确确认边界。
- 与旧系统差异：多一个明确确认节点，但库存误扣风险从“审核即扣”降为“Web 二次确认”，重复确认目标为 0 次重复扣减。

## DD-04 单号自动生成（需确认）

- 问题：当前入库和出库单号手填，存在重复和格式不一致。
- 方案：默认 `RN-YYYYMMDD-####`，入库/出库分别保留序列，配置页提供规则校验和下一个号预览。
- 备选：沿用手填；否决原因是无法满足旧 ERP 自动单号能力和可追溯性。
- 与旧系统差异：建单少 1 个手填步骤，提交前即可看到最终号；“是否按入库/出库不同前缀”需确认。

## DD-05 多来源商品聚合（需确认）

- 问题：141 个 SPEC 商品来自包级条码目录，428 个 ERP 商品来自历史单据，两套编码缺少可靠映射键。
- 方案：默认分来源展示、禁止跨来源合计；报表同时显示来源标签和未映射计数。
- 备选：按名称/型号模糊合并；否决原因是会静默改变库存和报表数据。
- 与旧系统差异：旧系统只有商品单目录；新系统显式展示两套口径，牺牲一次切换换取不误合计；默认口径需确认。

## DD-06 状态与流水类型原文回退

- 问题：生产样本包含 `audited`、`submit` 及 `check`、`import` 等值，新模型不能猜其业务语义。
- 方案：数据库保留原字符串，展示层有已知中文标签时映射，未知值显示原文并提供来源提示。
- 备选：强制映射到 open/frozen/confirmed；否决原因是会丢失历史语义并影响审计。
- 与旧系统差异：已知状态更易扫读，未知状态仍可查；目标是未知值不空白、不报错、不阻断历史列表。

## DD-07 库存调整与盘点回写

- 问题：旧系统支持库存调整和盘点差异回写，当前原型缺失；直接写库存会破坏流水连续性。
- 方案：调整/盘点都走原因必填的确认抽屉，在同一事务写库存、流水、操作日志和幂等结果；盘点先生成快照再处理差异。
- 备选：直接在库存表编辑数字；否决原因是无法审计前后值，也无法解释差异来源。
- 与旧系统差异：增加一次影响预览和确认，目标将误调从不可追溯变成可恢复记录。

## DD-08 报表性能与口径

- 问题：报表需要按日期、仓库、商品和来源聚合，万级数据下重复全表扫描会拖慢操作。
- 方案：查询先限定时间/来源，再使用组合索引和服务端分页；导出按分页流式生成，字段顺序与表格一致。
- 备选：前端拉全量后计算；否决原因是首屏和浏览器内存不可控。
- 与旧系统差异：默认筛选范围和分页降低等待，目标首屏 <1.5s、翻页 <500ms；实际基准在实现阶段补证据。

## DD-09 单用户权限边界

- 问题：手册包含用户/角色矩阵，但实际只有一个使用者，复杂 RBAC 会增加配置和故障面。
- 方案：保留登录、会话、客户端 channel 边界、操作日志和备份恢复；不实现组织、多租户、角色矩阵、多级审批。
- 备选：照搬管理员/审核员/操作员角色；否决原因是与 AGENTS 单用户约束冲突，且不能增加实际安全收益。
- 与旧系统差异：权限页面功能减少，业务写入边界更集中；通过 Web/PDA/小程序 E2E 验证错误客户端被拒绝。
