# 切换方案（CUTOVER_PLAN）

## 1. 目标

把老系统（erp.nbsmzwl.cn）的**期初库存、未完成单据、主数据**一次性搬进本系统，之后老系统只读归档。
普通已完成历史单据只读导入；未完成单据以原单号标legacy-open显式承接，切换后仅确认/作废，不允许改明细（§8）。

## 2. 原则

1. 切换是一次性动作；无新写入时可经校验恢复旧系统，有新账时按§9冻结双方并核对差额后恢复唯一写系统；
2. 期初只登记一次且作为不可变T0锚点；当前stock继续通过正常收发/调整变化，不锁死现存库存、不改写锚点；
3. 老单号保留原样，legacy-open也不重编；新RK/CK/GZ/PD按前缀/日期检查占用递增，绝不复用；
4. 切换前必须做一次完整演练，演练库与正式库同一套脚本。

## 3. 前置条件（T-7 天）

| # | 条件 | 负责 |
|---|---|---|
| 1 | 本系统规格定稿、页面改造完成、打印可用 | 开发 |
| 2 | 商品/客户/供应商/车辆主数据核对完成 | 业务 |
| 3 | 库存实物盘点完成，账面与实物一致 | 业务 |
| 4 | 老系统停止新增单据的时间点确定 | 业务 |
| 5 | 备份与恢复演练通过（含恢复后对账） | 开发 |
| 6 | PDA 新版安装包与目录版本准备就绪 | 开发 |

## 4. 切换日流程

### T-1 天

```
① 盘清全部未完成单据，逐单登记承接/作废结果；未完成单按原号legacy-open承接，不要求全部确认清零
② 老系统做一次全量备份（库 + 上传文件）
③ 本系统在演练库完成一次完整切库演练并留记录
```

### T 日（切换当天）

```
08:00  老系统置为只读（禁止新建/确认，可查询）
08:10  导出：库存快照、未完成单据、主数据、编号计数器
08:30  导入本系统：
         - 主数据（商品/客户/供应商/车辆）
         - 期初库存（按仓库×商品，包数+吨数）
         - 未完成入库单（未确认）
         - 未完成出库单（计划中/已冻结/部分发货）
         - 编号计数器起始值
09:00  校验（见第 6 节），差异逐项清零
09:30  业务试跑：登记 1 张入库、确认入账、查库存
10:00  正式启用本系统，老系统保持只读
```

### T+1 ～ T+7

```
每日核对：本系统库存 = T0期初 + T0至核对时点累计净入 - 累计净出 + 累计调整
或：昨日期末 + 当日净入 - 当日净出 + 当日调整 = 今日期末（包吨分别）
异常登记与处理；PDA旧队列收妥是启用前门禁，不推迟到T+7
```

## 5. 期初库存导入

**不迁移历史单据。** 老系统的 115 张入库、415 张出库不导入本系统；需要查旧单时继续查老系统（只读）。本系统从期初库存开始记新账。

切换日 = 用户实际导入期初库存的那一天，由用户自己操作，不预设日期。

| 项 | 规则 |
|---|---|
| 来源 | 老系统切换时刻的库存表（只读快照） |
| 粒度 | 仓库 × 商品 |
| 字段 | 仓库编码、商品编码、包数（整数）、吨数（4 位小数）、业务日期（= 导入日）、来源标记 `opening` |
| 主数据 | 商品、客户、供应商、车辆**另行导入**（新单要用），与库存导入分开执行、分开校验 |
| 一致性 | 导入前后总包数、总吨数、商品数必须一致 |
| 锁定 | stock_opening不可变锚点，当前stock可正常收发/调整；锚点覆盖的历史流水不得再次入账 |
| 审计 | 导入批次号、操作人、时间、文件哈希 |

期初导入**不需要**客户、供应商、车辆字段——库存只挂在仓库与商品上；但主数据必须先于库存导入，否则库存行找不到商品。

## 6. 校验清单（必须全部为 0 差异）

1. 商品数、客户数、供应商数、车辆数一致；
2. 每个仓库的库存行数一致；
3. 每个仓库的总包数、总吨数一致；
4. 逐商品（仓×品）差异 = 0，允许的舍入误差为 0；
5. 未完成单据数量与单号一致；
6. 每个目标前缀/上海日期的计数器高于该段实际已占用序列（含导入号/软删号），并发碰撞测试零重复；
7. 期初库存总额 = 本系统库存合计（导入后立即查）。

任一项不为0：停止启用并保全证据；恢复旧写入必须按§9确认是否已有新账，不能直接解除只读。

## 7. 单号切点

| 单据 | 老系统 | 新系统 |
|---|---|---|
| 入库 | `IN2026…`（保留） | `RK-YYYYMMDD-NNN` |
| 出库 | `OUT2026…`（保留） | `CK-YYYYMMDD-NNN` |
| 更正 | — | `GZ-YYYYMMDD-NNN` |
| 盘点 | — | `PD-YYYYMMDD-NNN` |

规则：
- 导入按原号，碰撞即阻断并出清单，不自动改号；不同格式不比较为一个最大整数。
- 新编号按同前缀/上海日期扫描所有占用再递增；仅无占用时从 001 起，不能重置已有计数。
- RK/CK/GZ 已有事务取号；PD 当前为日期+UUID 片段，统一日序号需另补 B10 编号能力。
- 普通新建不手输旧号，导入入口独立受控；GZ 旧号占用同样查重，历史号与原行关联保持不变。
- 位宽 3 位（999/日）；用尽报错并提示计划重编，不自动扩位。

### 7.1 主数据编码重编（方案 B）

客户、供应商、仓库的旧编码在导入阶段一次性重编为新规则：

| 对象 | 新格式 | 示例 |
|---|---|---|
| 客户 | `C` + 5 位 | `C00001` |
| 供应商 | `S` + 4 位 | `S0001` |
| 仓库 | `W` + 2 位 | `W01` |

步骤：
1. 导入前生成映射表：旧编码 → 新编码，按名称排序分配，保证可复现；
2. 导入主数据时同时写入新编码与 `legacy_code`；
3. 单据、库存、联系人等所有引用统一按映射替换；
4. 校验：客户数、供应商数、仓库数不变；单据引用数不变；无孤儿外键；
5. 抽样 10 条单据，核对客户名称与新旧编码对应正确；
6. 映射表与校验报告作为切换产出归档。

## 8. 未完成单据处理

**不承接任何未完成单据。** 切换前必须把老系统清空到“没有在途业务”的状态，否则不动手。

| 类型 | 处理 |
|---|---|
| 老系统未确认入库单 | 切换前确认或作废，做到没有待确认入库 |
| 老系统计划中/已冻结出库单 | 切换前完成出库或作废，不允许带到新系统 |
| 部分发货单 | 切换前完成或短关结单 |
| 进行中盘点 | 切换前结束或作废 |
| 待补传 PDA 扫码记录 | 切换前全部补传完毕；否则阻断切换 |
| 历史已完结单据 | 不导入；需要查询时回老系统看 |

前置检查：老系统待确认入库 = 0、未完成出库 = 0、进行中盘点 = 0、待补传 = 0，四项齐全才允许导入期初库存。

## 9. 回滚预案

发生无法短期修复的问题，先判断新系统是否已有写入；七天是重点观察期，不是数据安全回退界线：

```
① 冻结新旧双方写入，登记停写时间/流水水位，保全双方备份、PDA事实/队列与切换后所有差额
② 无新账：核对T0/导入批次及旧队列证据，确认旧系统仍与切点一致
③ 有新账：逐原单号/operation/UUID建立幂等补录映射，在隔离演练库重放切换后净变化并逐仓品对账
④ 所有差额、单据终态、事实和编号占用核清后，按另行批准的执行步骤补录并验证；不得任意作废已入账新单
⑤ 仅恢复一个系统写入，另一个继续只读；记录回退原因、映射、指纹、校验和生效水位
```

有新账优先前向修复；只有上述演练/补录/对账门禁全部通过才可回退，无法无损映射则不恢复旧写入。本文不授权连接生产或写旧系统。

## 10. 角色与产出

单用户执行，但需留下记录：

| 产出 | 内容 |
|---|---|
| 切换记录 | 时间线、每步结果、操作人 |
| 校验报告 | 第 6 节七项的实际数字 |
| 期初导入文件 | 原始 CSV + 哈希 |
| 演练记录 | 演练库的同样校验结果 |

## 11. 验收

1. 演练库完整跑通一次切换，七项校验为 0；
2. 正式切换七项校验为 0；
3. T0锚点不可变；当前库存正常收发可变且全程逐仓品对账；
4. 新单号从 RK-/CK- 起，老单号不可新建；
5. 切换前四项清零检查生效：存在待确认入库、未完成出库、进行中盘点或待补传时，导入期初被拒绝；
6. 切换后 7 天每日对账通过；
7. 回滚演练一次（在演练库完成，不碰正式）。

## 12. 承接模型（已废弃）

2026-11-11 决定：**不承接任何未完成单据**，原 `legacy-open` / `legacy_open_documents` / 承接余额与事务门禁整套设计作废，不再实施。

- 切换前老系统四项清零（待确认入库、未完成出库、进行中盘点、待补传），见 §8；
- 新系统只导入主数据与期初库存；
- 查旧单回老系统，本系统不保留 legacy-open 状态与相关接口；
- 原 §12 的 T0 锚点、承接行、确认/作废门禁不再作为 B10 的实施内容，B10 只保留期初导入与切换演练。
