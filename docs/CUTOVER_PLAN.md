# 切换方案（CUTOVER_PLAN）

## 1. 目标

把老系统（erp.nbsmzwl.cn）的**期初库存、未完成单据、主数据**一次性搬进本系统，之后老系统只读归档。
普通已完成历史单据只读导入；未完成单据以原单号标legacy-open显式承接，切换后仅确认/作废，不允许改明细（§8）。

## 2. 原则

1. 切换是一次性动作；无新写入时可经校验恢复旧系统，有新账时按§9冻结双方并核对差额后恢复唯一写系统；
2. 期初只登记一次且作为不可变T0锚点；当前stock继续通过正常收发/调整变化，不锁死现存库存、不改写锚点；
3. 老单号保留原样，legacy-open也不重编；新RK/CK/GZ/PD按前缀/日期检查占用递增，绝不复用；
4. 切换前必须做一次完整演练，演练库与正式库同一套脚本。

## 3. 前置条件（T-7 天）

| # | 条件 | 负责 |
|---|---|---|
| 1 | 本系统规格定稿、页面改造完成、打印可用 | 开发 |
| 2 | 商品/客户/供应商/车辆主数据核对完成 | 业务 |
| 3 | 库存实物盘点完成，账面与实物一致 | 业务 |
| 4 | 老系统停止新增单据的时间点确定 | 业务 |
| 5 | 备份与恢复演练通过（含恢复后对账） | 开发 |
| 6 | PDA 新版安装包与目录版本准备就绪 | 开发 |

## 4. 切换日流程

### T-1 天

```
① 盘清全部未完成单据，逐单登记承接/作废结果；未完成单按原号legacy-open承接，不要求全部确认清零
② 老系统做一次全量备份（库 + 上传文件）
③ 本系统在演练库完成一次完整切库演练并留记录
```

### T 日（切换当天）

```
08:00  老系统置为只读（禁止新建/确认，可查询）
08:10  导出：库存快照、未完成单据、主数据、编号计数器
08:30  导入本系统：
         - 主数据（商品/客户/供应商/车辆）
         - 期初库存（按仓库×商品，包数+吨数）
         - 未完成入库单（未确认）
         - 未完成出库单（计划中/已冻结/部分发货）
         - 编号计数器起始值
09:00  校验（见第 6 节），差异逐项清零
09:30  业务试跑：登记 1 张入库、确认入账、查库存
10:00  正式启用本系统，老系统保持只读
```

### T+1 ～ T+7

```
每日核对：本系统库存 = T0期初 + T0至核对时点累计净入 - 累计净出 + 累计调整
或：昨日期末 + 当日净入 - 当日净出 + 当日调整 = 今日期末（包吨分别）
异常登记与处理；PDA旧队列收妥是启用前门禁，不推迟到T+7
```

## 5. 期初库存导入

| 项 | 规则 |
|---|---|
| 来源 | 老系统切换时刻的库存表（只读快照） |
| 粒度 | 仓库 × 商品 |
| 字段 | 包数（整数）、吨数（4 位小数）、来源标记 `opening` |
| 一致性 | 导入前后总包数、总吨数、商品数必须一致 |
| 锁定 | stock_opening不可变锚点，当前stock可正常收发/调整；锚点覆盖的历史流水不得再次入账 |
| 审计 | 导入批次号、操作人、时间、文件哈希 |

## 6. 校验清单（必须全部为 0 差异）

1. 商品数、客户数、供应商数、车辆数一致；
2. 每个仓库的库存行数一致；
3. 每个仓库的总包数、总吨数一致；
4. 逐商品（仓×品）差异 = 0，允许的舍入误差为 0；
5. 未完成单据数量与单号一致；
6. 每个目标前缀/上海日期的计数器高于该段实际已占用序列（含导入号/软删号），并发碰撞测试零重复；
7. 期初库存总额 = 本系统库存合计（导入后立即查）。

任一项不为0：停止启用并保全证据；恢复旧写入必须按§9确认是否已有新账，不能直接解除只读。

## 7. 单号切点

| 单据 | 老系统 | 新系统 |
|---|---|---|
| 入库 | `IN2026…`（保留） | `RK-YYYYMMDD-####` |
| 出库 | `OUT2026…`（保留） | `CK-YYYYMMDD-####` |
| 更正 | — | `GZ-YYYYMMDD-####` |
| 盘点 | — | `PD-YYYYMMDD-####` |

规则：
- 导入按原号，碰撞即阻断并出清单，不自动改号；不同格式不比较为一个最大整数。
- 新编号按同前缀/上海日期扫描所有占用再递增；仅无占用时从1起，不能重置已有计数。RK/CK/GZ已有事务取号；PD当前为日期+UUID片段，统一日序号需另补B10编号能力。
- 普通新建不手输旧号，导入入口独立受控；GZ旧号占用同样查重，历史号与原行关联保持不变。

## 8. 未完成单据处理

| 类型 | 处理 |
|---|---|
| 老系统未确认入库单 | 按原号/原行导入legacy-open待确认，确认仅本次未入账量；只可确认/作废 |
| 老系统计划中出库单 | 按原号legacy-open，只可确认/作废；PDA可对固定原行采集确认所需事实并冻结，不能改计划/明细 |
| 已冻结未确认出库单 | 原号legacy-open，完整导入事实/版本/摘要并核验；只可确认/作废（见专用门禁），不重新生成UUID或重算旧正文 |
| 部分发货单 | 保留原计划/已发历史与待发余额，原已发已含T0不再扣库；剩余量作为一个承接批次确认或作废，不新增分批/短关动作 |
| 进行中盘点 | 老系统作废后重来（不迁移半成品） |
| 待补传 PDA 事实 | 切换前必须全部补传完毕，否则阻断切换 |

## 9. 回滚预案

发生无法短期修复的问题，先判断新系统是否已有写入；七天是重点观察期，不是数据安全回退界线：

```
① 冻结新旧双方写入，登记停写时间/流水水位，保全双方备份、PDA事实/队列与切换后所有差额
② 无新账：核对T0/导入批次及旧队列证据，确认旧系统仍与切点一致
③ 有新账：逐原单号/operation/UUID建立幂等补录映射，在隔离演练库重放切换后净变化并逐仓品对账
④ 所有差额、单据终态、事实和编号占用核清后，按另行批准的执行步骤补录并验证；不得任意作废已入账新单
⑤ 仅恢复一个系统写入，另一个继续只读；记录回退原因、映射、指纹、校验和生效水位
```

有新账优先前向修复；只有上述演练/补录/对账门禁全部通过才可回退，无法无损映射则不恢复旧写入。本文不授权连接生产或写旧系统。

## 10. 角色与产出

单用户执行，但需留下记录：

| 产出 | 内容 |
|---|---|
| 切换记录 | 时间线、每步结果、操作人 |
| 校验报告 | 第 6 节七项的实际数字 |
| 期初导入文件 | 原始 CSV + 哈希 |
| 演练记录 | 演练库的同样校验结果 |

## 11. 验收

1. 演练库完整跑通一次切换，七项校验为 0；
2. 正式切换七项校验为 0；
3. T0锚点不可变；当前库存正常收发可变且全程逐仓品对账；
4. 新单号从 RK-/CK- 起，老单号不可新建；
5. 原号legacy-open仅确认/作废，任意改头/改行/日期/更正/短关/撤销请求被拒且库不变；普通历史单仍拒绝确认；
6. 切换后 7 天每日对账通过；
7. 回滚演练一次（在演练库完成，不碰正式）。

## 12. 承接模型与事务门禁（B10，需要新增服务能力）

- M-CUTOVER-ANCHOR：cutover_batches保存T0的UTC时点/Asia-Shanghai日界、流水水位、导入清单/文件SHA、状态、操作者；stock_opening以(batch_id,warehouse,product)唯一保存精确包吨与来源证据，标不可变。开账导入按批次幂等，重复不覆盖stock、不再叠加已纳入锚点的历史流水。
- 新增legacy_open_documents/legacy_open_lines关联真实入/出库原单/行外键、source_id、原号/原状态、计划/已发/剩余包克、来源批次/hash、承接状态/版本、确认或作废操作。标记legacy-open是受控导入生成的资格，不允许普通建单提交此标记，也绝不清空source_id绕过现有历史保护。保留原单明细，剩余量以承接行表达。
- 资格只给白名单未确认入库、计划中/冻结/部分发货出库；已完成历史单仍只读。导入不产生新的收发发生额，历史已发只展示；已冻结单必须收妥UUID/正文、目录版本/hash、混版上下文、摘要算法版本和原行映射。旧队列全量收妥/冲突处理为T0启用前硬门禁，未知设备不可当0。
- 确认事务顺序：全局库存写锁→原单/承接行锁→幂等重放→资格/终态/版本/原号行指纹检查→未收齐/冲突与冻结摘要核验→盘点窗口→锁库存逐行校验独立包吨非负→只入账剩余量→流水/审计/幂等/承接终态同事务。同版本并发一胜一409；不能把原计划或原已发再扣一遍。
- 作废是放弃未入账的承接剩余部分，原因必填且二次确认；锁原单/交接清单并与PDA下发/冻结互斥，所有已登记事实及离线队列核清、操作者显式确认剩余实物未离场后才允许；请求绑定handoff_token与physical_not_departed_ack并写审计（不由单据状态推断离场）。保留事实/摘要/原已发历史，不写库存流水。若实物已离场，先完成有证据的确认，不可用作废掩盖；已确认承接单禁止作废或撤销。此为专用切换流程，不移除普通frozen不可撤销及历史拒绝守卫。
- 计划接口：受控cutover批次预检/导入/验证/封存；既有确认/作废服务仅新增服务端承接白名单分支，查询返回只读原信息+承接余额/终态与中文标签。客户端传legacy-open/source_id不能取得权限。导入原业务日期（未知保留NULL），切换后不允许改。
- 先完成B6a快照/资格、B5c余额和事实模型及B8a恢复演练，再执行切换专项；迁移有T0/承接业务数据时down拒绝，不能用down回滚已发生业务。原/新系统持续差额映射、重复导入、确认后重放、冻结单作废、旧队列缺失、T+多日累计对账及有新账回退均须隔离合成演练输出。

修订记录：C02 对齐部分发货已发/待发承接，确认不重放历史已发库存。
修订记录：C18 落实原号legacy-open仅确认/作废、不可变T0累计对账、编号占用与双冻结差额回退门禁。
