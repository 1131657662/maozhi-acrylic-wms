# 条码目录页面规范（CATALOG_PAGE_SPEC）

> 本文档中的状态、类型、结果等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 定位

条码目录只做三件事：**看当前目录、传新目录、查版本**。它不参与库存，只回答“扫这个条码，这一包多重”。

参照：SAP 条件记录的有效期与变更凭证、Oracle 接口表“先校验后导入”、NetSuite CSV 导入的预览与错误报告、GS1 条码规范。

## 2. 页面结构

```
┌ 条码目录 ──────────────────────────── [扫描测试] [上传新目录] ┐
│ 当前版本 v3 · 9,018 条 · 141 规格 · 3 天前更新 · 已放行 ✓      │
│ 交接证据：已登记作业的未收齐数  [查看]                            │
├────────────────────────────────────────────────────────────────┤
│ [条码 / 规格搜索 ________]  [筛选 ·0]      [导出当前视图]       │
├────────────────────────────────────────────────────────────────┤
│ Tabs：当前目录 ｜ 规格分组 ｜ 版本历史 ｜ 待发布（暂存区）      │
└────────────────────────────────────────────────────────────────┘
```

## 3. 当前目录 Tab

| 列 | 说明 |
|---|---|
| 条码 | 可复制；点击进入条码详情（版本轨迹） |
| 规格 | 对应 sku.txt 的规格描述 |
| 重量 | kg，显示 3 位小数；内部存吨 |
| 首次出现 | 第几版开始存在（v1 起=切库封存） |
| 最近变更 | 重量变过则显示「v2 起 300→302」 |
| 状态 | 有效 / 本版已消失（灰显） |

规则：
- 搜索框支持扫码枪直接输入（自动聚焦、回车即查、结果高亮）；
- 支持条码前缀匹配、规格模糊匹配；
- 分页 50/页，可切 100/200；
- 导出当前视图（XLSX）。

## 4. 规格分组 Tab

141 个规格，按规格聚合：

```
规格 H815B 1.3 RE 38 300 有光短纤
  条码数 95 · 重量 300–303 kg · 平均 301.2 kg
  [展开条码]
```

展开后列出该规格下所有条码、重量、首次出现版本。

用途：核对“同规格重量是否异常分散”“某规格是否只剩几个条码”。

异常提示：同规格内重量偏离均值 > 10% 的条码标黄（可能是录入错误）。

## 5. 版本历史 Tab

| 版本 | 发布时间 | 条码数 | 新增 | 消失 | 重量变更 | 状态 | 操作 |
|---|---|---|---|---|---|---|---|
| v3 | 11-06 14:20 | 9,018 | 120 | 8 | 15 | 当前 | 对比 / 查看 / 导出 |
| v2 | 10-20 09:10 | 8,906 | 300 | 0 | 2 | 历史 | 对比 / 查看 |
| v1 | 10-01（切库封存） | 9,018 | — | — | — | 历史 | 查看 |

- 点「对比」选两个版本 → 单列差异清单（新增/消失/重量变更）；
- 差异清单可导出 XLSX（发给供应商核对）；
- 历史版本永不删除；
- 回滚 = 以某历史版本内容**重新发布为新版本**，不改历史。

## 6. 上传流程（整页四步）

### 第 1 步：选择文件

```
[选择 sku.txt]   支持 GB2312 / UTF-8（自动识别）
说明：这是全量快照；新文件中消失的条码仅表示移出当前目录，不证明已确认出库，不自动扣库存
变更原因（选填）[ 11 月新到货 ]
```

### 第 2 步：解析与校验

```
解析中… 9,018 行
✓ 编码识别：GB2312
✓ 列数正确
✓ 条码唯一
✗ 3 行重量格式错误（第 120、800、9012 行）
→ 整版拒绝，可下载错误报告
```

校验项：

| 检查 | 规则 |
|---|---|
| 编码 | 自动识别 GB2312 / UTF-8 |
| 列数 | 必须 3 列（规格、条码、重量） |
| 条码 | 非空、唯一、长度 1–64、仅字母数字-_ |
| 重量 | 大于0、至多1,000,000 kg，精度0.1 kg（100克），沿用现有解析契约；50–5000 kg仅作异常提示区间 |
| 全量性 | 行数少于上版 50% 时额外警告 |

错误报告：导出 CSV（行号、原始内容、原因），可修正后重传。

### 第 3 步：暂存与差异预览

上传成功后进入**暂存区**（不生效），可反复查看、放弃候选、重新上传；上传已分配版本且保留上传证据。

```
本版 vs v3
  新增 120 条
  消失   8 条（移出当前目录）
  重量变更 15 条（最大 300→302，+0.7%）
  无变化 8,895 条

[展开明细] [导出差异] [放弃候选] [确认发布]
```

### 第 4 步：发布

```
发布中…
✓ 版本 v4 已发布，当前目录切换完成
✓ 已扫事实仍指向各自版本
✓ 编号计数器未受影响
```

发布为原子操作：失败则整版不生效，当前目录不变。

## 7. 暂存区（待发布）

- 允许保留多个已校验候选，展示上传时间/创建人/基准版本；同一时刻仅一个发布事务持有head锁，旧基准候选发布前重算差异并重新确认；
- 候选只能放弃，保留版本号、上传hash、解析结果与审计；不得物理删除、复用版本号或改已发布历史；
- 候选不生效期间，扫码仍用当前版本；
- 同一文件重复上传：提示「与 v3 内容一致」，默认不建版本；
- 发布掉响应/服务重启先查询版本和当前head，再以原幂等键重放；未提交事务回滚，已提交仍成功，不按客户端超时标失败。

## 8. 发布门禁

| 状态 | 显示 | 上传 |
|---|---|---|
| 已放行 | 绿色「已放行」 | 可用 |
| 被阻断 | 黄色「被阻断：3 台旧客户端未交接」+ 查看原因 | 禁用，hover 说明 |
| 未检查 | 灰色「未检查」+ 立即检查 | 可用，发布前强制检查 |

## 9. 设备同步状态

只展示服务端已登记的交接证据，不称为设备实时同步覆盖率。点开显示：

| 设备/客户端登记 | 交接登记时间 | 已登记期望/已收事实 | 未收齐数 |
|---|---|---|---|
| 登记标识的业务别名 | 实际登记时间 | 以交接清单为准 | expected − received |

当前目录版本的设备安装覆盖率、实时离线待传队列、未登记设备总数均为「不支持」；最后一条扫码记录版本只证明该事实上下文，不代表设备现在的版本。无记录显示未知，不能填0。未来设备观测须新增协议与M-DEVICE-OBSERVATIONS（device_id、reported_version/hash、observed_at、queue_observation及过期策略），本批不实现、不据推断放行。发布门禁仍检查已登记交接和未知客户端人工核验。

## 10. 扫描测试

页头「扫描测试」小工具：

```
输入/扫码 [100B0005788] →
结果：规格 H815B… · 重量 302 kg · 首次出现 v1 · 当前版本有效
```

现场扫不出来时，用它快速判断是条码问题、目录版本问题还是设备问题。

## 11. 审计

每次上传记录：文件名、哈希、行数、校验结果、发布人、发布时间、变更原因。
每次发布记录：从 v3 → v4，差异摘要。

## 12. 接口

| 接口 | 说明 |
|---|---|
| GET /api/v1/catalog | 沿用当前版本与门禁概览；扩展统计 |
| GET /api/v1/catalog/entries | 当前目录分页查询（条码/规格） |
| GET /api/v1/catalog/specs | 规格分组聚合 |
| GET /api/v1/catalog/versions | 版本列表 |
| GET /api/v1/catalog/versions/:id/diff?against= | 版本差异 |
| POST /api/v1/catalog/uploads | 上传到暂存区（解析+校验） |
| GET /api/v1/catalog/uploads/:id | 暂存区详情与差异 |
| POST /api/v1/catalog/versions/:id/abandon | 新增放弃候选（幂等、原因必填、保留证据） |
| POST /api/v1/catalog/versions/:versionId/publish | 沿用发布（幂等） |
| GET /api/v1/catalog/lookup?barcode= | 扫描测试 |
| GET /api/v1/catalog/devices | 新增已登记交接证据投影，实时同步/队列不支持 |

## 13. 边界

| 情况 | 处理 |
|---|---|
| 坏文件 | 整版拒绝，可下载错误报告 |
| 行数骤减 >50% | 警告，需二次确认 |
| 同文件重复上传 | 提示与当前版本一致，不建版本 |
| 上传中断 | 暂存不生效 |
| 发布中断 | 查询提交结果并原键重放；仅未提交时当前目录不变 |
| 条码重量异常（同规格偏离 >10%） | 标黄提示，不阻断 |
| 条码复用（旧条码给新包） | 记警告；取样记录按规格+重量校验 |
| 无上传权限 | 只读（当前仅 Web 渠道） |

## 14. 不做

| 不做 | 原因 |
|---|---|
| 在线编辑单条条码 | 全量快照语义，改单条会造成版本漂移 |
| 手工新增条码 | 同上 |
| 并排版本对比 | 单列差异清单够用 |
| 自动定时同步 | 手动上传是既定流程 |
| 条码校验位（EAN） | 现有条码格式不统一，暂不强校验 |

## 15. 验收

1. 上传坏文件整版拒绝，当前目录不变，错误报告可下载；
2. 上传相同文件提示一致，不产生新版本；
3. 差异预览三个数字与明细逐条吻合；
4. 发布后当前版本切换、历史版本仍在、事实版本不变；
5. 放弃候选保留已分配版本/上传/审计，不能发布已放弃候选或删除历史；
6. 行数骤减 >50% 触发二次确认；
7. 扫描测试对有效/无效/历史版本条码分别给出正确结果；
8. 已登记交接未收齐数可逐条复核；实时队列/同步覆盖率明确不支持，不因未知自动放行；
9. 版本对比导出 XLSX 内容正确；
10. 1440/1280 截图（当前目录、规格分组、版本历史、上传四步、门禁阻断）。

## 16. 缺失服务与兼容

B6d 拆为两个子批次。B6d-1（页面骨架）只按本文区块顺序重建展示结构，迁入既有上传、编码选择、候选差异、版本列表、发布门禁和交接清单/确认；不新增接口、不改数据库或既有行为。B6g 联想搜索顺延至 B6d-1 之后，理由为联想搜索不影响目录页结构；随后进入 B6d-2（新增能力）。

B6d-2 新增当前目录搜索/规格聚合/条码版本轨迹、任意版本对比与导出、候选放弃及交接证据投影；既有上传、版本查询、发布路由保持兼容。版本内容用既有游标afterBarcode/limit，不机械改为主单分页；公共查询外壳/视图/导出限制引用WEB_UX_SPEC。新增`M-CATALOG-CANDIDATES`为候选添加abandoned状态及abandoned_at/by/reason，迁移保留既有staging/validated/published与所有版本、事实、hash，非空放弃证据拒绝down。前端不再声称上传不产生版本。

现有编码参数为utf-8/gb18030；界面可识别候选并让用户确认编码后传现有参数，识别不确定须选择，不能静默错解；自动识别属于新增能力。长度/重量沿用服务端硬范围，历史目录及已扫事实不按新警告区间重写。目录移出/条码复用只作目录证据，Web确认出库才扣库存；取样按规格/重量快照校验身份。
