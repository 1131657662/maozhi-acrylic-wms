# 条码目录页面规范（CATALOG_PAGE_SPEC）

> 本文档中的状态、类型、结果等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 定位

条码目录只做三件事：**看当前目录、传新目录、查版本**。它不参与库存，只回答“扫这个条码，这一包多重”。

参照：SAP 条件记录的有效期与变更凭证、Oracle 接口表“先校验后导入”、NetSuite CSV 导入的预览与错误报告、GS1 条码规范。

## 2. 页面结构

```
┌ 条码目录 ──────────────────────────── [扫描测试] [上传新目录] ┐
│ 当前版本 v3 · 9,018 条 · 141 规格 · 3 天前更新 · 已放行 ✓      │
│ 交接证据：已登记作业的未收齐数  [查看]                            │
├────────────────────────────────────────────────────────────────┤
│ [条码 / 规格搜索 ________]  [筛选 ·0]      [导出当前视图]       │
├────────────────────────────────────────────────────────────────┤
│ Tabs：当前目录 ｜ 规格分组 ｜ 版本历史 ｜ 待发布（暂存区）      │
└────────────────────────────────────────────────────────────────┘
```

## 3. 当前目录 Tab

| 列 | 说明 |
|---|---|
| 条码 | 可复制；点击进入条码详情（版本轨迹） |
| 规格 | 对应 sku.txt 的规格描述 |
| 重量 | kg，显示 3 位小数；内部存吨 |
| 首次出现 | 第几版开始存在（v1 起=切库封存） |
| 最近变更 | 重量变过则显示「v2 起 300→302」 |
| 版本 | 当前已发布版本 |
| 状态 | 有效 / 本版已消失（灰显） |

规则：
- 搜索框支持扫码枪直接输入（自动聚焦、回车即查、结果高亮）；
- 支持条码精确/片段匹配、规格模糊匹配；
- 搜索范围仅为条码与规格，不支持商品名：目录快照不含商品名，当前解析流程也不填充旧商品映射；本批不以不完整关联产生误命中；
- 分页 50/页，可切 100/200；
- 导出当前视图（XLSX）导出当前搜索/筛选条件的全部命中结果，不限于当前页；列与屏幕一致，包含条码、规格、重量和版本；最多 100,000 行，超出返回 422 并提示缩小条件；使用流式 XLSX 写入，不整表载入内存，生成后直接下载且不持久化导出产物。

## 4. 规格分组 Tab

141 个规格，按规格聚合：

```
规格 H815B 1.3 RE 38 300 有光短纤
  条码数 95 · 总重量 … kg · 最小 300 kg · 最大 303 kg · 平均 301.2 kg
  [展开条码]
```

对当前已发布目录按规格分组，返回条码数、总重量、最小重量、最大重量和平均重量；重量作为统计指标，不参与分组。重量单位为 kg，页面显示 3 位小数。

展开后列出该规格下所有条码、重量、首次出现版本。

用途：核对“同规格重量是否异常分散”“某规格是否只剩几个条码”。

异常提示：同规格内重量偏离均值 > 10% 的条码标黄（可能是录入错误）。

## 5. 版本历史 Tab

| 版本 | 发布时间 | 条码数 | 新增 | 消失 | 重量变更 | 状态 | 操作 |
|---|---|---|---|---|---|---|---|
| v3 | 11-06 14:20 | 9,018 | 120 | 8 | 15 | 当前 | 对比 / 查看 / 导出 |
| v2 | 10-20 09:10 | 8,906 | 300 | 0 | 2 | 历史 | 对比 / 查看 |
| v1 | 10-01（切库封存） | 9,018 | — | — | — | 历史 | 查看 |

- 点「对比」选两个版本 → 分页差异清单（新增/消失/重量变化/规格变化/未变化）；
- `against` 缺省时仍比较该版本的 `baseVersionId`；显式指定时比较 `against` 与路径版本。版本不存在返回 404；版本存在但未通过校验（staging）返回 422。当前只有一个全局目录，不引入 `catalog_id` 或跨目录校验；未来若支持多目录，再补归属校验。
- 差异查询按条码分页，只读取当前页所需记录，不整表载入内存；重量与规格同时变化时两个标志均保留；
- B6d-3a 实现任意两版对比；本批 XLSX 只导出当前目录命中集，差异清单 XLSX 另行排期；
- 历史版本永不删除；
- 回滚 = 以某历史版本内容**重新发布为新版本**，不改历史。

## 6. 上传流程（整页四步）

### 第 1 步：选择文件

```
[选择 sku.txt]   支持 GB2312 / UTF-8（自动识别）
说明：这是全量快照；新文件中消失的条码仅表示移出当前目录，不证明已确认出库，不自动扣库存
变更原因（选填）[ 11 月新到货 ]
```

### 第 2 步：解析与校验

```
解析中… 9,018 行
✓ 编码识别：GB2312
✓ 列数正确
✓ 条码唯一
✗ 3 行重量格式错误（第 120、800、9012 行）
→ 整版拒绝，可下载错误报告
```

校验项：

| 检查 | 规则 |
|---|---|
| 编码 | 自动识别 GB2312 / UTF-8 |
| 列数 | 必须 3 列（规格、条码、重量） |
| 条码 | 非空、唯一、长度 1–64、仅字母数字-_ |
| 重量 | 大于0、至多1,000,000 kg，精度0.1 kg（100克），沿用现有解析契约；50–5000 kg仅作异常提示区间 |
| 全量性 | 行数较基准版减少 ≥50% 时上传返回 warning，由前端确认；属于 backlog，本批不实现，不设服务端发布硬门禁 |

解析时收集全部错误，但最多返回 500 条。每条含行号、原始行内容（最多 200 字符）和原因；超过 500 条时提示「错误过多，仅显示前 500 条」。整版拒绝时随 422 响应返回错误清单，前端提供「下载错误清单」按钮生成 CSV，可修正后重传。错误清单与导出产物不落库；既有成功上传的 source_bytes 与安全失败审计行为保持不变。CSV 对以公式字符开头的单元格加文本前缀，避免表格软件执行上传内容。

### 第 3 步：暂存与差异预览

上传成功后进入**暂存区**（不生效），可反复查看、重新上传。候选是一整份已校验目录版本；B6d-3b 只允许整版放弃，不支持逐条条码放弃或跳过发布。上传已分配版本且保留上传证据。

```
本版 vs v3
  新增 120 条
  消失   8 条（移出当前目录）
  重量变更 15 条（最大 300→302，+0.7%）
  无变化 8,895 条

[展开明细] [导出差异] [放弃候选] [确认发布]
```

### 第 4 步：发布

```
发布中…
✓ 版本 v4 已发布，当前目录切换完成
✓ 已扫事实仍指向各自版本
✓ 编号计数器未受影响
```

发布为原子操作：失败则整版不生效，当前目录不变。

## 7. 暂存区（待发布）

- 允许保留多个已校验候选，展示上传时间/创建人/基准版本；同一时刻仅一个发布事务持有head锁。基准已变时拒绝发布，需重建候选；不自动重算或修改旧候选基准；
- 候选只能整版放弃，保留版本号、上传hash、解析结果与审计；不得物理删除、复用版本号或改已发布历史。放弃不可撤销；重新处理须显式重建为新版本，旧放弃证据永久保留；
- 已放弃候选不得发布，但不阻断其他符合条件的候选。没有逐条跳过、部分发布或条码黑名单；要发布的文件有问题须修正后重传；
- 候选不生效期间，扫码仍用当前版本；
- 同一内容重复上传默认不建版本；仅命中已放弃版本时返回该版本与已放弃状态，提示「与第 X 版内容一致，该候选已放弃；如需重新处理，请显式重建候选」（X 为 matchedVersionId），不自动恢复或新建；其他状态沿用「与第 X 版内容一致」；
- 发布掉响应/服务重启先查询版本和当前head，再以原幂等键重放；未提交事务回滚，已提交仍成功，不按客户端超时标失败。

## 8. 发布门禁

| 状态 | 显示 | 上传 |
|---|---|---|
| 已放行 | 绿色「已放行」 | 可用 |
| 被阻断 | 黄色「被阻断：3 台旧客户端未交接」+ 查看原因 | 禁用，hover 说明 |

## 9. 设备同步状态

只展示服务端已登记的交接证据，不称为设备实时同步覆盖率。点开显示：

| 设备/客户端登记 | 交接登记时间 | 已登记期望/已收事实 | 未收齐数 |
|---|---|---|---|
| 登记标识的业务别名 | 实际登记时间 | 以交接清单为准 | expected − received |

当前目录版本的设备安装覆盖率、实时离线待传队列、未登记设备总数均为「不支持」；最后一条扫码记录版本只证明该事实上下文，不代表设备现在的版本。无记录显示未知，不能填0。未来设备观测须新增协议与M-DEVICE-OBSERVATIONS（device_id、reported_version/hash、observed_at、queue_observation及过期策略），本批不实现、不据推断放行。发布门禁仍检查已登记交接和未知客户端人工核验。

B6d-3b 在候选详情下只读展示该候选基准版本（不是候选自身版本）已登记的交接清单摘要。预期扫码记录数来自 PDA 登记的本机全部事实快照，不是目录条码数；放弃候选不得扣减该数、修改交接清单或把未收齐解释为实时离线队列。只显示登记时间、预期/登记/已收妥/未收齐数、确认状态，不展示设备内部标识；无登记时明确显示「暂无已登记交接证据，设备情况未知」。

## 10. 扫描测试

页头「扫描测试」小工具：

```
输入/扫码 [100B0005788] →
结果：存在 · 规格 H815B… · 重量 302 kg · 当前版本有效
```

只查询当前已发布版本。无匹配条码时返回明确的「未找到」结果。该 GET 查询只读，不写扫码事实、审计或其他数据库记录。

## 11. 审计

每次上传记录：文件名、哈希、行数、校验结果、发布人、发布时间、变更原因。
每次发布记录：从 v3 → v4，差异摘要。

| 接口 | 说明 |
|---|---|
| GET /api/v1/catalog | 沿用当前版本与门禁概览 |
| GET /api/v1/catalog/search?q=&page=&pageSize= | 当前目录分页搜索（仅条码/规格），返回当前版本上下文 |
| GET /api/v1/catalog/spec-summary | 按规格聚合条码数、总重量、最小/最大/平均重量 |

| GET /api/v1/catalog/versions | 版本列表 |
| GET /api/v1/catalog/versions/:id/diff?against=&kind=&afterBarcode=&limit= | 任意两版差异，游标分页；不存在 404，未校验 422（B6d-3a） |
| GET /api/v1/catalog/export?q=&versionId= | 当前搜索/筛选全部命中结果 XLSX；版本与屏幕不一致返回 409，流式、不持久化、上限 100,000（B6d-3a） |

## 13. 边界

| 情况 | 处理 |
|---|---|
| 坏文件 | 整版拒绝，可下载错误报告 |
| 行数骤减 ≥50% | backlog：上传返回 warning + 前端确认，不做服务端发布硬门禁 |
| 同文件重复上传 | 按内容匹配已有版本，不建版本；已放弃匹配必须显示状态并引导显式重建 |
| 上传中断 | 暂存不生效 |
| 发布中断 | 查询提交结果并原键重放；仅未提交时当前目录不变 |
| 条码重量异常（同规格偏离 >10%） | 标黄提示，不阻断 |
| 条码复用（旧条码给新包） | 记警告；取样记录按规格+重量校验 |
| 无上传权限 | 只读（当前仅 Web 渠道） |

## 14. 不做

| 不做 | 原因 |
|---|---|
| 在线编辑单条条码 | 全量快照语义，改单条会造成版本漂移 |
| 手工新增条码 | 同上 |
| 并排展示两套版本内容 | 以单列差异清单呈现（任意两版对比归 B6d-3a） |
| 自动定时同步 | 手动上传是既定流程 |
| 条码校验位（EAN） | 现有条码格式不统一，暂不强校验 |

## 15. 验收

1. 上传坏文件整版拒绝，当前目录不变，错误报告可下载；
2. 上传相同文件提示一致，不产生新版本；
3. 差异预览三个数字与明细逐条吻合；
4. 发布后当前版本切换、历史版本仍在、事实版本不变；
5. 放弃候选保留已分配版本/上传/审计，不能发布已放弃候选或删除历史（B6d-3b）；
6. 行数骤减 ≥50% 的上传 warning 与前端确认记 backlog，不计本批已实现或验收项；
7. 当前目录搜索支持条码精确/片段与规格匹配，并分页返回版本上下文；
8. 规格聚合五项指标与逐条计算一致；
9. 条码轨迹包含已发布与待发布候选版本，并按中文状态映射展示；
10. 扫描测试对存在/不存在条码返回明确结果；四个新增 GET 接口查询前后相关表行数一致；
11. 已登记交接未收齐数可逐条复核；实时队列/同步覆盖率明确不支持，不因未知自动放行（B6d-3b）；
12. 当前目录命中集 XLSX 与页面列/计数一致（B6d-3a）；差异清单 XLSX 另行排期；
13. 既有版本历史、上传四步和门禁阻断保持可用；
14. 1440/1280 截图（目录搜索、规格聚合、条码轨迹抽屉、扫描测试）。

## 16. 缺失服务与兼容

B6d 分为四个子批次。B6d-1（页面骨架）只按本文区块顺序重建展示结构，迁入既有上传、编码选择、候选差异、版本列表、发布门禁和交接清单/确认；不新增接口、不改数据库或既有行为。B6g 联想搜索顺延至 B6d-1 之后，理由为联想搜索不影响目录页结构；随后依次进入 B6d-2、B6d-3a 与 B6d-3b。

B6d-2 只增加当前目录搜索（条码/规格）、规格聚合、包含候选状态的条码版本轨迹与只读扫描测试；接口为`GET /catalog/search`、`GET /catalog/spec-summary`、`GET /catalog/barcode-trace`、`GET /catalog/lookup`。搜索返回当前版本上下文；轨迹包含已发布和已校验待发布候选并标注状态。扫描测试只查询当前已发布版本，不写扫码事实或其他记录。只读查询，不加迁移、不改006/007结构，不改变上传、发布或交接行为。

B6d-3a 只承接任意两版分页对比、当前搜索/筛选全部命中结果的流式 XLSX、上传错误 CSV。两版必须存在且均为已校验或已发布版本；跨目录校验不适用当前单目录模型，未来引入多目录时另补归属校验（backlog，不预留字段或参数）。「不落库」仅指错误清单与导出产物，不改变上传原文与既有审计。本批不写业务库、不改发布门禁、不加迁移、不改 006/007。

B6d-3b 承接整版候选放弃及交接证据投影；新增 `023_catalog_candidate_abandons`，通过追加式放弃表投影状态，不修改 006/007 或 catalog_versions 的主键/原状态。保留所有版本、事实和 hash，存在放弃证据时在任何 down DDL 前拒绝回退。既有上传、版本查询、发布及交接行为保持兼容。
