# B6i-4 列宽松手与保存渲染

日期：2026-11-16。起点 `master@153040d`；分支 `codex/b6i-4-resize-commit`；AF-056。

## 范围与决定

用户确认仅做 A：收敛松手提交与保存阶段的渲染。松手先将最终列宽写入 DOM，异步保存偏好；保存 pending/success 不驱动表格渲染。列宽、表格总宽、固定列偏移、横滚位置及手柄语义同步；取消恢复拖动前宽度。下一次正常布局/列设置更新接回最新宽度，不依赖延时隐藏任务。

列偏好沿用身份/列表隔离、500ms 防抖、单写者、迟到 GET/PUT 防覆盖、失败缓存及重进续传。宽度保存与渲染通知分离；列显隐/顺序/重置仍正常通知。键盘、双击复位、隐藏列重开、具名视图、刷新和跨会话恢复不得丢失最新宽度。对 DOM 的临时控制必须在正常布局接管、取消及卸载时清理。

不做 B 的就绪等待修复，不做虚拟滚动、排序记忆化、选择状态重构或排序性能优化；不改业务规则、依赖、迁移、库存、历史数据或开发样本库。

## 只读基线

1280×960、Chromium、Umi dev:e2e、50 行，现有随机可销毁 MySQL 合成夹具。交替 +100/-100px、每次40步/25ms，10次连续完整手势；末次观察到保存结束。入库 trace 为40个>50ms任务，10/10手势超限，松手254–297ms；无trace入库/出库各40个，松手分别196–232ms/209–238ms。前一轮保存任务落入随后9次拖动。预览与最终宽度全部为预期320/220px。

应用层本来就是一次 `resize → change → publish`，没有逐列状态提交。主栈为React render/commit、Cell和context通知；无字体加载，GC单长任务累计最多5.91ms，不是主体。原E2E观察结束在mouse.up之前，不能代表完整手势。原始证据 `.local/evidence/b6i4-diagnosis/`，早期summary阶段分类已由trace-analysis/diagnosis更正；诊断命令一次宽度目标误算的超时不计入正式样本。
