# 工作台与数据看板规范（WORKBENCH_SPEC）

> 本文档中的状态、类型、结果等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 两页分工

| | 工作台（/） | 数据看板（/dashboard） |
|---|---|---|
| 回答 | 我现在该干什么 | 生意在往哪走 |
| 时间 | 今天 | 本月 / 本年 / 近 12 月 |
| 交互 | 可操作 | 只读 + 下钻 |
| 刷新 | 30 秒 | 进入时一次 |
| 加载 | < 1 秒 | < 2 秒 |

工作台是干活的地方，看板是看数的地方。

## 2. 工作台结构

| 区块 | 内容 | 交互 |
|---|---|---|
| KPI ×4 | 今日入库、今日出库、待确认、进行中盘点（各带环比与迷你趋势） | 点击进对应列表/详情 |
| 待我处理 | 待确认入库/出库、冻结超时、锁仓盘点 | 每行直达处理 |
| 目录健康 | 当前版本、条码数、上次更新、本版新增/消失/重量变更 | 去上传 |
| 交接证据 | 已登记作业未收齐事实数、已落库冲突数及时间；设备实时离线队列不支持；扫码记录仅供参考，不参与库存计算 | 查看已登记清单 |
| 今日车号关联单据 | 按车号汇总计划中/待确认/已确认单据，不代表车辆状态；在装/离场不支持 | 进入单据 |
| 最近操作 | 最近 10 条 | 操作记录 |
| 快捷入口 | 登记入库、新建出库、开始盘点、上传目录 | — |
| 14 天迷你趋势 | 入库/出库两条线 | 进看板 |

规则：
- 除迷你趋势外每个区块都能点或操作；
- 进行中盘点与冻结超时必须首屏可见；
- 只发一个 /api/v1/web/dashboard 请求，缓存 30 秒；
- 空态给可执行动作，不给空白卡片。

## 3. 数据看板结构

| 区块 | 图表 |
|---|---|
| 时间范围 | 本月/上月/今年/去年/自定义（全局） |
| 12 个月趋势 | 折线/面积，入库 vs 出库，可切吨数/包数 |

| 周转趋势 | 近 6 个月周转次数与天数 |

## 5. 图表

ECharts 按需注册（Line/Bar/Heatmap + Grid/Tooltip/Legend/Calendar/VisualMap/CanvasRenderer），自封 <Chart> 组件（init + ResizeObserver + dispose），不用 echarts-for-react。看板不注册 Pie；库龄与 Top 使用条形图。
迷你趋势线用 SVG 手写。
配色取chartTheme.inbound/outbound与colorBorderSecondary等theme token，不用裸色值。

## 6. 接口

GET /api/v1/web/dashboard → today、pending、stocktake、stale、stock、trend14d、topProducts、topCustomers、recent、catalogHealth、handoffEvidence、vehicleOrders、asOf、watermark、verification
GET /api/v1/web/analysis?fromDay=&toDay=&basis=posted → monthly、tops、aging、turnover、heatmap、duration；basis 可取 posted/restated
两接口均服务端聚合，缓存 30 秒。

## 7. 边界

| 情况 | 处理 |
|---|---|
| 已核验无数据 | 显示0并给动作入口；未知/不可验证显示原因，不支持项明示不支持 |
| 进行中盘点 | 必须显示，且显示锁仓时长 |
| 图表数据缺失 | 显示「暂无数据」占位，不画空坐标轴 |
| 聚合超时 | 显示部分数据 + 顶部提示「部分数据加载失败」 |

## 8. 验收

1. 待办单数与同条件去重单数一致，吨/包KPI与同条件数量汇总一致，不能把吨数对列表条数；
2. 进行中盘点与冻结超时首屏可见；
3. 工作台只发一个请求，p95 < 1s；
4. 看板 8 个区块均有数据或空态；
5. 六条下钻路径可达且条件正确；
6. 1440 一屏放下前两行，1280 无横向滚动；
7. 1440/1280 截图。

## 9. 聚合服务契约（需要新增服务能力）

两个API与/dashboard页面当前不存在，B7b（UI-3）新增；/当前出库列表迁到/outbound需保留旧链接和登录跳转兼容。聚合复用B3c、B5d及B6f的服务端读模型，不由浏览器逐页拼统计，不必为聚合本身建新库存表。

每个指标返回value、unit（单/包/克/次/天）、period、basis、verification/reason；日期统一上海自然日半开区间，今日只到asOf。入/出库与报表页同口径：确认减撤销，数量更正差额计入对应有效收发量，同时保留更正分类；调整/盘点/转移不混入收发，样品出库含在出库。不另建一套计算规则，复用报表事件归一化和收发累计函数。取样统计后置，不返回假零。环比同等时间窗，分母0/未知返回NULL及原因。Top排序用数值+业务编码稳定排序；缺历史快照不得拿当前名称假装原证据。

dashboard一次读快照返回全部区块，共用asOf/watermark；analysis复用同basis和条件，默认入账口径，重述能力服从REPORT_SPEC。超时区块明确失败而非0；缓存30秒且写入后失效。只读值可为真实空0，车辆在装/离场、设备实时队列和全设备同步覆盖率均不支持，不能用确认时间推断。

性能目标按WEB_UX_SPEC §11固定数据量/硬件/并发、冷/热30次样本验证；未取得原始输出前不承诺达标。前置B6f库存+B7a报表+B6d目录证据；不把未来设备事件表视为当前已有依赖。

修订记录：C11 替换设备实时队列与车辆离场卡片，仅展示可核验单据/交接证据，不可推断项标不支持。
修订记录：C12 明确新增聚合API、单位/归期/水位/空未知态、缺失响应与性能基准。
修订记录：C17 图表颜色改token，补热力图注册依赖。
修订记录：C18 登记 B7b-2 的接口、聚合口径、Top/时效、183日热力、按需图表和性能验收约束。

## 10. B7b-1 工作台与路由（2026-11-16，已确认范围）

本批只实施工作台及 `/web/dashboard`，看板、analysis、热力图、Top、单据时效、取样统计、设备实时状态和旧书签提示均后置。起点 `3e4b31b`，分支 `codex/b7b-1-workbench-routing`，最大迁移025；无必需DDL，不写开发样本库，不合并或推送。六笔提交后停止。

### 10.1 五项修订与业务边界

1. 本文旧“更正不混入收发”已废弃，由 DOMAIN_RULES §7 和本节取代。今日及14天趋势使用报表 posted、inventory-eligible、全部仓库商品口径，复用报表 normalizeEvent/addMovement；包数与克数分别累计，前端只将克格式化为吨。比较必须固定相同日期和asOf，不按建单时间统计收发。
2. 原“冻结超时”按已结束扫码仍未完成发货定义：本地未删除的 open/frozen/partially_shipped 且 scan_closed_at 非空，满7天提示；不写 frozen，不用建单时间猜结束扫码时间。部分发货保留提醒，已完成/短关/撤销/作废排除。缺少历史结束扫码时间则标未知。盘点只读 counting 与活动窗口，显示 started_at 起锁仓时长，24小时提示。
3. 待确认与盘点KPI是截至asOf的当前去重单数；没有历史状态快照，环比和历史迷你趋势标“历史状态依据不足”，不倒推。收发环比为昨日上海零点起相同经过时长；14天含今天（今天截止asOf），真正无发生额为0，未归期/不可验证或查询失败返回原因。
4. 本批不实现取样统计，也不新增取样表/协议；设备实时队列、全设备覆盖率、车辆在装/离场均不支持。交接只计已登记UUID/正文匹配证据；冲突只计服务器保存的扫码冲突尝试，不推断未解决冲突状态。
5. 库龄结构与库龄段下钻留给看板后续批次，不扩大库存筛选接口。本批不做Top、时效或看板页。

### 10.2 八区块与接口

- 顺序：四张KPI → 待我处理 → 目录健康/交接证据 → 今日车号关联单据 → 最近操作/快捷入口 → 14天趋势。车号块仍属于原八块，用户首屏顺序未另行取消；首屏必须看到盘点和超时。
- KPI：今日入库/出库展示包、吨；待确认总数=待确认入库+未完成出库去重单数，分别展示；盘点为进行中单数。未完成出库包括open/frozen/partially_shipped（历史来源单据不作为可操作待办）。
- 待办分别返回准确总数与每类最多5条最近登记记录；锁仓与扫码超时单独展示，不能被普通待办挤出首屏。详情直达，列表入口保持筛选条件。
- 目录：当前发布版本、条码数、发布时间与已存差异计数；未初始化为未知/可操作空态。交接：已登记未收妥去重事实数、关联作业单数、最新登记时间；已保存的扫码冲突尝试数与最新发生时间，不称实时队列。
- 今日车号：仅使用已有本地出库单/发货车号证据，今日创建或今日发货的关联单据去重；按车号展示计划中/待确认/部分发货/已确认与可访问单号，空车号显示“未记录车号”，不增加入库车号字段。
- 车号总单数按单据去重；同单的不同计划/实发车号仍保留各自关联。待办和车号标签沿用审计安全文本规则，异常UUID只保留在导航地址中，不显示为业务名称。
- 最近操作：复用安全投影最近10条；快捷入口为登记入库、新建出库、开始盘点、上传目录，均导航而非首页写入。14天趋势为SVG，数字提交后再挂载，不加载ECharts。
- 单次GET `/api/v1/web/dashboard` 返回8块及asOf/watermark；每个数值指标包含value/unit/period/basis/verification/reason。区块失败返回null及原因，真实空集可返回0；失败区块顶部提示，不泄露内部错误。
- 一个只读一致性事务，固定批量SQL；禁止逐单/逐清单调用详情。读模型复用报表分类/精确加法，收发事件一次批量读取覆盖14天和比较窗，不能重复逐日查。30秒TTL以现有readCacheClock为键/版本，写入后失效，读取期间版本变化不得把旧结果存入新版本缓存。
- 侧栏进行中盘点订阅相同工作台query结果，不再请求或轮询stocktakes active；工作台每30秒刷新，失败保留错误状态，禁止未知显示0。
- 技术落实：先在SQL中压缩可加的流水差额，再复用报表归期校验、事件归一化和累计函数；不查询单据明细，不新增汇总表/迁移。未知日期必须保留独立计数，历史午夜不得因小数秒字符串长度不同被排除。聚合只提供收发数量，不复制报表的完整余额链核验。
- 待办每类最多5条保持独立列，长列表在列内滚动，盘点和扫码超时入口不被普通待办挤出首屏；图表采用浏览器绘制周期后挂载的独立SVG模块。业务写入后刷新共享查询，列宽偏好保存不触发工作台刷新，保留B6i-4松手性能约束。
- 冷首屏使用根页面head脚本尽早启动同一聚合请求，与应用脚本加载并行；响应只暂存在当前页面内存，由共享query消费一次，仍走统一响应/契约校验，接口鉴权不变。非根页不预取，失败使用已有错误展示与显式重试，超过30秒丢弃旧预取；不持久化数据，不增加第二套统计或HTTP缓存。

### 10.3 路由与兼容

`/` 为工作台，`/outbound` 为独立出库列表菜单；新建/编辑/详情地址不变。旧根路径只要含已知出库列表查询键（status/statusMissing、keyword、page/pageSize、sortBy/direction、from/to、customer/warehouse/vehicle、billType、productCodes/productMode等现有列表参数）就replace到`/outbound`，保留原query/hash；裸根路径进工作台，不提示、不猜旧书签意图。统一更新详情返回、新建取消、登录redirect、AuthGate和listReturn；拒绝外站redirect。列表偏好仍使用outbound身份键。

### 10.4 验证与六笔提交

六笔依次为：规格与决策；契约与批量数据投影；聚合接口/缓存与接口回归；路由兼容与导航回归；工作台页面与交互；性能/全量验证与验收记录。每笔代码提交前审查，不合并、不推送。

验收：三组合成收发场景（含更正、撤销、跨日与样品）与同日同asOf报表包/克一致；权限、未知/真实空、部分失败、缓存写后失效、固定批量查询；旧链接参数保留、裸根路径工作台、详情返回与登录恢复；完整test/build/E2E。至少1万主单/10万流水，同机并发1和5，冷/热各30次，单独记录接口与首屏p95，均目标<1秒；冷请求不可用缓存掩盖，不先宣称达标。1440/1280截图仅存.local/evidence，复用隔离测试库，不改变截图基础设施。

## 11. B7b-2 数据看板（2026-11-16，已确认实现范围）

- 本批新增只读页面 `/dashboard` 与 `GET /api/v1/web/analysis?fromDay=&toDay=&basis=posted`；basis 支持 posted/restated，默认 posted。日期校验、上海自然日口径和最大跨度服从报表契约。
- 一次只读一致性快照产生全部区块，固定类别/数量的聚合查询，不按月份、日期或单据逐条查询。每块带单位、实际统计期间、basis、verification 和 reason；不能验证的数据为 null 并说明原因，不以0代替。真实无发生量可以为0；空图不绘制坐标轴。
- 报表复用优化：日终边界按快照事件建立索引；周转图只构建计算字段，无流水且验证原因相同的零贡献项只保留一份，仍传播不可验证，不折叠库龄余额；原报表输出逐字段回归。
- 收发SQL按日、商品、往来编码与报表事件分类压缩；复用归一化数量与校验。固定8次批量读（含水位、日期更正、完整余额/FIFO证据和时效），不读取单据行详情，不新增汇总表。
- 同一只读连接内提交独立的余额证据读取与日聚合；驱动串行执行SQL，Node投影计算与数据库聚合可重叠。所有读取结束后才提交或回滚，不使用不同连接拼接快照。
- 12个月趋势与月度对比共用一次月度投影/聚合，使用请求 fromDay/toDay；Top 与时效也使用该请求区间。库龄以 toDay 为截止日。周转趋势使用截至 toDay 的最近六个月；热力图使用截至 toDay 的连续183个上海自然日。
- 趋势可切吨数/包数；完整月份共用月聚合，非整月边界由同一日聚合裁剪；期间对比显示等长窗口环比，分母0/未知明示原因。下钻复用现有报表参数，库龄进入同截止日对应band；客户进入按编码检索的出库列表，列表不代表同期间有效收发量。
- Top 最多10项：商品以有效出库克数降序排名，客户以有效出库克数降序，供应商以有效入库克数降序；只列出排名克数大于0的对象。Tooltip 分别列出入库、出库数值；并列时业务编码升序，内部主键仅作最终稳定排序且不显示。
- 热力图色阶值为每日有效入库克数与有效出库克数之和；Tooltip 保留两方向的克数。返回恰好183个位置，0表示已核验无发生，null表示该日数据无法核验。末日为 toDay，当日数据仅统计至 asOf。
- 入库平均确认时长为 receipt.created_at 至其确认操作流水时间；出库平均确认时长为 outbound_orders.created_at 至使单据最终完成的最后一笔发货 shipped_at。平均值按确认/完成事件落在请求日期区间的单据计算。最长滞留为快照时仍未完成的入库待确认或出库未完成单据中 created_at 最早的一张，按建单至 asOf 的小时数展示。缺少任一时间证据时返回不可验证原因。
- 时效样本限定快照时当前有效完成：入库posting_state=confirmed、出库status=confirmed；撤销、短关、作废、未完成均不计入均值。此项为补充澄清未回复时采用的建议口径，不改变库存或流水收发口径。
