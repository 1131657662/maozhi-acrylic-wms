# 领域规则

适用产品：**茂智云仓 · 腈纶仓储管理系统**（茂智腈纶仓 / Maozhi Acrylic Fiber WMS）。

规则确认日期：2026-11-09。

本文记录已确认的业务规则与后续批次边界，不代表所有规则均已实现。初始文档提交未启动 B5a；后续 B5a 已单独授权实施，其实现边界和原始验收结果见 `B5A_ACCEPTANCE.md`。代码完成、构建通过、模拟器验证、实体设备验收和生产验收必须分别记录，不能互相替代。

## 1. 通用边界

1. 系统为单用户作业，保留身份验证、操作日志、数据校验与备份恢复；不增加多租户、复杂 RBAC、多用户审批或多级审批。
2. 包数与吨数独立记录。入库只录包数和总吨数，不扫码，不用统一件重反推总重量。
3. PDA 只记录扫码记录；结束扫码不是出库。库存扣减必须经过 Web 明确确认，并在同一事务内写库存、流水和审计。出库扣减数量取人工录入的实发量，扫码仅用于预填与打印凭证，不参与库存计算。
4. 扫码记录的 UUID 与正文不可变；重试沿用原 UUID 和正文，不静默丢弃离线或冲突记录。
5. **负库存一律禁止**：任何库存写入都不得使相关库存包数或吨数为负；异常场景、溢发和更正均不构成例外。
6. 当前仅本地合成数据；本文不授权生产连接、生产写入、历史数据删除或 warehouse 系统修改。

## 2. 时间与日期

### 2.1 三个独立概念

| 概念 | 含义 | 是否允许修改 |
|---|---|---|
| 登记时间 | 单据在系统中登记的时间 | 不可修改 |
| 入账时间 | 库存操作明确确认并实际入账的时间 | 不可修改 |
| 业务日期 `business_date` | 单据归属的实际业务发生日期 | 新建时可填；确认入账后锁定，填错只能走日期更正 |

登记时间、入账时间和业务日期不得相互覆盖或混为一个字段。回填业务日期不等于回填登记时间或入账时间。

### 2.2 填写与锁定

- 新建单据时可填写 `business_date`，允许回填过去日期。
- `business_date` 不得晚于今天。
- 回填超过 3 个月时，必须进行二次确认；二次确认不等于多用户审批。
- 确认入账后锁定业务日期。
- 未入账业务日期直接修改仅限本地待确认入库、计划中出库（未生成任何发货记录）；一旦有发货记录即锁定已入账业务日期与发货记录，计划数量仍按 §5.1 在计划中/部分发货时修改。结束扫码不阻断修改。历史日期缺失保留 NULL，不以导入日补齐；复用 011 字段，入账后日期更正另建追加式记录。
- B5a：新建未填时默认上海当天；未来日期、超过三个月未带二次确认、入账后修改均返回 422。三个月按上海日期的日历月计算，月底截到目标月末；二次确认留审计。
- 锁定后填错，走独立的**日期更正**流程，保留原值和更正记录，不能直接覆盖原始业务日期。
- 日期更正与下文的数量更正是两个不同操作；数量更正单不允许改业务日期。日期更正不能借机改登记时间、入账时间、包数或吨数。

### 2.3 报表归期

- 报表默认按**入账日**归月；业务日期单独保留、单独展示，不因业务日期回填而默默改写默认月报。
- 提供**重述视图**开关，用于明确查看业务日期归属及日期更正后的重述口径。
- 开启重述视图时，页面与相关输出必须标注“重述视图”和所用日期口径，避免与默认按入账日归月的报表混淆。
- 原日期与更正关系可追溯；不能用重述结果覆盖原始入账事实。

## 3. 数量更正（入库、出库通用）

### 3.1 允许与禁止

| 项目 | 规则 |
|---|---|
| 可以更正 | 仅包数、吨数 |
| 不可更正 | 商品、仓库、供应商/客户、单号、业务日期 |
| 原因 | 必填 |
| 关联 | 必须引用原单，保留更正链 |
| 历史导入单 | `source_id` 非空即禁止更正，只能库存调整 |
| 库存约束 | 更正后库存包数或吨数为负，一律拒绝 |
| 盘点约束 | 更正必须检查相关仓库的盘点暂停窗口，不得绕过暂停 |
| 防环 | 更正链禁止自引用和任何间接成环 |

更正通过独立记录表达原单数量差额，保留原单及历次更正，不直接改写原始业务事实。不能把更正当成改商品、改仓库、换往来单位或重编单号的入口。

### 3.2 入账与幂等

- 更正必须生成对应库存流水和审计记录；库存变更、更正关联、流水与审计保持一致。
- 重复提交必须幂等，不能重复更正、重复增减库存或生成重复流水。
- 入库与出库的库存方向分别计算：增加入库数量增加库存，增加出库数量减少库存；减少数量时方向相反。包数和吨数分别计算、分别检查。
- 必须在更正实际生效前检查历史来源、盘点暂停窗口、库存非负和更正链无环；校验失败不得留下部分库存写入。
- 不得通过拆单、更换幂等键或增加更正链层级绕过上述限制。
- 有效数量 = 原数量 + Σ(历次更正后值 − 前值)。入库库存变化 = 本次(后值 − 前值)；出库库存变化 = −(本次(后值 − 前值))。包数与吨数独立计算、独立校验，允许只改包数不改吨数。
- 更正单不携带业务日期，只记录更正时间和操作人；原单业务日期不随更正变化。
- 撤销已更正的原单时，按有效数量反向；更正链标记已抵消，保留全部原值、差额与流水，终结后的原单不能再更正。

### 3.3 原单详情

原单详情必须展示：

> 已被更正：±N 包（单号，日期）

其中单号、日期指向对应更正记录。存在多次更正时应保留可追溯的记录关系；吨数差额也须可查看，不能因包数差额为零而隐藏重量更正。

原单详情直接显示有效数量、累计包数/吨数差额、最近更正时间及单号；时间线展示“原单 → 更正1 → 更正2”。更正入口仅在详情底部操作条及列表行内“更多”菜单；更正抽屉展示原值、后值、差额与原因，提交前二次确认。每页最多一个一级主按钮，危险动作不占主位；选择及操作不移动表格区域。打印仅 disabled 占位并提示“待接入积木报表”。UI-2 的批量栏、查询抽屉与反查单据等功能不在 B5a 实施。

## 4. 入库异常

| 场景 | 处理规则 |
|---|---|
| 短装：实收 < 计划 | 允许，按实收记录，保留计划与实收差额及原因 |
| 溢装：实收 > 计划 | 允许，按实收记录，保留超收差额及原因 |
| 供应商后补 | 创建追加入库，引用原单 |
| 仓库入错 | 使用库存转移单处理 |
| 供应商挂错 | 撤销重录，不用数量更正修改供应商 |
| 商品挂错 | 撤销重录，不用数量更正修改商品 |
| 历史导入单 | 仅允许库存调整，不对历史原单做更正 |

短装、溢装和追加入库不得用计划值代替实收值。撤销重录与库存转移仍受现有库存安全、审计和确认约束，不因异常处理跳过校验。

“仓库入错”的库存转移单是纠错用途；与后文后置的日常仓库间调拨业务分开列项，不因此开放完整调拨作业流程。

## 5. 出库异常

| 场景 | 处理规则 |
|---|---|
| 短发 | 按实发确认；剩余量保留待发（`backorder`） |
| 溢发 | 允许，记录超发量与原因；实际扣减仍须满足库存非负 |
| 分批发货 | 支持，新增 `partially_shipped` 状态表示已部分发货且仍有待发量 |
| 短关 | 使用 `short_closed` 状态关闭未发余额，不动库存 |
| 重复确认 | 幂等拦截，不重复扣减、写流水或审计 |
| 已结束扫码但未确认 | 不可撤销；结束扫码本身仍不等于出库或库存扣减 |
| 已离场后发现数量错 | 走更正单，不能直接改扫码记录或原确认记录；更正后库存不得为负 |

分批发货按各批实际发出量确认，不一次性按整单计划扣减。未发余额须明确保留待发或按短关处理，不能静默消失。短关不把余额计入出库量，也不产生库存增减。

### 5.1 B5c 发货余额与状态模型（待实现）

- **实发来源**：出库扣减数量一律取人工在明细行录入的实发包数/实发吨数；扫码只做预填（包数、重量 kg×0.001）与打印凭证，不参与库存计算。扫码汇总在确认时快照存入 `scan_packages/scan_weight_grams`，供追溯与导出。
- **计划可改**：`open`、`partially_shipped` 状态可改计划（含明细行增删），只影响待发量，不影响已生成发货记录；`confirmed/short_closed/voided` 不可改。2026-11-12 收尾裁定：编辑后的每行计划包数、克数分别不得小于已发量，低于或终态编辑均返回 422；商品、客户、仓库不可借计划编辑修改。编辑使待发归零不自动结单，保留显式完成。
- **发货记录**：复用 016 的 `outbound_shipments`（order_id、seq、vehicle_no、shipped_at、business_date、operator、operation_id）与 `outbound_shipment_lines`（shipment_id、order_line_id、packages、weight_grams、overage_reason）。一次确认生成一条记录；记录不可修改；`seq` 按单递增。
- **余额**：已发 = 各发货记录实发之和（含溢发）；待发 = max(计划 − 已发, 0)；溢发 = max(已发 − 计划, 0)。包数与吨数分别计算，不相互推导。
- **状态（2026-11-12 用户裁定）**：每次人工确认发货后，所有行包数、克数待发均为 0 则自动 `confirmed`，否则 `partially_shipped`；首次发满亦自动结单。人工「完成发货」保留，仍必须检查每行待发为 0；人工「短关」转 `short_closed`。`/confirm` 与 `/shipments` 使用相同规则，禁止新产生「已出库但仍有待发」的数据。
- **短关**：原因必填，待发义务清零并单独保留关闭时未发量，不写库存流水、不计出库量。短关后不可重开或追加发货；货再到只能另开新单。
- **业务日期与归期**：每条发货记录带自己的 `business_date`（默认确认当天，可回填但不得晚于今天），仅作单据说明与核对；月报与对账按**入账日（确认当天）**归月，回填业务日期不追溯改动历史月份。
- **更正**：数量更正作用于**发货记录行**，引用原发货记录并保留原值，链式版本与防环沿用第 3 节；整单撤销按全部有效发货记录反向，终结订单。
- **撤销**：`partially_shipped`、`confirmed` 与 `short_closed` 均可整单撤销，反向所有发货记录与库存；沿用现有库存流水证据与后续依赖保护，存储状态保持 `cancelled`（界面「已撤销」），不新增同义的 `reversed` 出库状态；不开放单批发货记录撤销。
- **盘点锁仓**：盘点进行中禁止确认发货（不仅是确认出库），与入库确认、调整、撤销同属被锁操作。
- **并发**：确认与短关使用订单版本互斥，同一幂等键重放返回原结果，不重复生成发货记录或扣减库存。

### 5.2 样品出库与取样

**样品出库**是整包/整批实物出库，单据类型为「样品出库」，按普通出库单的人工实发录入与 Web 确认链路扣库存并计出库量；不得以样品名义绕过负库存或历史单守卫。**取样**是包内少量取出，按第6节条码级标记，不扣库存、不写库存流水。两者入口、类型和统计分开，不得混用。客户退货 RMA 仍后置。

## 6. 取样

### 6.1 记录边界与字段

取样为**条码级标记**，使用独立表 `sample_marks`。取样不写库存流水，不改变包数或吨数；即使填写了取样克数，也不据此自动扣减库存。

每次取样至少记录以下业务信息：

| 字段/信息 | 规则 |
|---|---|
| `barcode` | 被取样包的条码 |
| 仓库 | 取样发生时的仓库 |
| 商品 | 取样发生时的商品；保留用于条码复用校验的规格信息 |
| 取样时重量快照 | 保留取样时对应包的重量，不随当前目录覆盖 |
| 取样时间 / 人 | 可追溯此次取样操作 |
| 原因 | 记录取样原因 |
| 取样克数 | 选填；只用于取样记录，不自动形成收发量或库存扣减 |
| 备注 | 补充说明 |
| 状态 | 保存取样标记状态；具体状态枚举不在本文假定为已实现 |

同一包可多次取样，每次保留独立历史，不覆盖以前的取样记录。

### 6.2 出库提示与条码复用

- 出库扫到已取样包时，提示取样情况并要求二次确认；默认不阻断出库。
- 条码相同不必然是同一包。必须对比当前目录与取样快照的规格、重量。
- 当前目录与取样快照的规格或重量不一致时，视为另一包，不弹出旧包的取样提示。
- 历史取样记录仍保留，不因条码复用而删除或改写。
- 取样报表分别统计取样包数和取样次数：同一包多次取样不应把次数误作包数。取样不计入收发量。

## 7. 报表口径与对账

### 7.1 独立分类

| 类型 | 报表分类与收发量口径 |
|---|---|
| 正常入库 | 计入入库量 |
| 正常出库 | 计入出库量 |
| 样品出库 | 整包/整批出库，计入出库量，类型单独可筛选 |
| 更正 | 独立分类、单列差额，不混入正常收发量 |
| 库存调整 | 独立分类，不混入正常收发量 |
| 盘点回写 | 独立分类，不混入正常收发量 |
| 库存转移 | 独立分类，不混入正常收发量 |
| 取样 | 独立统计包数/次数，不计入收发量，不形成库存流水 |

### 7.2 库存恒等式

包数与吨数均须按各自单位核对：

**期初 + 入库 − 出库 ± 调整 = 期末**

这里的“调整”为对账等式中的非正常收发库存净变动汇总项，须可拆分到更正、库存调整、盘点回写、库存转移等独立分类。各笔影响只能计入一次，不允许把汇总项和分项重复相加，也不能为了配平将这些事件归入正常收发量。取样对该等式的库存影响为零。

- 计算期末与实际期末之间的差额必须可见，不得隐藏。
- 不可验证区间必须标注原因，例如期初依据不足、历史数据链不完整或所需来源缺失；不得用 0 代替未知或不可验证。
- 默认按入账日归月；重述视图开关和日期口径标注遵循第 2 节。
- 明细、汇总、导出与重述视图的分类口径须一致，保留追溯原单、更正及相关流水的入口。

## 11. 盘点录入（本次已确认，增强能力待实现）

- 包数与吨数独立存储、独立校验。吨数默认按「系统吨数 ÷ 系统包数 × 实盘包数」折算，可手工覆盖；不是固定件重，也不改变入库的独立录入规则。系统包数为零、快照外盘盈及半包/拆包时必须手填吨数；半包按整包计。
- 保存估算/手工来源；手工覆盖后改包数不静默覆盖吨数。估算按整数克精确计算并四舍五入到 100 克（0.0001 吨），入账前展示包吨差异，手工值按现有精度校验。
- 明盘即时显示默认值；盲盘在核对差异前不返回系统包吨、均重或差异，未手填吨数先记“待折算”，核对时由服务端折算并揭示差异；零基数/半包仍须手填。揭示后再修改须重做核对，凭版本化核对令牌回写。
- 200 行仅为一次渲染上限；分页/筛选不丢已填数据，不截断整张盘点。固定快照不可变，盘盈行另存；继续保留暂停窗口、漂移检查、未入账清单 ACK、幂等重放及同事务流水/审计守卫。
