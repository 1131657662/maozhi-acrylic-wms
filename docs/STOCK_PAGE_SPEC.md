# 库存概览与流水页面规范（STOCK_PAGE_SPEC）

> 本文档中的状态、类型、结果等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。

## 1. 定位

回答三个问题：现在有多少货（在库/待发/可发）、货有多老（库龄）、这货怎么变成这样的（流水）。

## 2. 页面结构

```
┌ 库存概览 ────────────────── [单位 吨▾] [导出] [打印占位] ┐
│ 快捷：仓库 [主仓▾]  商品 [______]   [筛选 ·0] [视图 ▾]   │
├──────────────────────────────────────────────────────────┤
│ 汇总：1,408.5930 吨 · 4,688 包 · 121 种 · 待发 320 包 · 超90天 18% │
├──────────────────────────────────────────────────────────┤
│ ▸ │ 仓库 │ 编码 │ 名称 │ 在库 │ 待发 │ 可发 │ 库龄 │ 最近变动 │ 操作 │
├──────────────────────────────────────────────────────────┤
│ 合计（固定）：4,688 包 / 1,408.5930 吨 · 待发 320 包       │
└──────────────────────────────────────────────────────────┘
```

## 3. 口径

1. 按 MASTER_DATA_SPEC §0 的 inventory_eligible + 来源证据统计；资格迁移前保持 erp-product 白名单，不以排除 sku-spec 放开未知来源；
2. 在库 = stock 当前值；
3. 待发 = max(计划量 − 累计已发, 0)（open / partially_shipped；排除撤销、作废、短关）；累计已发取自分批发货记录，包/克独立聚合；计划可改，改后待发按新计划重算，已发不变；
4. 可发 = 在库 − 待发，包/吨分别计算；负值标「计划缺口」，不代表实际负库存或放行扣减；
5. 库龄复用库龄报表的 FIFO 投影核心；库存页按 §12 的新五档分桶，不可归龄独立显示；
6. 单位切换（吨/千克）只影响显示。

## 4. 主表字段

展开箭头、仓库、商品编码、名称、在库包数、在库吨数、待发包数、待发吨数、可发包数/吨数、库龄（五档吨数分布+无法归龄）、最近变动、操作。

库存页五档：0–30 / 31–60 / 61–90 / 91–180 / >180 天，另列不可归龄；颜色只用对应主题token。报表仍保留 REPORT_SPEC 的原分档，两者共用 FIFO 耗用/撤销/未知池规则。一个仓品可有多个FIFO层，不返回无定义的单一agingDays，不由吨数分桶反推包数。

行操作：查看流水（普通行操作，不占页面primary）、更多（调整库存、导出该商品流水、复制编码）。
批量：导出选中、打印占位、取消。

## 5. 行内展开（Peek）

最近 3 条流水，单号可点，撤销/更正标类型，一次只展开一行。

## 6. 流水抽屉

标题为商品 + 当前在库/待发/可发；最近 20 条（时间、类型、单号、包数变化、吨数变化、前后值）；底部「查看全部流水」带条件跳转；只读。

## 7. 筛选抽屉

商品（编码/型号/品名、多选、是否有待发）、库存（仓库、包数/吨数范围、零库存）、库龄（五档、含不可归龄）、时间（最近变动）。

预置视图：全部 / 超 90 天 / 零库存 / 有待发。

## 8. 接口

GET /api/v1/web/lists/stock：新增scope=inventory；旧source=erp-product仍仅返回历史ERP子集，二者互斥，详见MASTER_DATA_SPEC；保留现有warehouse/product、page/pageSize/sortBy等契约及viewToken/行token；新增productKeyword/productMode、hasPending、packagesMin/Max、tonnesMin/Max、zeroStock、agingBucket、hasUnaging、changedFrom/To，兼容规则见WEB_UX_SPEC §11。
响应保留items/subtotal/total，扩展onHand、pending、available（各包/克）、agingBuckets、unagingGrams、lastMovementAt、asOf、watermark、verification；不改名rows。分阶段字段以 §12 为准。

GET /api/v1/web/stock/:warehouse/:product/journal?limit=20

汇总与列表在同一读快照/水位返回，按仓×品先聚合库存、订单行余额、库龄再连接，禁止N+1或JOIN放大。subtotal是全部筛选结果；pageTotals只对当前页；品种数去重。流水下钻扩展类型/时间/单号/分页/导出，现有最近20条不能冒充全量读模型。B6f-2a 的 subtotal 仍仅为现有在库包数/克数，不新增全筛选待发汇总或 pageTotals。

## 9. 边界

零库存默认隐藏；负库存顶部红条告警；可发为负标「计划缺口」；不可归龄不进分段；历史导入库存流水不完整标「流水不完整」；条码目录商品不出现；打印占位。

## 10. 验收

1. 全筛选subtotal与独立全量聚合一致；pageTotals与本页可加项之和一致，品种数去重；
2. 抽 3 个有计划的商品：可发 = 在库 − 待发；
3. 行内展开、抽屉、流水页三处一致；
4. 库存页新五档边界正确，复用报表 FIFO；五档已归龄量 + 不可归龄 = 同快照在库，整数克差异 0；
5. 单位切换换算正确；
6. 勾选零位移；表底合计滚动可见；
7. 保存视图后恢复条件、列、单位；
8. 1440/1280 无页面横向滚动；筛选p95目标<800ms，按WEB_UX_SPEC的同机数据/冷热点基准报告，未实测不得写通过。

### B6f-2b：固定合计行与库龄合并（2026-11-14 用户确认）

- BusinessList 新增可选 `tableSummary`（默认 undefined）；既有 `summary` 仍为表格上方汇总区。仅传入时使用 Ant Design Table.Summary fixed bottom，随表格横滚、可见列顺序/宽度/固定列及选择列对齐；其他列表不传，行为不变。
- 库存页固定行标「当前页合计」，只加本页响应中包数、整数克、待发包/克、可发包/克（含负值）；不重算可发。列/维度有值才累加，全部缺失或空页显示「—」，有效 0 显示 0；非可加列显示「—」。不把全筛选 subtotal 当本页合计，不增加全筛选待发汇总。
