# PDA 连续扫码规范（PDA_SCAN_SPEC）

> 本文档中的状态、类型等库值仅作实现标识；界面显示必须按 docs/UX_STANDARDS.md 映射为中文。
> 参考项目：acrylic-pda-outbound（仅借鉴扫码效率做法，不沿用其流程模型）。

## 1. 定位

扫码是**辅助计数**：帮用户快速数清这一车装了多少包，结果用于预填出库数量与打印扫码清单，不参与库存计算。

因此 PDA 只做三件事：

```
扫 → 记到本机 → 显示进度
```

不做审批、不做召回、不做续作、不做逐包处置。

## 2. 从参考项目借的四点

| 做法 | 为什么有效 |
|---|---|
| 前台注册扫码广播，**不做防抖** | 防抖会丢掉连扫的合法条码；重复应在保存时判重 |
| 输入队列**单一消费者**按序处理 | 连扫时不会并发写库、不会乱序 |
| **即扫即存**本地库，不等网络 | 扫描速度不受网络影响 |
| 声音 + 震动反馈 | 不看屏幕也能知道成功/失败 |

补充借鉴（保存逻辑，不看它的页面与流程）：

- 每条记录保存**原始字符串 + 规范化条码 + 扫码序号 + 设备序号 + 时间**；
- 判重靠数据库唯一索引，插入冲突即视为重复，不先查后插；
- 保存与计数在同一事务内完成，失败则整条回滚，不留半条。

## 2.1 广播优先，键盘楔兜底

| 模式 | 触发 | 说明 |
|---|---|---|
| 广播（优先） | 厂家扫码服务发送 Intent | 不依赖输入框焦点，连扫最快；参考项目即此模式 |
| 键盘楔（兜底） | 扫码枪当键盘输入 + 回车 | 任何设备可用；必须保证焦点与输入缓冲 |

实现规则：
1. 进扫码页后注册广播；收到第一条广播即标记「广播模式」；
2. 连续 2 秒无广播且检测到键盘回车，切换为「键盘模式」；
3. 两种模式的提交入口是同一条队列，不写两套逻辑；
4. 广播 action 与 key 做成设置项，默认值：
   `com.android.decodewedge.decode_action` /
   `com.android.decode.intentwedge.barcode_string`；
5. 页面前后台切换时注册/注销广播，避免后台耗电与误收。

## 3. 明确不借的五点

| 不借 | 原因 |
|---|---|
| 召回 / 停止证明 / 续作 | 流程太重，你的业务不需要 |
| 逐包处置（卸货/隔离） | 同上 |
| 失败后暂停整个队列 | 一条扫错就停工，现场会骂人；改为提示后继续 |
| 审计归档与跨代恢复 | 本系统已有 Web 审计，PDA 不做第二套 |
| 多轮基线/周期模型 | 目录版本已有，不重复建模 |

## 4. 交互设计

```
┌ 出库单 CK-20261110-001 · 苏F80807 ─────────────┐
│  计划 100 包   已扫 68 包   剩余 32 包          │
│  ██████████████░░░░░░  68%                     │
│                                                │
│  [ 扫码输入框（常驻焦点，扫完自动清空）        │
│                                                │
│  最近：100B0005788  302kg  ✓                   │
│        100B0005791  301kg  ✓                   │
│        100B0005791  重复，已忽略  ✗            │
│                                                │
│  [撤销上一条]  [查看全部 68 条]  [结单冻结]     │
└────────────────────────────────────────────────┘
```

规则：
1. 输入框**常驻焦点**，每次扫码后自动清空、不重建界面（重建会丢焦点）；
2. 扫码枪按键盘楔处理：字符进缓冲，回车提交；
3. 成功：短提示音 + 轻震动 + 计数 +1；
4. 重复：低音提示 + 红色提示「重复条码」，**不阻断下一条**；
5. 无效：低音提示 + 「目录中没有此条码」，同样不阻断；
6. 超过计划数量：黄色提示「已超计划 N 包」，继续可扫（扫码只是参考）；
7. 「撤销上一条」只删最近一条未同步记录，已同步的走 Web 更正；
8. 屏幕常亮，扫码页不自动锁屏。

## 5. 性能要求

| 指标 | 目标 |
|---|---|
| 单包处理（本地写入完成） | p95 < 50ms |
| 连续扫码 | ≥ 5 包/秒不丢、不卡 |
| 连续 200 包 | 焦点不丢、界面不卡顿 |
| 内存 | 不随扫码数量线性增长（只缓存计划与最近 10 条） |

实现要点：
- 计划与明细行**进页面时解析一次**，缓存内存；不在每包重新解析整单 JSON；
- 计数用增量变量，不每次遍历全部事实；
- 重复判断交给数据库唯一索引，插入冲突即判重，不先查询；
- 界面只更新计数与最近列表，不整页重绘；
- 网络同步交给后台队列，扫描路径不发起网络请求。

### 5.1 针对现有代码的改造点

| 现状 | 问题 | 改法 |
|---|---|---|
| 每包重新 `JSONObject(plan.json)` | 100 包解析 100 次整单 | 进页面解析一次，内存缓存计划与行 |
| 每包遍历本地 facts 数容量（O(n²)） | 越扫越慢 | 进入页面时统计一次，之后增量 +1 |
| 先 `findBarcode` 再插入 | 两次数据库操作 | 直接插入，靠唯一索引冲突判重 |
| 保存后整页重建 | 输入框焦点丢失 | 只更新计数与最近列表两个视图 |
| 只有输入框模式 | 依赖焦点 | 增加广播接收，优先广播 |

页面与流程**不参考**旧项目：它们有多级确认、召回、续作、处置页，本系统只保留一个扫码页。

### 5.2 M71 真机适配

| 项 | 要求 |
|---|---|
| 广播注册 | targetSdk 35，动态注册必须带 `RECEIVER_EXPORTED`（`ContextCompat.registerReceiver`），否则新系统抛 SecurityException |
| 扫码输出 | M71 扫码服务需在系统设置里选「广播输出」；扫码页提供「扫码自检」按钮，提示当前是否收到广播 |
| 屏幕 | 扫码页 `FLAG_KEEP_SCREEN_ON`，不自动锁屏 |
| 生命周期 | 页面前台注册、后台注销；返回扫码页时重新注册 |
| 队列缓冲 | 广播可能在主线程连续到达，用 Channel/队列交给 IO 协程消费；队列满时不丢，提示音并落库失败计数 |
| 声音 | 成功短音、失败低音；媒体音量为 0 时以震动兜底 |
| 条码归一化 | 去首尾空白与不可见字符；保留原始串一并入库；M71 若带前缀（如 `]C1`）需在设置里配置剥离规则 |
| 冻结后 | 广播仍会到达，直接丢弃并提示「已冻结」，不写库 |

### 5.3 自动选行

扫码时按条码对应的商品自动匹配明细行：

1. 该商品只有一行 → 自动选中，用户不需要先选行；
2. 该商品有多行 → 若只有一行还有剩余计划，自动选它；否则提示「该商品有多行，请选择」，暂停本条直到选定；
3. 选行结果在页面上可见，可手动切换；
4. 切换行不影响已扫记录。

## 6. 离线与补传
- 每条扫码立即写入本机库，状态「待上传」；
- 联网后后台批量补传，失败自动重试；
- 补传不阻塞继续扫码；
- 结单冻结后不再接受新扫码，已有记录正常补传；
- 补传冲突在 Web 审计中可见，PDA 只提示「有 N 条待核对」。

## 7. 与 Web 的关系

| 环节 | 归属 |
|---|---|
| 扫码计数 | PDA |
| 实发数量 | Web 人工填写（扫码结果预填） |
| 库存扣减 | Web 确认 |
| 扫码清单导出 | Web |

## 7.1 边界规则

| 情况 | 处理 |
|---|---|
| 同一包条码扫到另一张单 | 拒绝并提示「该条码已属于 CK-…」，不写库；一包只能属于一单 |
| 撤销上一条时该条已在补传 | 不删记录，提示「已上传，请到 Web 更正」 |
| 撤销上一条时正在写入 | 等写入完成再撤销，提示「正在保存，请稍候」 |
| 连续扫到同一条码 | 提示重复，计数不变 |
| 扫描枪漏回车 | 键盘模式下超过 300ms 无后续字符自动提交 |
| 扫码页进入后台 | 注销广播，返回时重新注册并重算当前计数 |

## 8. 验收
1. 连续扫 100 包：耗时、p95、无丢包、焦点不丢；
2. 扫重复条码：提示一次，计数不变，下一条可继续；
3. 扫目录外条码：提示一次，不阻断；
4. 超出计划：黄色提示，仍可继续；
5. 撤销上一条：记录消失、计数 −1、导出不含该条；
6. 断网扫 50 包：全部落库，联网后自动补传；
7. 结单冻结后再扫：拒绝并提示已冻结；
8. 真实 PDA 上声音与震动可闻可感。

## 8.1 文案调整（B9 必做）

扫码不再参与库存后，PDA 上旧的“事实/出库”话术会误导操作员，必须一起改：

| 旧文案 | 新文案 |
|---|---|
| 扫码事实 | 扫码记录 |
| 冻结后才出库 | 结束扫码后，出库数量在网页填写并确认 |
| 已冻结，待 Web 确认 | 已结束扫码，待网页确认出库数量 |
| 待补传事实 | 扫码记录待上传 |
| 扫码异常 | 扫码未通过 |
| 扫码即出库 | 不允许出现这类表述 |

规则：
- PDA 界面同样遵守 `UX_STANDARDS.md` §11：不出现「事实、冻结、幂等、落库、字段、接口」等词；
- 扫码页顶部说明固定为：**「扫码只做计数参考，出库数量以网页填写为准」**；
- 结单按钮从「结束核对 · 冻结」改为「结束扫码」。
