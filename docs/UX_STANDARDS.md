# 全站体验标准与文档审计（UX_STANDARDS）

本文件是 11 份页面规格的**横向约束**：文案、格式、图标、配置、操作舒适度。
各页面规格与本文件冲突时，以本文件为准。

## 1. 三条总原则

1. **用户看到的是业务语言，不是数据库语言**：不出现 `success`、`pending`、`open`、`frozen`、`audited`、UUID、内部 ID。唯一例外是登录后的审计详情「原始数据」折叠区（§2.6）。
2. **不硬编码**：颜色、阈值、文案、格式、分页、超时全部来自 token / 常量 / 枚举。
3. **操作要顺，不要炫**：每一步都可返回、可取消、不丢输入；动画只用于反馈，不用于装饰。

## 2. 文案映射（禁止直接显示库值）

### 2.1 单据状态

| 库值 | 显示 |
|---|---|
| pending | 待确认 |
| confirmed | 已入账（入库）/ 已出库（出库） |
| open | 计划中 |
| frozen | 已结束扫码，待确认（过渡期仍可能出现） |
| partially_shipped | 部分发货 |
| short_closed | 已短关 |
| reversed | 已撤销 |
| voided | 已作废 |
| audited（历史导入） | 历史单据 |
| completed | 已完成 |
| cancelled（入/出库生命周期） | 已撤销确认 |
| cancelled（其他对象） | 按该对象含义映射为已取消，不跨对象复用 |
| legacy-open（来源标记） | 切换承接（不是状态） |

### 2.2 盘点状态

counting → 盘点中；completed → 已完成；voided → 已作废。

目录候选独立映射：validated → 待发布；published → 已发布；abandoned → 已放弃（整版，不表示条码或扫码事实失效）。放弃详情显示原因、放弃时间、操作人；交接统计用「预期扫码记录数」，不称为目录条码数。

### 2.3 操作结果

| 库值 | 显示 |
|---|---|
| success / ok | 完成 |
| failed / error | 失败 |
| conflict | 冲突 |
| pending | 处理中 |

### 2.4 流水类型

inbound → 入库；outbound → 出库；check → 盘点；import → 导入；
stock.adjust → 库存调整；inbound.reverse → 入库撤销；outbound.reverse → 出库撤销；
stock.correct → 更正；stocktake.post → 盘点回写。

### 2.5 渠道

web → 网页端；pda → 手持终端；miniapp → 小程序。

### 2.6 未知值

普通列表、时间线和详情正文统一显示「未识别」，不附原始值。仅已登录审计详情的「原始数据」默认折叠区可按需读取、展示/复制脱敏原始值、错误码、追踪号并导出诊断记录；凭证/密码/token始终遮蔽。未登录接口拒绝，列表响应和普通导出不携带原始值/追踪号。

### 2.7 空值

- 单据快照字段缺失（NULL/空字符串）专用映射：**历史未记录**；单据详情、列表、导出一致，不回退显示当前主数据名称。其他空值仍按下列通用规则。

统一显示「—」，不显示 null / undefined / 空白。

## 3. 数值与日期格式

| 类型 | 格式 | 示例 |
|---|---|---|
| 吨 | 4 位小数 | 72.0000 吨 |
| 千克 | 3 位小数 | 302.000 kg |
| 包数 | 整数 | 240 包 |
| 百分比 | 1 位小数 | 18.0% |
| 日期时间 | YYYY-MM-DD HH:mm；审计列表/详情精确到秒 | 2026-11-11 14:37:30 |
| 日期 | YYYY-MM-DD | 2026-11-11 |
| 时长 | 中文 | 2 小时 15 分钟 |
| 负数 | 前置减号，红色 | −2 包 |

规则：数字右对齐、等宽字体；单位用 12px 灰字紧跟在数字后。

日期时间禁止出现斜杠与本地化自动格式：

- 页面、表格、导出、文件名统一用 `YYYY-MM-DD HH:mm:ss`（或到分钟）；
- 实现上统一走一个格式化函数（`Intl.DateTimeFormat('sv-SE', { timeZone: 'Asia/Shanghai' })`），不各处自己拼；
- 不允许直接 `toLocaleString()` 依赖运行环境；浏览器/系统语言不同会得到不同分隔符。

## 4. 图标

1. 页面标题左侧统一 **16px 线性 SVG 图标**（与左侧菜单图标同族），不放大、不加底色；2. 状态标签用「图标 + 文字」，不只靠颜色区分；3. 图标来源统一：`@ant-design/icons`，不自绘混搭、不用 emoji；4. 按钮内图标与文字间距 4px，纯图标按钮必须有 tooltip。

## 5. 不硬编码与配置清单

| 类别 | 要求 | 存放位置 |
|---|---|---|
| 颜色 | 只用 theme token；图表色也在主题里定义 | `app.tsx` token + `chartTheme.ts` |
| 状态/类型/原因 | 枚举 + 中文标签成对定义，前后端共用 | `packages/contracts` |
| 阈值（差异 10%、50 包、超时 7 天、锁仓 24 小时、目录 30 天、库龄 90 天） | 常量表，不散落页面 | `packages/contracts/constants.ts` |
| 分页（50/100/200）、缓存 TTL（30s）、请求超时、导出上限（10 万行） | 常量 | 同上 |
| 文案（空态、错误、确认） | 集中文案表 | `apps/web/src/text.ts` |
| 导出文件名 | 模板常量 | 同上 |
| 表名/字段名 | 只出现在数据层 | — |

验收方式：全局搜索页面代码，出现裸颜色值、裸阈值、裸状态字符串即为不合格。

## 6. 操作舒适度与流转

### 6.1 步骤预算

| 动作 | 上限 |
|---|---|
| 新建入库 / 出库 | ≤ 2 屏 |
| 确认入账 / 出库 | 1 次点击 + 1 次确认 |
| 更正 | 打开 → 填写原后值/差额/原因 → 二次确认；不得为步数省略确认 |
| 查一张单 | ≤ 2 步（搜索 → 打开） |
| 盘点一仓 | 建单 → 数 → 填 → 回写，4 步 |

### 6.2 不打断

- 抽屉/弹窗打开不改变页面滚动位置；
- 列表加载只做表内 loading，不整页闪白；
- 小于 300ms 的请求不显示 loading（避免闪烁），超过显示骨架；
- 提交失败保留输入与滚动位置；
- 任何抽屉支持 Esc 关闭，关闭后焦点回到触发按钮。

### 6.3 防误触

- 危险操作与主操作不并排，间距 ≥ 8px；
- 危险操作二次确认文案写明后果与受影响单号；
- 库存撤销/作废/短关始终二次确认；仅清空选择等纯界面动作可用toast恢复，不把业务补偿视为无风险可逆操作。

### 6.4 键盘与焦点

- Enter 提交/下一行，Esc 关闭，Tab 顺序符合视觉顺序；
- 列表中空格切换当前行选中，Enter 打开详情；
- `/` 聚焦搜索框；
- 表格行选中后 Enter 打开详情；
- 弹窗打开聚焦第一个输入框。

### 6.5 空态与错误

- 空态：一句说明 + 一个动作（如「暂无入库单，去登记」）；
- 错误：说清原因 + 重试按钮，保留筛选；
- 403：说明无权限，不显示半截数据。

## 10. 错误提示规范

### 10.1 三条原则

1. **让用户知道发生了什么**，不是让用户看异常；
2. **让用户知道下一步做什么**：自己重试、改输入、刷新、还是找开发；
3. **技术细节默认折叠**，需要时能复制给开发。

### 10.2 错误分类与文案

| 类型 | 触发 | 用户看到的 | 动作 | 用户该做什么 |
|---|---|---|---|---|
| 网络中断 | 断网、连接被拒 | 网络连接中断，请检查网络后重试 | 重试 | 自己重试 |
| 服务未就绪 | API 未启动、网关 502/503 | 服务暂时不可用，请稍后重试 | 重试 | 等几秒再试 |
| 请求超时 | 30 秒无响应 | 服务响应超时，本次操作未完成 | 重试 | 自己重试 |
| 系统错误 | 5xx | 系统出错了，已记录（编号 XXXX） | 重试 / 复制编号 | 先重试；仍失败报开发 |
| 数据异常 | 返回非 JSON、契约校验失败 | 数据异常，已记录（编号 XXXX） | 重试 / 复制编号 | 报开发 |
| 输入不合法 | 422 校验失败 | **具体字段原因**，如「入库单号已存在」 | 定位到字段 | 改输入 |
| 状态冲突 | 409 | 该单据已被修改，请刷新后重试 | 刷新 | 刷新后重做 |
| 库存不足 | 409 | 库存不足：当前可用 24 包，需 30 包 | 修改数量 | 改数量 |
| 权限不足 | 403 | 没有权限执行此操作 | — | 联系管理员 |
| 登录过期 | 401 | 登录已过期，请重新登录 | 去登录 | 重新登录 |
| 数据不存在 | 404 | 该记录不存在或已被删除 | 返回列表 | 返回 |

禁止出现：

- 裸英文异常（`Unexpected token`、`Failed to fetch`、`ECONNREFUSED`）；
- 裸状态码（`500`、`409`）作为主文案；
- 只有一句「操作失败」，不说原因也不给动作；
- 堆栈、SQL、内部表名。

### 10.3 提交失败

1. **明确告知结果**：用「未提交成功」而不是「失败」，避免用户以为已保存；
2. **保留现场**：表单内容、滚动位置、已上传文件全部保留；
3. **重试安全**：重试使用同一幂等键，不会重复建单、重复扣库存；
4. **连续失败**：同一操作连续失败 3 次，提示「请联系开发并提供编号 XXXX」；
5. **成功后**：清空草稿、跳转详情、给出单号。

### 10.4 判断用户能否自己解决

```
是输入问题？      → 指出哪个字段、什么要求，光标定位过去
是等一会儿就好？  → 给「重试」按钮，说明未保存
是需要刷新？      → 给「刷新」按钮，说明数据已过期
需要开发介入？    → 显示编号 + 「复制编号」，并说明已记录
```

### 10.5 技术细节

- 折叠区显示：时间、接口路径、状态码、traceId；
- 提供「复制」按钮，方便发给开发；
- 主界面不显示 traceId，只在折叠区与提示语里带编号。

### 10.6 防刷屏

- 同一错误 5 秒内只显示一条；
- 同时最多 3 条通知，超出排队或合并；
- 持续失败（如轮询）不弹窗，改为页面内状态条。

### 10.7 验收

1. 停掉 API → 打开列表 → 显示「服务暂时不可用」+ 重试可用；
2. 断网提交 → 显示「网络连接中断」且表单内容保留；
3. 断网恢复后重试 → 不产生重复单据；
4. 422 → 高亮具体字段，不只弹一句失败；
5. 409 → 提示刷新，刷新后数据为最新；
6. 5xx → 显示编号，复制后可在操作记录中检索到同编号；
7. 任何页面上搜索不到 `Unexpected token`、`Failed to fetch`、`ECONNREFUSED`、`SQL`、`stack`。

## 11. 界面语言规范

### 11.1 总原则

**界面上每一个字，都应该是用户能读懂的业务语言。**

判断标准：仓库管理员第一次看到这个词，能不能不问你、直接明白它是什么意思。

### 11.2 禁止出现的词

| 禁止 | 原因 | 改成 |
|---|---|---|
| 口径 | 财务/开发黑话 | 直接写「按入账日期统计」 |
| 打印口径 / 报表口径 | 同上 | 「打印内容」「统计方式」或直接说明 |
| 快照 | 技术词 | 「盘点开始时的库存」 |
| 主数据 | 技术词 | 「基础资料」 |
| 明细行 / 单据头 | 表结构词 | 「商品行」「单据信息」 |
| 冻结 | 技术词 | 「已扫码，待确认」 |
| 冲销 / 红冲 | 财务术语 | 「撤销」 |
| 反写 / 落库 / 写库 | 技术词 | 「更新库存」「保存」 |
| 幂等 / 事务 / 回滚 / 参数 / 枚举 / 字段 / 接口 | 纯开发词 | 不出现 |
| 校验 / 校验失败 | 技术词 | 「检查」「填写有误」 |
| 硬编码 / 配置项 / 开关 | 开发词 | 不出现 |
| 占位 / 待接入 | 开发词 | 「暂不可用」或直接隐藏 |

### 11.3 状态词必须说人话

| 库值 | 界面显示 |
|---|---|
| pending | 待确认 |
| confirmed（入库） | 已入账 |
| confirmed（出库） | 已出库 |
| frozen | 已扫码，待确认 |
| reversed | 已撤销 |
| voided | 已作废 |
| audited | 历史单据 |
| counting | 盘点中 |
| partially_shipped | 部分发货 |
| short_closed | 已短关 |

**任何页面不得直接显示库值、英文、状态码。**

### 11.4 编码不是给人看的

| 场景 | 规则 |
|---|---|
| 仓库 | 显示「龙山库」，不显示 `WH002` |
| 客户 | 显示「宁波中纤」，编码小字附后 |
| 商品 | 显示名称，编码小字附后 |
| 单据号 | 正常显示（它是业务标识） |
| 内部 ID / UUID | 任何列表都不显示 |

### 11.5 句子规则

1. 说清「发生了什么 + 该做什么」：不要只写「操作失败」；
2. 数字带单位：`240 包`、`72.0000 吨`，不写裸数字；
3. 时间用中文可读格式：`11 月 10 日 21:45`，不写 ISO 字符串；
4. 不用缩写：`PD-…` 可以，`PD` 单独出现要写「盘点单」；
5. 动词开头：按钮写「确认入账」，不写「入账确认操作」。

### 11.6 文案审查

验收时在 `apps/web/src` 搜索以下关键词，命中数必须为 0：

```
口径、快照、主数据、幂等、事务、回滚、落库、校验、枚举、
字段、接口、参数、占位、待接入、硬编码
```

另外人工走查：随机打开 5 个页面，确认没有英文状态、没有 UUID、没有裸编码当主标签。

## 12. 数据选择与联想

### 12.1 原则

**系统里已经存在的数据，不允许让用户凭记忆精确输入。**

凡是「商品、客户、供应商、仓库、车辆、单据号、条码」这类实体，输入框必须是：

```
输入即联想 → 模糊匹配 → 可多选 → 选中后以标签回显
```

用户不可能记得 376 个客户的完整名称，更不可能记得编码。

### 12.2 各字段的要求

| 字段 | 匹配方式 | 单选/多选 |
|---|---|---|
| 商品 | 编码、名称、型号，任意片段 | 多选（查询）；单选（表单） |
| 客户 | 名称、编码、拼音首字母 | 单选（表单） |
| 供应商 | 名称、编码、拼音首字母 | 单选 |
| 仓库 | 名称、编码 | 单选 |
| 车辆 | 车牌，任意片段 | 单选，可新建 |
| 单据号 | 任意连续片段 | 多选（查询） |
| 条码 | 精确或前缀，扫码枪可直接输入 | 单选 |

### 12.3 交互规则

1. **输入即搜**：至少 1 个非空白字符，停顿 300ms 自动查询，不需要先点搜索按钮；B6g-2 的组件范围与验收见 §12.9；
2. **结果带上下文**：显示「宁波中纤 · C00001」「003 · 腈纶短纤 3D×65mm」，不只显示名称；
3. **最近优先**：默认列出最近用过的 5 条；
4. **键盘可用**：上下键选择、回车确认、Esc 关闭；
5. **多选回显**：选中项以标签展示，可单个移除；
6. **空结果给出口**：显示「没有匹配项」+「换个词试试」；基础资料可给「新建」入口，查询场景不给；
7. **粘贴多值**：支持逗号、换行分隔一次粘贴多个单据号；
8. **不区分大小写与空格**：`苏F80807` 与 `苏f 80807` 视为相同。

### 12.4 中文场景必须支持拼音首字母

用户输入 `nbzx` 应该能匹配「宁波中纤进出口有限公司」。

实现方式：
- 主数据表增加 `search_text` 字段（名称 + 拼音首字母 + 编码），保存时生成；
- 查询用 `LIKE` 匹配 `search_text`，加索引；
- 不在运行时计算拼音，避免每次查询都跑转换；
- 已有数据在迁移时批量回填。

### 12.5 后端要求

以下为完整联想目标；B6g 本次已批准的兼容实施范围与例外以 §12.8 为准。

| 项 | 要求 |
|---|---|
| 接口 | 统一的联想接口，按实体类型区分，不在前端全量拉取 |
| 参数 | `keyword`、`limit`（默认 20，最大 50） |
| 返回 | `{ value, label, sublabel }`，label 是名称，sublabel 是编码 |
| 性能 | p95 < 150ms；索引覆盖 `search_text` |
| 空关键字 | 返回最近使用项，不返回全表 |

### 12.6 禁止的做法

| 禁止 | 原因 |
|---|---|
| 纯文本输入框要用户手打客户全称 | 记不住、易错 |
| 下拉框一次加载全部选项 | 376 个客户、569 个商品，卡且难找 |
| 只支持前置匹配 | 用户往往只记得中间几个字 |
| 只按编码匹配 | 用户更常记得名称 |
| 输入错了只提示「未找到」不给建议 | 用户不知道该怎么改 |

### 12.7 验收

1. 商品输入框输入 `腈纶` 能出现相关商品；
2. 客户输入 `nbzx` 能出现「宁波中纤」；
3. 输入 `80807` 能出现对应车牌；
4. 单据号粘贴多个（逗号或换行）能一次查询；
5. 多选后标签可单个移除；
6. 空结果有提示，不出现空白下拉；
7. 联想接口 p95 < 150ms，输入停顿 300ms 才发请求（不每键一次）。

### 12.8 B6g 持久化检索（2026-11-13 已批准）

- 选 A：API 依赖精确版本 `pinyin-pro@3.29.5`（MIT）。按库默认读音生成无声调全拼/首字母，不加人工多音字词库，不在查询时转换拼音。
- 022 在商品、客户、供应商、车辆四表增加 `search_text VARCHAR(512) NULL` 和非唯一普通 B-tree 索引。down 必须先检查四表，任一列存在非 NULL 值（含空串）即拒绝，且不执行 DDL。
- 商品检索片段为编码、名称、型号以及名称/型号各自的全拼与首字母；客户/供应商为编码、名称、旧编码以及名称全拼与首字母；车辆为归一化车牌、原车牌，不生成拼音。
- 片段统一小写、删除空白和 Unicode 标点，按完整片段去重后拼接；不按字符去重。超过 512 个 Unicode 字符明确报错并回滚，不静默截断或丢弃检索字段。
- 新建、修改、车辆隐式建档使用同一个生成函数，在原写入事务内同步。已有数据由 `scripts/backfill-search-text.ts` 仅回填 NULL 行，重复执行补齐数为零；不改业务原列与时间戳。
- 复用 `/master/{catalog}`（兼容 `/master-data/{catalog}`）分页接口，新增 `q`，保留 `keyword` 别名。两者同时出现时 `q` 优先，显式空 `q` 维持空查询；不传 `q` 时旧调用不变。`search_text` 用归一化关键词匹配，`code/name` 仍按原关键词片段匹配，以保留旧编码标点/空格搜索能力。LIKE 特殊字符按字面转义；只有标点的输入不产生全匹配。
- 空查询仍按编码分页，不新增最近使用排序；列表响应和页大小契约不变。管理列表仍可查询停用项，选择候选继续显式 `status=active`；商品候选继续 `scope=inventory`，排除条码规格/已删除来源。车辆仍按 `plate_normalized` 搜索，支持 `q` 别名。
- 仓库/分类保留编码和名称查询，不增加检索列。最近使用、统一 limit/value-label 接口、多值单据粘贴、全站输入改造和前端交互改版不属于本次范围；现有 Web 通过 keyword 别名直接获得新增匹配能力。
- 普通 B-tree 无法为前后通配 `LIKE '%q%'` 提供范围定位；不得以“已加索引”代替验收。开发样本库对商品/客户各记录一份 EXPLAIN，并各以 10 个不同关键词串行测量完整列表服务耗时（含 count/分页/投影）；p95 用 nearest-rank，10 个样本取最大值。超过 150ms 报告方案，不擅自改为分页缓存。
- 验收覆盖全拼、首字母、型号、旧编码、候选资格、keyword 兼容、回填幂等、修改同步与非空拒绝 down；运行 test/build/E2E，记录代码、本地构建/自动化与实际设备/生产验收的区别。开发样本库应用 022 前备份并核验身份/原列指纹；只执行已授权回填，不新增业务样本。
- 本次持久化交付为 B6g-1：原两条 E2E 红灯分别连续三次复核并记录实测；稳定失败必须修复。列表拖拽 50ms 门槛与断言不变，确认的偶发长任务归 B6i 并登记验收/问题台账；完整主 E2E 全绿、022 为 applied、开发样本四表 search_text 无 NULL 后才合并推送，随后停止，不启动 B6g-2。

### 12.9 B6g-2 Web 联想接入（2026-11-13）

- 范围为所有现有 MasterSelect 调用（含仓库/分类）与车辆字段；只改 Web、浏览器测试及文档，不修改后端、共享契约或数据库，不替换其他列表筛选控件。
- 输入去首尾空白后满 1 字符才查询，防抖固定 300ms，空输入不加载候选；保留已选项详情回填。请求使用 q，原有 keyword 调用仍兼容；每页 20 条，换词回第一页。
- React Query 按实体/词/页隔离响应并传递 AbortSignal；输入等待防抖及请求期间隐藏旧候选，旧响应不能覆盖当前词的结果；卸载清理定时器。
- 候选只含启用项，商品同时要求库存资格；不可用资料不进入下拉候选，历史已选值仍独立回填，不以停用候选灰显替代。名称为主，编码/型号为次；车辆以车牌为主，保留自由录入新车牌及原有表单值语义。
- 加载期显示小 Spin，不显示无数据；请求完成且零结果显示「没有匹配的商品/客户/供应商/车辆，换个关键词试试」（按类型替换，仓库/分类同理）。无输入显示输入提示；失败保留中文错误和重试入口。
- 上下键选择、回车确认、Esc 关闭沿用 Ant Design。验证首字母/编码片段/型号、300ms 合并请求、1 字符起查、响应竞态、加载/空态、回填、20 条分页及资格过滤；1440 截图保存在 .local/evidence，不进 Git。
- 自动化实测：浏览器受控时钟下，快速输入两次后最后一次输入的第 299ms 请求数为 0，第 300ms 仅发出最终词的 1 次请求；商品单字符输入会查询，空白不查，车辆同样验证 299/300ms 边界。这是防抖时序验证，不是服务端响应耗时或生产性能测量；详情见 B6G_ACCEPTANCE。

## 13. 防重复提交

### 13.1 为什么必须做

鼠标按键老化会出现“点一次触发两次点击”（chatter），触控板双击、键盘回车连发也会造成同样结果。落在提交按钮上，就是**重复建单、重复扣库存、重复撤销**。

### 13.2 三层防护

| 层 | 做法 |
|---|---|
| 交互层 | 点击后立即锁定，按钮进入「提交中…」并禁用，直到请求结束 |
| 请求层 | 同一提交意图使用同一个幂等键（Idempotency-Key），重试复用 |
| 服务端 | 幂等键命中时返回首次结果，不产生第二条记录 |

### 13.3 前端必须遵守

1. 用 **ref 同步加锁**，不能只依赖 `disabled` 状态——React 状态更新是异步的，同一 tick 内的两次点击都会通过；
2. 锁定时间窗 ≥ 500ms；
3. 按钮在锁定期间显示「提交中…」，视觉上明确不可再点；
4. 请求失败后解锁，允许重试，但重试复用同一幂等键；
5. 回车提交同样受锁保护，忽略 `keydown` 的重复触发（`event.repeat`）。

### 13.4 幂等键规则

- 每次打开表单生成一个 UUID，作为本次提交意图的键；
- 提交失败后重试，键不变；
- 提交成功后清空，下次新建重新生成；
- 同一表单内不同动作（保存草稿 / 提交）使用不同键。

### 13.5 危险操作同样适用

二次确认弹窗的「确认」按钮也要防抖——**双击弹窗的确认按钮，同样会产生两次请求**。

### 13.6 验收

1. 连续快速点击提交 10 次 → 只产生 1 条记录；
2. 模拟请求超时后重试 → 仍只有 1 条记录；
3. 回车键按住连发 → 只提交 1 次；
4. 双击确认弹窗 → 只执行 1 次；
5. 提交中按钮显示「提交中…」，不可再次点击。
